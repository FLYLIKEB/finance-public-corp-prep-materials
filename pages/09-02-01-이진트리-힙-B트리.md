## 핵심 개념

- 이진트리(Binary tree)
  - 각 노드는 최대 2개의 자식(왼쪽·오른쪽)을 가진다.
  - 연결 구조는 포인터(참조)나 배열(완전이진트리의 경우)로 표현할 수 있다.
- 이진 탐색 트리(BST, Binary Search Tree)
  - 각 노드의 왼쪽 서브트리의 모든 키 < 노드 키 < 오른쪽 서브트리의 모든 키.
  - 이 특성 덕분에 탐색과 순회(inorder)에 대한 효율적 연산이 가능하다.
- 힙(Heap)
  - 완전이진트리를 기반으로 하는 우선순위 큐 구현 방식.
  - 최대 힙(max-heap)은 부모 키 ≥ 자식 키, 최소 힙(min-heap)은 부모 키 ≤ 자식 키 성질을 갖는다.
  - 힙은 정렬된 순서를 보장하지 않으므로 임의 원소 탐색은 비효율적이다.
- B트리(B-tree)
  - 한 노드가 여러 키와 자식 포인터를 가질 수 있는 균형 검색 트리.
  - 디스크/블록 기반 저장소에서 I/O 횟수를 줄이도록 설계됨(높이 낮춤).

## 쉽게 이해하기 (핵심 포인트 요약)

- 이진트리/이진 탐색 트리
  - 구조: 최대 두 자식. 부모-왼쪽-오른쪽 관계를 이용한 정렬 속성.
  - BST 특징: inorder traversal → 오름차순(또는 내림차순) 정렬 결과.
  - 활용: 메모리 내 정렬된 집합, 맵/셋 구현, 간단한 검색·삽입·삭제.

- 힙
  - 종류: max-heap / min-heap.
  - 성질: 루트에서 항상 최댓값(혹은 최솟값)을 읽을 수 있음(즉시 접근 O(1)).
  - 구현: 배열 기반 구현이 일반적. (0-based 인덱스 기준 부모(i)→자식(2i+1, 2i+2))
  - 사용처: 우선순위 큐, 힙 정렬, 이벤트 스케줄러, 그래프(다익스트라) 등.

- B트리
  - 구조: 노드 하나에 여러 키/포인터가 있고 모든 리프가 같은 깊이를 가짐(균형).
  - 목적: 블록(페이지) 단위 접근을 최소화하여 디스크 성능 위주로 설계.
  - 사용처: DB 인덱스, 파일 시스템, 대용량 범위 쿼리.

## 세부 개념 및 연산(시험·실무에 자주 나오는 포인트)

### 이진 탐색 트리(BST)
- 주요 연산 및 시간복잡도
  - 탐색(search): 평균 O(log n) — 트리가 균형일 경우. 최악 O(n) — 편향 트리(예: 정렬된 입력을 순서대로 삽입).
  - 삽입(insert): 평균 O(log n), 최악 O(n).
  - 삭제(delete): 평균 O(log n), 최악 O(n) — 경우에 따라 후속 노드(후계자)를 찾아 교체.
  - 순회(traversal): inorder(정렬), preorder, postorder — 모두 O(n).
- 시험 포인트(구체적 예시)
  - inorder traversal은 BST의 정렬된 순서를 반환한다. (재귀/스택으로 구현 가능)
  - 예: 1,2,3,4,5 순서로 삽입하면 편향(한쪽으로 늘어진) 트리가 되어 탐색이 O(n)으로 악화된다.
  - 균형 이진 탐색 트리(AVL, Red-Black)는 삽입·삭제 후 회전(rotate)으로 높이를 O(log n)로 유지한다.
- 구현 참조(간단한 inorder 재귀 예)

```
# 재귀적 inorder (의사코드)
def inorder(node):
    if node is None:
        return
    inorder(node.left)
    visit(node)  # 예: 키 출력
    inorder(node.right)
```

- 실무 연결
  - 간단한 메모리 내 키-값 저장소 구현 시 사용. 하지만 실무에서는 균형 트리나 해시 기반 구조가 더 자주 사용됨.
  - 트리 기반 자료구조의 동시성(concurrency)이나 메모리 지역성(locality)은 실무 성능에 큰 영향을 미침.

### 힙(Heap)
- 주요 연산(완전이진트리·배열 표현 기준)
  - peek: O(1) — 루트의 최댓값/최솟값을 확인.
  - insert: O(log n) — 끝에 추가 후 up-heap(sift-up).
  - extract-max/min: O(log n) — 루트와 마지막 요소 교환 후 down-heap(sift-down).
  - build-heap: O(n) — 배열을 바닥에서부터 siftdown하면 선형 시간.
- 배열 인덱스 관계(0-based)
  - 부모(i) = (i-1)//2, 왼쪽 자식 = 2i+1, 오른쪽 자식 = 2i+2
- build-heap이 O(n)인 이유(직관적 설명)
  - 바닥에 가까운 노드들은 siftdown 비용이 작고, 상단 노드는 수가 적다. 전체를 합치면 선형 시간 복잡도가 됨.
- 핵심 연산 의사코드(중요한 시험 포인트)

```
# siftdown (0-based 인덱스)
def siftdown(A, i, n):
    while True:
        left = 2*i + 1
        right = 2*i + 2
        largest = i
        if left < n and A[left] > A[largest]:
            largest = left
        if right < n and A[right] > A[largest]:
            largest = right
        if largest == i:
            break
        swap(A[i], A[largest])
        i = largest

# build-heap
for i in range((n//2)-1, -1, -1):
    siftdown(A, i, n)
```

- 시험 포인트(정리)
  - 힙은 최댓값/최솟값 추출에 최적화되어 있으나 임의 원소 탐색은 O(n).
  - Heap sort는 힙을 이용해 O(n log n) 시간에 정렬하며 제자리 정렬(in-place)이 가능.
- 실무 연결
  - 우선순위가 핵심인 시스템(스케줄러, 이벤트 큐, 실시간 top-k 유지)에 적합.
  - 다익스트라의 경우 힙(우선순위 큐) 성능이 전체 알고리즘 성능에 직접 영향.

### B트리(B-tree)
- 핵심 성질
  - 차수(order) m: 노드는 최대 m개의 자식을 가짐, 최대 키 수는 m-1.
  - 루트 제외한 내부 노드는 최소 ⌈m/2⌉-1개의 키를 가짐(즉, 최소 자식 수 ⌈m/2⌉).
  - 모든 리프가 같은 깊이에 있어 균형을 유지.
- 주요 연산
  - 탐색: 노드 안에서 선형(혹은 이진) 검색 후 자식으로 이동 — 전체 시간 O(log n).
  - 삽입: 적절한 리프에 삽입 후 노드가 가득 차면 분할(split)을 통해 균형 유지.
  - 삭제: 키를 제거하고 필요 시 형제와 병합(merge) 또는 대체 키를 받아서 균형 유지.
- 삽입 시 노드 분할(개념적 단계)
  1. 리프 노드에 키를 삽입한다.
  2. 키 수가 m-1을 초과하면 가운데 키를 부모로 올리고 노드를 둘로 분할한다.
  3. 부모가 넘치면 재귀적으로 위로 분할한다.
- 시험 포인트
  - B트리는 디스크 블록 읽기 수를 줄이기 위해 노드당 많은 키를 유지한다는 설계 목적을 이해하라.
  - B트리와 B+트리의 차이(기본적으로 B+는 모든 실제 데이터 키를 리프에만 둠)를 알고 있으면 응용 문제에 유리하다.
- 실무 연결
  - 데이터베이스 인덱스(B-tree/B+tree), 파일시스템의 디렉터리 인덱싱 등에서 핵심 자료구조.
  - 디스크 I/O 비용과 메모리 페이지 크기 고려가 성능 설계의 중심.

## 비교 정리: 언제 어떤 자료구조를 쓰나?
- 메모리 내에서 작은 집합/맵, 빈번한 순회나 정렬이 필요하면: BST 또는 균형 BST(AVL/Red-Black).
- 최댓값/최솟값을 빈번히 추출해야 하면(우선순위 큐): 힙.
- 디스크 기반의 대용량 데이터에서 범위 검색/인덱스가 필요하면: B트리 계열.

## 시험 포인트(간단 체크리스트)
- [ ] inorder traversal이 BST에서 정렬 결과를 반환함을 설명할 수 있다.
- [ ] 힙의 insert와 extract 연산이 O(log n)인 이유를 말할 수 있다.
- [ ] 힙은 임의 원소 탐색에 비효율적(O(n))임을 이해한다.
- [ ] B트리가 왜 디스크 친화적인지(노드 당 많은 키) 설명할 수 있다.
- [ ] BST의 최악 시간복잡도가 O(n) 되는 상황(편향 트리)을 예로 들 수 있다.
- [ ] build-heap이 O(n)인 직관적 이유를 설명할 수 있다.
- [ ] 균형 BST(예: AVL, Red-Black)의 회전이 왜 높이 보장을 하는지 개념적으로 설명할 수 있다.

## 실무 팁/면접 대비
- 질문이 "가장 빠른 최댓값/최솟값" 관련이면 힙(우선순위 큐)을 먼저 언급하고, 추출·삽입 복잡도와 임의 탐색의 한계를 같이 설명하라.
- 파일시스템/DB 관련 면접에서는 B트리(또는 B+트리)를 언급하고, 디스크 블록 접근 횟수를 줄이기 위한 노드 크기 설계 의도를 설명하라.
- BST 관련 문제에서는 입력 분포(랜덤 vs 이미 정렬됨)에 따른 성능 차이를 반드시 언급하고, 필요 시 자가 균형 트리 도입을 제안하라.
- 구현 팁: 힙은 배열 인덱스 연산만으로 구현 가능하므로 구현과 디버깅이 비교적 쉽다. B트리는 포인터/노드 구조와 디스크-페이지 단위 I/O를 고려해야 한다.

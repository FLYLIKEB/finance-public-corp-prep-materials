# 06-02-02. 선점형과 비선점형

> 학습 목적: 선점형과 비선점형 스케줄링을 “CPU를 강제로 빼앗을 수 있는가”라는 기준으로 구분하고, 문맥교환·응답시간·기아 가능성과 연결한다.  
> 관련 기출: [05-9-운영체제-기출-모음](05-09-운영체제-기출-모음.md)  
> 연결 핵심정리: [04-3-소프트웨어공학-운영체제-컴퓨터구조](04-03-소프트웨어공학-운영체제-컴퓨터구조.md)

## 핵심 구분

| 구분 | 의미 | CPU가 바뀌는 대표 시점 | 대표 알고리즘 | 장점 | 단점 |
|---|---|---|---|---|---|
| 비선점형 | 실행 중인 프로세스가 스스로 CPU를 내놓을 때까지 기다림 | 종료, I/O 요청 | FCFS, 비선점 SJF, HRN | 구현 단순, 문맥교환 적음 | 긴 작업 독점, 응답시간 악화 |
| 선점형 | 운영체제가 실행 중인 프로세스의 CPU를 강제로 회수 가능 | time quantum 만료, 높은 우선순위 도착, 더 짧은 잔여시간 도착 | RR, SRTF, 선점 우선순위 | 응답성 좋음, 대화형 시스템에 적합 | 문맥교환 오버헤드, 설계 복잡 |

> 그림: P1 실행 중 더 짧은 P2가 도착했을 때, 비선점형은 P1을 계속 실행하고 선점형은 P1을 중단한 뒤 P2를 실행할 수 있다.

## 판단 기준

선점형과 비선점형을 구분할 때는 알고리즘 이름보다 실행 타임라인을 먼저 본다.

```text
실행 중인 프로세스가 아직 끝나지 않았는데 CPU가 다른 프로세스로 넘어갔다
→ 선점이 발생했다
→ 선점형 알고리즘 또는 인터럽트 기반 정책이다
```

반대로 CPU가 바뀌는 이유가 항상 `종료` 또는 `I/O 요청`뿐이라면 비선점형으로 볼 수 있다.

## 선점이 발생하는 대표 조건

| 조건 | 설명 | 예시 |
|---|---|---|
| Time Quantum 만료 | 정해진 시간만큼 실행했으므로 CPU를 회수 | RR |
| 더 짧은 잔여시간 도착 | 새 프로세스의 실행시간이 현재 프로세스의 남은 시간보다 짧음 | SRTF |
| 더 높은 우선순위 도착 | 우선순위가 높은 프로세스가 Ready 상태가 됨 | 선점 우선순위 |
| 인터럽트 발생 | I/O 완료, 타이머 인터럽트 등으로 커널이 제어권 획득 | 시분할 OS |

## 문맥교환과 오버헤드

선점형이 응답성이 좋은 이유는 운영체제가 실행 중인 프로세스를 중단하고 다른 프로세스를 실행할 수 있기 때문이다. 하지만 이때 CPU 레지스터, 프로그램 카운터, 스택 포인터 같은 실행 문맥을 PCB에 저장하고, 다음 프로세스의 문맥을 복원해야 한다. 이 작업이 문맥교환이다.

문맥교환 중에는 실제 사용자 작업이 진행되지 않으므로 오버헤드가 발생한다. 따라서 선점형이 항상 좋은 것은 아니다.

- time quantum이 너무 작다: 자주 바뀌어 응답은 빠르지만 문맥교환 비용이 커진다.
- time quantum이 너무 크다: 문맥교환은 줄지만 RR의 장점이 약해지고 FCFS처럼 동작한다.
- 우선순위 선점이 과도하다: 낮은 우선순위 프로세스가 계속 밀려 기아가 생긴다.

## 선점형 SJF와 비선점형 SJF

SJF라는 이름만 보고 선점 여부를 단정하면 안 된다.

| 이름 | 의미 | 판단 |
|---|---|---|
| SJF | CPU가 비는 시점에 실행시간이 가장 짧은 작업 선택 | 보통 비선점 |
| SRTF | 실행 중에도 남은 시간이 더 짧은 작업이 오면 교체 | 선점형 |

예를 들어 P1이 0에 도착해 실행시간 8로 실행 중이고, P2가 2에 도착해 실행시간 2라면 다음처럼 달라진다.

- 비선점 SJF: P1을 8까지 끝내고 P2 실행
- SRTF: t=2에 P1의 남은 시간 6과 P2의 실행시간 2를 비교해 P2로 선점

## 금융 IT 관점 연결

금융권 시스템은 배치성 작업과 대화형 요청이 섞인다. 대량 정산·통계 배치처럼 오래 걸리는 작업은 처리율이 중요하고, 고객 조회·인증·결제 요청은 응답시간이 중요하다.

- 배치 작업 중심: 비선점형 또는 긴 quantum이 효율적일 수 있다.
- 사용자 요청 중심: 선점형, 우선순위, RR 계열이 응답성 확보에 유리하다.
- 중요 거래 처리: 우선순위를 높이되 낮은 우선순위 작업의 기아를 막기 위해 aging이 필요하다.

## 오답 포인트

- “선점형 = 무조건 빠름”이 아니다. 문맥교환 오버헤드 때문에 처리율이 떨어질 수 있다.
- “비선점형 = 불공정”도 아니다. 구현이 단순하고 예측 가능성이 필요한 환경에서는 장점이 있다.
- RR은 선점형이다. time quantum이 끝나면 실행 중인 프로세스가 완료되지 않았어도 CPU를 회수한다.
- FCFS는 비선점형이다. 먼저 실행한 프로세스가 I/O를 요청하거나 종료할 때까지 계속 실행한다.
- 우선순위 스케줄링은 선점형/비선점형 둘 다 가능하다. “높은 우선순위가 도착했을 때 즉시 빼앗는가”가 기준이다.

## 빠른 점검

- 실행 중인 프로세스가 끝나지 않았는데 CPU가 바뀌는 예를 만들 수 있는가?
- RR이 선점형인 이유를 time quantum과 연결해 설명할 수 있는가?
- SJF와 SRTF의 차이를 간트 차트로 나타낼 수 있는가?
- 선점형의 장점과 문맥교환 오버헤드를 함께 설명할 수 있는가?

## 약어 풀이

- CPU: Central Processing Unit, 중앙처리장치
- FCFS: First-Come, First-Served, 선입선처리
- I/O: Input/Output, 입출력
- PCB: Process Control Block, 프로세스 제어 블록
- RR: Round Robin, 라운드 로빈
- SJF: Shortest Job First, 최단 작업 우선
- SRTF: Shortest Remaining Time First, 최소 잔여시간 우선

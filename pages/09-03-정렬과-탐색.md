# 09-03. 정렬과 탐색

> 학습 목적: 정렬·탐색 알고리즘의 시간복잡도를 비교한다.
> 관련 기출: [05-13-알고리즘-기출-모음](05-13-알고리즘-기출-모음.md)

## 핵심 개념

- 이진 탐색은 정렬된 배열에서 O(log n)이다. (반씩 좁혀 가므로)
- 퀵정렬 평균은 O(n log n)이다. (분할 후 병합 비용이 선형)
- 버블·선택·삽입 정렬은 기본 원리를 손으로 추적한다. (작은 입력이나 학습용)

설명 보충:
- 시간 복잡도 표기법: Big-O는 상한(최악), Ω는 하한(최선), Θ는 상한·하한이 같은 경우(타이트 바운드)를 의미한다. 문제 풀이 시에는 최악/평균/최선과 추가 공간(스택 포함)을 함께 적는 습관을 들이자.
- 안정성(stability): 같은 키의 원소들 간 상대적 순서가 유지되는지. 다중 키 정렬(예: 1차 키로 정렬한 상태에서 2차 키로 안정 정렬을 적용할 경우)에 중요하다.
- 제자리(in-place) 정렬: 입력 배열 이외에 상수 수준의 추가 공간만 사용하는 정렬. 예: 힙 정렬은 제자리로 구현 가능하지만 병합 정렬은 추가 O(n) 공간을 일반적으로 사용한다.
- 비교 기반이 아닌 정렬(Counting / Radix)은 키의 범위나 자릿수 조건이 맞으면 선형 시간에 가까운 성능을 낼 수 있다(예: O(n + k)). 그러나 키 범위(k)가 크면 실제로 비효율적일 수 있다.

### 서술형 확장 개념

- 항상 최악/평균/최선과 공간 복잡도를 구분해 기술한다. 예: 퀵정렬은 평균 O(n log n), 최악 O(n^2) (피봇 편향), 공간복잡도는 구현에 따라 O(log n)~O(n) (재귀 호출 스택).
- 안정 정렬의 예: 병합 정렬, 삽입 정렬(일반 구현). 퀵 정렬과 힙 정렬은 기본 구현에서 불안정하다.
- 제자리 정렬의 장단점: 추가 메모리를 적게 쓰지만 cache locality나 상수계수에 따라 실제 성능이 달라질 수 있다. 예를 들어 힙 정렬은 O(1) 추가 공간이지만 메모리 접근 패턴 때문에 실제 성능이 떨어질 수 있다.
- Counting/Radix 정렬: 비교 기반 한계를 벗어나 O(n + k) 또는 O(n * d) (d는 자릿수) 성능을 기대할 수 있으나, 추가 배열과 키 분해 비용이 필요하다.

| 정렬 | 평균 시간 | 최악 시간 | 안정성 | 특징 |
| --- | --- | --- | --- | --- |
| Quick | O(nlogn) | O(n²) | 보통 불안정 | pivot 선택 중요 |
| Merge | O(nlogn) | O(nlogn) | 안정 | 추가 공간 필요 |
| Heap | O(nlogn) | O(nlogn) | 불안정 | 제자리 가능 |
| Insertion | O(n²) | O(n²) | 안정 | 거의 정렬된 입력에 유리 |

(표 해설) 표는 핵심 비교 포인트만 요약한 것이다. 시험에서는 각 알고리즘의 '언제 유리한가', '공간 복잡도', '안정성 여부', '실제 구현 시 주의점'을 함께 서술하는 것이 좋다.

## 쉽게 이해하기

- 정렬은 데이터를 찾기 좋게 순서대로 세우는 작업이다. 책을 가나다순으로 꽂는 것과 같다. 정렬된 상태에서는 탐색(검색)이 효율적이다.
- 탐색은 원하는 값을 찾는 작업이다. 정렬되어 있을 때의 대표적 탐색이 이진 탐색(binary search)으로, 매번 검사를 통해 검색 범위를 절반으로 줄인다.
- 문제 풀이 관점: 정렬 비용과 이후 탐색/처리로 얻는 이득을 함께 고려해야 한다. 예를 들어, 한 번의 탐색만 필요한 경우 정렬 비용이 오히려 손해일 수 있다.

(그림 해설) 정렬된 배열에서 중간값을 비교해 대상이 중간보다 작으면 왼쪽 절반만, 크면 오른쪽 절반만 다시 조사하는 과정을 반복한다. 경계(off-by-one)와 루프 종료 조건을 시험에서 자주 묻는다.

## 코드 예시 (의사코드)

- 이진 탐색 (반복형)

```
function binary_search(A, target):
  lo = 0
  hi = len(A) - 1
  while lo <= hi:
    mid = lo + (hi - lo) // 2
    if A[mid] == target:
      return mid
    else if A[mid] < target:
      lo = mid + 1
    else:
      hi = mid - 1
  return -1  # not found
```

- 퀵 정렬 (기본 재귀형, 분할 후 재귀)

```
function quicksort(A, lo, hi):
  if lo >= hi: return
  pivot_index = partition(A, lo, hi)  # 분할을 수행하고 pivot의 최종 위치 반환
  quicksort(A, lo, pivot_index - 1)
  quicksort(A, pivot_index + 1, hi)
```

(시험에서 요구하면 partition 알고리즘(예: Lomuto, Hoare)을 설명하고 최악의 경우가 언제 발생하는지 서술할 것)

## 시험 포인트 (빈출)

- 이진 탐색의 경계 조건(lo, hi, mid 계산)과 루프/재귀 종료 조건을 정확히 설명하거나 구현하라.
- 퀵정렬의 평균/최악 시간복잡도 유도(분할 균형/편향 경우) 및 pivot 선택 방식(임의 선택, 중앙값 선택)에 따른 영향.
- 병합정렬의 안정성, 분할·병합 과정의 시간·공간 분석. 병합정렬을 제자리(in-place)로 변형하는 어려움.
- 힙정렬의 힙 구성(빌드 힙) 비용 O(n)과 힙 정렬 전체 비용 O(n log n) 유도, 제자리 구현의 의미.
- 삽입정렬의 장점: 작은 n이나 거의 정렬된 데이터에서 매우 빠름. 즉시 정렬(online) 특성.
- Counting/Radix 정렬의 적용 조건(키 범위 제한, 정수/문자열 등)과 공간 복잡도 고려.
- 안정성 판단: 어떤 상황에서 안정 정렬이 반드시 필요한지(다중 키 정렬) 사례로 설명.
- 공간 복잡도(추가 배열, 재귀 스택) 명시.

## 실무 연결 (실용 팁)

- 실제 개발에서는 검증된 라이브러리 구현(표준 라이브러리의 sort/stable_sort 등)을 사용하는 것이 일반적이다. 시험에서는 구현 원리와 복잡도 분석을 묻는다.
- 정렬 알고리즘 선택 기준:
  - 데이터 크기(n)
  - 이미 정렬된 정도(삽입정렬 유리)
  - 안정성이 필요한지 여부(예: UI에서 다중 키 정렬)
  - 메모리 제약(제자리 정렬 필요)
  - 키의 성격(정수/문자열 혹은 큰 객체)
- 성능 최적화 팁:
  - 퀵정렬 구현에서 pivot을 무작위로 선택하면 최악 케이스 확률을 낮출 수 있다.
  - 작은 부분 배열에 대해서는 삽입정렬로 전환하면 상수계수 이득을 얻는다.
  - 병합 정렬은 외부 정렬(디스크 기반 대용량 데이터 정렬)에 적합하다.
  - Radix/Counting은 키 범위가 작고 메모리 허용 시 매우 빠르다.
- 병렬화: 분할 정렬(예: 병합정렬의 분할)과 같은 알고리즘은 병렬화하기 용이하다. 실무에서는 멀티코어를 활용한 병렬 정렬이 성능 개선에 유용하다.

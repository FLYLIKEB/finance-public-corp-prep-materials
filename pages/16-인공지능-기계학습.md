한국은행 컴퓨터공학 전공학술에서는 인공지능과 기계학습이 전산학 기본 이론과 금융 데이터 활용 관점에서 연결될 수 있다. 이 장은 최신 트렌드가 아니라 필기 답안에 필요한 기본 개념, 모델, 평가, 위험 관리를 정리한다. 금융공기업 필기 및 면접에서 자주 요구되는 실무 연결점과 짧은 답변 포인트를 함께 제공한다.

## 핵심 개념

- **AI / Machine Learning / Deep Learning**
  - AI: 지능적 행동을 수행하는 시스템 전체(정책·규칙·학습 포함).
  - ML: 데이터로부터 규칙(함수)을 추정하는 방법론(통계적 관점 강조).
  - DL: 다층 신경망(표현 학습)을 사용해 복잡한 비선형 관계를 모델링.
  - 면접 포인트: 정의 → 간단한 예시(예: 신용평가(ML) vs. 챗봇(DL)) → 금융 적용(어떤 문제에 적합한지)을 30초 내 정리.

- 학습 유형
  - 지도학습: 입력 X와 라벨 Y를 이용해 f(X)=Y를 학습(회귀/분류).
  - 비지도학습: 군집, 이상치 탐지, 차원축소 등에 사용(라벨 없음).
  - 강화학습: 행동 A의 보상을 최대화하는 정책 학습(주로 트레이딩·시뮬레이션 연구).
  - 면접 포인트: 각 유형의 금융 예시(신용평가=지도, 이상거래탐지=비지도+지도 혼합, 포트폴리오 최적화 연구=강화학습).

- 손실·학습·최적화
  - 손실함수: 예측과 정답 차이(예: 회귀=MSE, 분류=cross-entropy).
  - 최적화: 경사하강법(gradient descent) 기반 업데이트, 학습률·배치크기·초기화 영향 큼.
  - 정규화: L1/L2, 드롭아웃 등으로 과적합 완화.
  - 면접 포인트: 학습률과 배치크기의 트레이드오프, 조기종료(early stopping) 설명.

- 과적합 vs 과소적합
  - 과적합(overfitting): 훈련 성능은 좋지만 일반화가 나쁨(복잡한 모델·데이터 부족 원인).
  - 과소적합(underfitting): 모델이 데이터의 기본 패턴도 못 잡음(모델 단순성·특성 부족).
  - Bias-variance trade-off: 편향(bias) 감소는 보통 분산(variance) 증가로 이어짐.
  - 면접 포인트: 금융 데이터에서 과적합을 방지하기 위한 실무 조치(교차검증, 정규화, 피처 엔지니어링, 보수적 성능 보고).

## 학습·검증 절차

| 단계 | 목적 | 주의점 |
| --- | --- | --- |
| Train | 모델 파라미터 학습 | 데이터 누수 방지(훈련 데이터만 사용), 시계열인 경우 시간순 분리 |
| Validation | 하이퍼파라미터 선택 | 테스트셋을 반복 사용하지 않음, 교차검증 시 fold 분포 확인 |
| Test | 최종 일반화 성능 평가 | 학습 종료 후 한 번만 사용, 백테스트(시계열)에 유의 |
| Cross-validation | 데이터가 적을 때 안정적 평가 | fold 간 분포 차이 확인, 시계열 CV는 시간블록 기반 분리 권장 |

- Data leakage(데이터 누수) 예시(금융):
  - 승인 이후에만 생성되는 변수(예: 고객의 사후 행동)가 훈련에 포함됨.
  - 타임스탬프를 무시한 무작위 분할로 미래 정보가 훈련에 섞이는 경우.
  - 전체 데이터로 표준화(mean/std)를 계산해 훈련·검증·테스트에 동일 통계 적용.
- 실무 조치(검증 절차 체크리스트):
  - 시간 기반 분할(time split) 적용 여부 확인(거래/결제 데이터 등).
  - 피처 생성 시 사용 가능한 시점(feature as-of)을 명시.
  - 데이터 파이프라인에서 재현성(시드 고정, 버전 관리) 확보.
  - 레이블 지연(label latency) 고려: 라벨확정까지 걸리는 시간 반영.

- 면접 질문 대비(짧은 답변 템플릿):
  - "데이터 누수를 어떻게 검사하나요?" → "레이블 생성 시점과 각 피처의 생성 시점을 대조하고, 시계열 분리를 통해 재현성 테스트를 진행합니다. 전체 통계로 스케일링하지 않고, 훈련에서 계산한 파라미터만 사용합니다."

## 평가 지표

| 지표 | 의미 | 쓰임 |
| --- | --- | --- |
| Accuracy | 전체 중 맞춘 비율 | 클래스 균형일 때 직관적(불균형 데이터에서는 오해 유발) |
| Precision | 양성 예측 중 실제 양성 비율 = TP / (TP+FP) | 오탐(False Positive) 비용이 클 때(예: 의심거래로 과도한 조사 발생) |
| Recall | 실제 양성 중 찾아낸 비율 = TP / (TP+FN) | 미탐(False Negative) 비용이 클 때(예: 사기 미탐지) |
| F1 | precision과 recall의 조화평균 | 불균형 데이터에서 균형 있는 평가 |
| ROC-AUC | 임계값 변화에 따른 분류 성능(전체 순위 능력) | 클래스 불균형 시에도 사용 가능하나, 실제 비용 반영은 아님 |

- 추가 고려사항
  - PR-AUC(Precision-Recall AUC): 긍정 클래스가 희소할 때 ROC보다 해석에 유리.
  - 임계값 선정: 운영 비용(탐지·조사 비용)에 따라 precision/recall 트레이드오프를 조정.
  - 비용 행렬(cost matrix): FP, FN 각각의 금전·운영 비용을 정량화해 최적의 임계값 설정.
  - 백테스트: 시계열 모델은 과거 시점부터 순차적으로 평가(백테스트)해 실전 성능을 확인.

- Confusion matrix(혼동행렬)과 실무 예시
  - 구성: TP, FP, FN, TN.
  - 예: 이상거래탐지에서 TN이 대부분인 경우 accuracy는 높으나 실무 관점에서는 의미가 없음. 이 경우 recall(미탐 최소화)과 precision(조사 비용 통제)을 함께 제시.

- 면접 포인트: "모델 성능이 좋게 나왔는데도 배포하지 못하는 경우"
  - 데이터 누수 의심, 샘플링 편향, 라벨의 신뢰도 문제, 설명가능성 부족, 규제·내부통제 미비 등을 이유로 듦.

## 주요 모델

- 선형 모델
  - Linear regression: 연속값 예측에 간단·해석 가능. 다중공선성(VIF) 체크 필요.
  - Logistic regression: 이진 분류에서 베이스라인으로 유용. 특성 중요도 해석이 쉬움.
  - 실무 적용 포인트: 규제 환경에서는 해석 가능한 모델 선호.

- Tree 계열
  - Decision tree: 규칙 기반, 해석성 높음 but 과적합 쉬움.
  - Random forest: 배깅으로 분산 감소, 기본 성능 강건.
  - Gradient boosting (예: XGBoost, LightGBM): 부스팅으로 편향 감소, 금융 데이터(수치·카테고리 혼합)에 널리 사용.
  - 실무 포인트: 결측치·스케일에 둔감, 변수 중요도(feature importance) 제공으로 규제 대응에 도움.

- SVM
  - 마진 기반 분류, 커널로 비선형 처리 가능. 대규모 데이터에는 계산비용 큼.
  - 실무 포인트: 중간 규모 데이터·고차원 특성에 사용 가능하나 최근에는 트리 기반 모델·딥러닝에 밀리는 경향.

- 비지도 학습
  - K-means: 군집 중심 기반, 초기 k 선택·스케일 민감.
  - PCA: 차원 축소, 노이즈 제거 및 시각화에 유용(피처 엔지니어링 전처리로 활용).
  - 이상치 탐지 모델(LOF, Isolation Forest 등): FDS 초기 필터링 단계에서 쓰임.

- 신경망(딥러닝)
  - 구성요소: perceptron, 활성화 함수(ReLU, sigmoid 등), 손실, 역전파(backpropagation), 최적화.
  - 강점: 복잡한 비선형성·대용량 데이터에 강함(문서분류, 음성, 시퀀스 데이터 등).
  - 실무 포인트: 설명가능성·과적합·컴퓨팅 비용 이슈로 규제 민감 업무(신용평가 등)에는 보수적 접근 권장.

- 면접 대비: "어떤 모델을 선택하나요?"
  - 간단 모델(선형·로지스틱)로 베이스라인 → 트리 계열로 성능 개선 → 필요 시 딥러닝 적용. 해석성·데이터 크기·피처 특성·규제조건을 고려해 설명.

## 금융권 적용과 위험

- 주요 적용 사례(짧은 설명 포함)
  - 신용평가: 대출 승인 · 한도 산정에 활용(신용점수 모델). 안정성과 설명가능성이 중요.
  - 이상거래탐지(FDS): 실시간 규칙·모델 결합, 높은 Recall 요구 + 조사 비용 통제 필요.
  - AML(자금세탁방지): 네트워크 분석·행동 패턴 학습, 규제기관에 제출 가능한 근거 마련 필요.
  - 상담 챗봇·문서분류: 고객 응대 자동화, 개인정보 처리 및 응답 정확성 관리 필요.

- 설명가능성(XAI) 요구사항
  - 이유: 소비자 권익 보호, 내부감사, 감독당국 대응.
  - 기법: 단일 예측에 대한 설명(예: SHAP, LIME), 전반적 특성 영향 분석, 규칙 기반 보완.
  - 면접 포인트: "왜 이 고객을 거절했는지 설명하라"에 대한 간결한 답변(상위 피처·임계값 근거 제시)을 준비.

- 모델 리스크 관리(운영 단계 포함)
  - 데이터 품질 관리: 입력 분포 모니터링, 결측·오류 탐지.
  - 편향 및 공정성 점검: 특성별 성능(연령·성별 등) 비교, 차별적 결과 최소화 대책.
  - 성능 모니터링: Drift 감지(데이터·레이블 드리프트), 주기적 재학습 트리거 정의.
  - 검증·승인 절차: 독립 검증(모델리스크팀), 문서화(모델 설명서, 데이터 라인지), 감사 로그 보관.
  - 운영 보안: 접근통제·키 관리·모델 서명.

- 개인정보 보호와 준수
  - 최소 수집 원칙, 목적 제한, 가명처리·비식별화, 접근권한 제한.
  - 개인정보가 민감할 경우 모델 입력에서 제외하거나 별도 평가(대표성·편향) 수행.

- 면접 예시 질문과 모범 응답 포인트
  - Q: "신용평가 모델의 공정성을 어떻게 검증하겠나?"
    - A 포인트: 집단별 성능(precision/recall·FPR) 비교, 중요 변수 영향 분석, 정책적 예외 처리·인간 검토 라인 도입.
  - Q: "이상거래탐지 모델의 실시간 성능을 보장하려면?"
    - A 포인트: 라이트웨이트 피처·모델(온라인 추론), 큐잉·샘플링 전략, 실시간 피드백 루프와 재학습 파이프라인.

## 약어 풀이

- AI: Artificial Intelligence, 인공지능
- AUC: Area Under the Curve, 곡선 아래 면적
- FDS: Fraud Detection System, 이상거래탐지시스템
- ML: Machine Learning, 기계학습
- PCA: Principal Component Analysis, 주성분 분석
- ROC: Receiver Operating Characteristic, 수신자 조작 특성
- SVM: Support Vector Machine, 서포트 벡터 머신
- XAI: Explainable AI, 설명가능 인공지능

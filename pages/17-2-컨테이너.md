# 17-2. 컨테이너

## 핵심 개념

- 컨테이너는 애플리케이션과 의존성을 이미지로 묶고, 호스트 OS 커널을 공유해 격리 실행하는 방식이다.
- Docker image는 불변 실행 패키지이고, container는 image의 실행 인스턴스다.
- Kubernetes는 컨테이너 배포, 서비스 발견, 스케일링, 롤링 업데이트, self-healing을 제공하는 오케스트레이션 플랫폼이다.

| 구성 요소 | 역할 |
| --- | --- |
| Pod | 하나 이상의 컨테이너를 묶는 최소 배포 단위 |
| Deployment | 원하는 Pod 개수와 업데이트 전략 관리 |
| Service | Pod 집합에 안정적인 접근 지점 제공 |
| Ingress | 외부 HTTP/S 트래픽 라우팅 |
| ConfigMap/Secret | 설정과 민감정보 분리 |

## 금융권 답안 포인트

컨테이너는 배포 일관성과 빠른 확장에 유리하지만 이미지 취약점, secret 관리, 런타임 권한, 네트워크 정책, 감사 로그가 중요하다. 금융 시스템에서는 CI/CD에서 이미지 서명과 취약점 스캔을 수행하고, 운영 클러스터에서는 namespace와 RBAC으로 권한을 분리한다.

# 09-01-02. 연결리스트

> 학습 목적: 연결리스트의 포인터 구조와 장단점을 정리한다.
> 관련 기출: [05-13-알고리즘-기출-모음](05-13-알고리즘-기출-모음.md)

## 핵심 개념

- 노드는 데이터와 다음 노드 주소(포인터)를 가진다. 일반적으로 하나의 노드 구조체는 다음과 같은 필드로 구성된다: 데이터 필드, 다음 포인터(또는 이전 포인터 포함).
- 삽입·삭제는 포인터 변경으로 처리한다. 즉, 기존 노드의 포인터를 새 노드를 가리키도록 바꾸거나, 삭제할 노드의 이전 노드가 삭제할 노드의 다음을 가리키도록 변경한다.
- 임의 접근(random access)은 배열보다 느리다. 임의 위치에 접근하려면 첫 노드(head)부터 순차적으로 따라가야 하므로 O(n)이 걸린다.

### 용어 정리

- head: 리스트의 첫 노드를 가리키는 포인터.
- tail: 리스트의 마지막 노드를 가리키는 포인터(있을 수도 있고 없을 수도 있음).
- null / nullptr: 리스트의 끝을 나타내는 값.
- 노드(node): 데이터와 포인터를 포함하는 단위.

## 쉽게 이해하기

- 연결리스트는 각 칸이 다음 칸의 위치를 들고 있는 구조다. 지하철 노선에서 다음 역 정보를 따라가는 느낌이다.
- 중간 삽입과 삭제는 연결만 바꾸면 되지만, 특정 번째 원소를 바로 찾기는 어렵다. 예를 들어 5번째 원소를 찾으려면 1→2→3→4→5 순으로 따라가야 한다.
- 배열과 비교할 때 접근 속도와 삽입·삭제 비용을 함께 봐야 한다. 배열은 인덱스로 O(1) 접근이 가능하지만, 삽입·삭제 시에는 이동(cost)이 발생할 수 있다.

## 구현 관점: 자주 묻는 연산과 의사코드

- 기본 연산
  - 탐색(traverse): head부터 next를 따라가며 방문.
  - 삽입(insert): 위치에 따라 헤드 삽입, 꼬리 삽입, 중간 삽입으로 나뉨.
  - 삭제(delete): 삭제할 노드의 이전 노드를 알고 있는가에 따라 구현이 달라짐.

- 삽입(헤드에 삽입) 의사코드

```
# 새 노드를 head 앞에 추가 (C 스타일 의사코드)
new_node.next = head
head = new_node
```

- 삭제(특정 값의 첫 발생을 삭제) 의사코드

```
# 특정 값을 가진 노드를 삭제
if head == null: return
if head.value == target:
    head = head.next
    return
prev = head
curr = head.next
while curr != null:
    if curr.value == target:
        prev.next = curr.next
        return
    prev = curr
    curr = curr.next
```

- 꼬리 삽입: tail 포인터가 있으면 O(1), 없으면 O(n) (마지막까지 순회해야 함).

## 시간 복잡도 표 (단일 연결 리스트, 일반적 상황)

| 연산 | 시간 복잡도 |
|---|---:|
| 접근 (i번째 원소 읽기) | O(n) |
| 탐색 (값 찾기) | O(n) |
| 헤드에 삽입 | O(1) |
| 헤드에서 삭제 | O(1) |
| 임의 위치(포인터 알고 있는 경우) 삽입/삭제 | O(1) |
| 꼬리에 삽입 (tail 포인터 없을 때) | O(n) |

> 메모: tail 포인터를 유지하는 경우 꼬리 삽입은 O(1)이 될 수 있다. 하지만 랜덤 접근은 여전히 O(n)이다.

## 장단점 요약 (시험용 문장)

- 장점
  - 동적 크기 조정이 용이하므로 메모리 활용이 효율적이다(필요한 만큼 노드를 할당).
  - 삽입과 삭제가 포인터 조작으로 이루어져 특정 상황에서 매우 빠르다(특히 리스트 앞쪽 또는 포인터를 알고 있을 때).

- 단점
  - 임의 접근이 불가능하여 특정 인덱스 접근이 느리다(O(n)).
  - 추가적인 포인터(메모리 오버헤드)를 필요로 한다.
  - 캐시 친화도가 낮아 배열보다 실제 실행 속도가 느릴 수 있다.

## 시험 대비 체크리스트

- [ ] 단일(singly)/이중(doubly)/원형(circular) 연결리스트의 차이점을 설명할 수 있다.
- [ ] 헤드(head)와 테일(tail)의 역할과 유지 비용을 설명할 수 있다.
- [ ] 노드 삭제 시 이전 노드(prev)가 왜 필요한지 설명할 수 있다.
- [ ] 포인터를 알고 있는 경우 삽입/삭제가 O(1)인 이유를 말할 수 있다.
- [ ] 연결리스트와 배열의 장단점을 비교해 설명할 수 있다.
- [ ] 간단한 삽입/삭제/탐색 의사코드를 작성할 수 있다.

## 시험형 문제 예시 (문제 + 풀이 요지)

1) 문제: 단일 연결리스트에서 k번째 노드를 삭제하려면 어떤 과정을 거쳐야 하는가? 시간 복잡도는?
   - 풀이 요지: k번째 노드의 이전 노드까지 순회(1..k-1)하여 prev를 찾은 뒤 prev.next = prev.next.next로 연결을 끊음. 시간 복잡도 O(k) = 최악 O(n).

2) 문제: 연결리스트에서 tail 포인터를 유지하면 어떤 연산이 빨라지는가? 그리고 어떤 단점이 추가되는가?
   - 풀이 요지: 꼬리 삽입이 O(1)로 빨라진다. 단점으로는 구조가 복잡해지고(테일 포인터 갱신 필요), 일부 삭제 연산(예: tail 삭제 시 이전 노드를 찾기 위해 O(n)이 필요할 수 있음)이 남아 있음.

3) 문제: 연결리스트로 스택을 구현할 때 어떤 쪽에 삽입/삭제를 해야 효율적인가? 이유는?
   - 풀이 요지: 리스트의 head 쪽을 사용하면 삽입/삭제가 모두 O(1)로 가능하므로 효율적이다.

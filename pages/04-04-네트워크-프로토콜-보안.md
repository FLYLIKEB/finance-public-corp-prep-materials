## 프로토콜

> 중요도: **상** (★★★)


![주요 프로토콜 계층 지도](https://upload.wikimedia.org/wikipedia/commons/thumb/8/8d/OSI_Model_v1.svg/500px-OSI_Model_v1.svg.png)
> 그림: OSI 7계층 구조 기반으로 주요 프로토콜 계층 지도 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:OSI_Model_v1.svg

### 1. 개념

: 컴퓨터 네트워크에서 데이터 통신을 위해 정해진 규칙이나 표준. 데이터가 어떻게 전송되고,
수신되고, 처리되어야 하는지를 정의

### 2. 종류

CMIP (Common Management Information Protocol)
- **설명:** 네트워크 장치와 시스템을 관리하기 위한 네트워크 관리 프로토콜로, OSI 모델 기반임.
- **특징:** 관리 정보베이스(MIB)를 사용하여 네트워크 장치의 상태를 모니터링하고 제어함.

IPX (Internetwork Packet Exchange)
- **설명:** Novell NetWare 환경에서 사용되는 네트워크 계층 프로토콜.
- **특징:** 연결 지향적이지 않으며, 패킷의 순서 보장이나 오류 수정 기능이 없음.

TCP (Transmission Control Protocol)
- **설명:** 데이터의 신뢰성 있는 전송을 보장하는 인터넷 프로토콜.
- **특징:** 연결 지향적이며, 데이터 전송 전에 연결을 설정하고, 데이터의 순서 보장 및 오류
  수정 기능 제공.

SNMP (Simple Network Management Protocol)
- **설명:** 네트워크 관리 프로토콜로, 네트워크 장치의 모니터링과 관리를 위해 사용됨.
- **특징:**
  관리 정보베이스(MIB)를 통해 네트워크 장치의 상태 정보를 수집함.
  트랩(trap) 메시지를 통해 이벤트 발생 시 관리자에게 알림을 전송함.
  인증, 접근제어, 보안 로그 등 네트워크 관리 정보에 보안 체계를 갖춘 프로토콜.
  OSI 참조 7 계층 프로토콜을 사용하여 정보를 전송함.
  이벤트 발생 기능을 지원하여 관리 프로세스가 관리 대상을 계속 모니터링할 필요가 없음.

SPX (Sequenced Packet Exchange)
- **설명:** IPX 와 함께 사용되는 연결 지향적 프로토콜로, Novell NetWare 환경에서 주로 사용됨.
- **특징:** IPX 위에서 동작하며, 데이터의 순서 보장 및 오류 수정 기능 제공.

X.25
- 설명 : 패킷 교환 네트워크를 통해 데이터 통신을 하기 위한 표준 프로토콜
- 특징
  패킷 교환 방식: 데이터를 작은 패킷으로 나누어 전송하며, 각 패킷은 독립적으로 전송되고
  재조립됨.
  연결 지향적: 데이터 전송 전에 먼저 가상 회선을 설정하여 안정적인 전송을 보장함.
  오류 수정 및 흐름 제어: 전송 중 발생할 수 있는 오류를 감지하고 수정하며, 데이터 손실을
  방지함.
  네트워크 및 데이터 링크 계층에서 동작: OSI 모델의 네트워크 계층과 데이터 링크 계층에서
  데이터 전송을 처리함.

IPv4 (Internet Protocol version 4)
- **주소 형식:** 32 비트 주소를 사용하며, 4 개의 10 진수로 표기(예: 192.168.0.1).
- **주소 공간:** 약 43 억 개의 고유 주소 제공.
- 주소 고갈 문제: 인터넷 사용자의 급증으로 인해 IPv4 주소가 부족함.
- **기타 특징:** 주로 점-분리 10 진수로 표현되고, 네트워크 주소 변환(NAT)을 통해 주소를
  확장함.

IPv6 (Internet Protocol version 6)
- **주소 형식:** 128 비트 주소를 사용하며, 8 개의 16 진수로 표기(예:
  2001:0db8:85a3:0000:0000:8a2e:0370:7334).
- **주소 공간:** 사실상 무한대에 가까운 주소 제공.
- 주소 고갈 해결: IPv4 주소 고갈 문제를 해결하기 위해 설계됨.
- **기타 특징:** 향상된 보안(IPSec), 자동 구성 기능, 더 효율적인 라우팅, 그리고 NAT 불필요.

#### 주요 프로토콜 암기표

| 프로토콜 | 계열/계층 | 핵심 역할 | 선지 판단 포인트 |
| --- | --- | --- | --- |
| CMIP | OSI 관리 | 네트워크 장치 관리 | OSI 기반 관리 프로토콜 |
| SNMP | TCP/IP 관리 | 장비 모니터링·Trap | MIB, Trap 메시지 |
| IPX | NetWare 네트워크 | 패킷 전달 | 비연결형, Novell |
| SPX | NetWare 전송 | 순서 보장 | IPX 위에서 연결 지향 |
| TCP | 전송 계층 | 신뢰성 있는 전송 | 연결 지향, 순서 보장 |
| X.25 | 패킷 교환 | 가상 회선 기반 전송 | 오류·흐름 제어 |

## 네트워크

> 중요도: **중** (★★)


![네트워크 연결 방식](https://upload.wikimedia.org/wikipedia/commons/thumb/6/6e/LAN_WAN_scheme.svg/960px-LAN_WAN_scheme.svg.png)
> 그림: LAN과 WAN 연결 구조 기반으로 네트워크 연결 방식 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:LAN_WAN_scheme.svg

### 1. NIC(Network Interface Card)

**개념:** 컴퓨터를 네트워크에 연결하는 하드웨어 장치. 컴퓨터 내부의 데이터를 네트워크를 통해
전송할 수 있는 신호로 변환하고, 반대로 네트워크에서 수신된 신호를 컴퓨터가 이해할 수 있는
데이터로 변환하는 역할을 함. 이를 통해 컴퓨터가 다른 컴퓨터나 네트워크 장비와 통신할 수 있게
해줌.

주요기능 및 특징
- 데이터 전송: NIC 는 데이터를 네트워크를 통해 송수신하는 기능을 함. 이를 위해 이더넷
  (Ethernet), Wi-Fi 등 다양한 네트워크 표준을 지원함.
- MAC 주소: NIC 에는 고유한 식별자인 MAC(Media Access Control) 주소가 할당되어 있음.
  MAC 주소는 네트워크 상에서 장치를 구별하는 데 사용됨.
- 유선 및 무선: NIC 는 유선(이더넷 케이블) 및 무선(Wi-Fi) 네트워크를 지원할 수 있음. 유선
  NIC 는 이더넷 포트를 통해 네트워크에 연결되며, 무선 NIC 는 무선 주파수를 통해
  네트워크에 연결됨.
- 프로토콜 지원: NIC 는 TCP/IP, IPX/SPX, NetBEUI 등 다양한 네트워크 프로토콜을 지원하여
  러 가지 네트워크 환경에서 작동할 수 있음.

### 2. 네트워크 연결방식

LAN (Local Area Network)
- **정의:** 제한된 공간(일반적으로 하나의 건물이나 캠퍼스 내)을 커버하는 네트워크.
- 사용 예시: 가정 내 네트워크, 소규모 사무실 네트워크
- **특징:**
  짧은 거리(수십 미터에서 수백 미터)를 커버함
  높은 데이터 전송 속도
  유선(이더넷) 및 무선(Wi-Fi) 연결을 포함함
  설치와 관리가 비교적 간단함

WAN (Wide Area Network)
- **정의:** 넓은 지역(도시, 국가, 대륙, 전 세계)을 커버하는 네트워크.
- 사용 예시: 인터넷, 기업의 지사 간 연결
- **특징:**
  매우 긴 거리(수 km 에서 수천 km)를 커버함
  비교적 낮은 데이터 전송 속도
  다양한 전송 매체(광섬유, 위성, 공공 네트워크)를 사용함
  구축과 관리가 복잡하고 비용이 많이 듦

CAN (Campus Area Network)
- **정의:** 대학 캠퍼스나 기업 단지 내의 여러 건물을 연결하는 네트워크.
- 사용 예시: 대학교의 학내 네트워크, 대형 기업의 사내 네트워크
- **특징:**
  LAN 보다 넓은 범위(수 km)를 커버하지만 MAN 보다 좁음
  고속 데이터 전송 가능
  일반적으로 광섬유 케이블을 사용함
  한정된 지역 내에서 다양한 건물 간 연결을 제공함

GAN (Global Area Network)
- **정의:** 전 세계를 커버하는 네트워크.
- 사용 예시: 인터넷
- **특징:**
  글로벌 범위를 커버함
  WAN 의 일종으로, 매우 큰 규모의 네트워크
  다양한 국가와 대륙을 연결함
  통신 위성, 광섬유 케이블, 해저 케이블 등을 이용함

#### 네트워크 범위 비교표

| 구분 | 범위 | 대표 예시 | 암기 포인트 |
| --- | --- | --- | --- |
| LAN | 건물·사무실 | 가정, 소규모 사무실 | 가장 좁고 빠름 |
| CAN | 캠퍼스·기업 단지 | 대학교, 대기업 사옥 | LAN보다 넓고 MAN보다 좁음 |
| WAN | 도시·국가·대륙 | 지사 간 연결, 인터넷망 | 넓은 지역 연결 |
| GAN | 전 세계 | 인터넷 | 가장 넓은 범위 |

## 공개키 알고리즘 vs 대칭키 알고리즘

> 중요도: **중** (★★)


![대칭키와 공개키 암호](https://upload.wikimedia.org/wikipedia/commons/thumb/f/f0/Asymmetric_encryption_scheme.png/960px-Asymmetric_encryption_scheme.png)
> 그림: 비대칭 공개키 암호화 구조 기반으로 대칭키와 공개키 암호 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Asymmetric_encryption_scheme.png

### 1. 공캐키 알고리즘
- 개념 : 비대칭 암호화 방식으로, 암호화와 복호화에 서로 다른 키(공개키와 개인키)를
  사용하는 알고리즘
- 주요 알고리즘
#### RSA (Rivest-Shamir-Adleman)
  설명: 소인수 분해의 어려움에 기반을 둔 알고리즘.
  특징: 데이터 암호화와 디지털 서명에 널리 사용됨. 보안성이 높지만 연산 속도가 느림.
#### DSA (Digital Signature Algorithm)
  설명: 디지털 서명에 특화된 알고리즘으로, 디피-헬만 키 교환 문제에 기반함.
  특징: 디지털 서명에 주로 사용되며, 서명 생성과 검증에 특화됨.
- 공개키 알고리즘의 장점
  키 분배 용이: 공개키를 이용해 안전하게 키를 교환할 수 있음.
  확장성: 다수의 사용자와 안전하게 통신할 수 있음.
  보안성: 대칭키 알고리즘보다 높은 보안성을 제공함.
- 공개키 알고리즘의 단점
  연산 속도: 대칭키 알고리즘에 비해 연산 속도가 느림.
  복잡성: 구현과 관리가 더 복잡함.
  자원 소모: 더 많은 계산 자원을 요구함.
- 공개키 알고리즘의 응용
  데이터 암호화: 이메일, 파일 등 민감한 데이터를 안전하게 보호함.
  디지털 서명: 문서나 소프트웨어의 무결성과 출처를 검증함.
  키 교환: 안전한 통신을 위해 대칭키를 안전하게 교환함.

### 2. 대칭키 알고리즘

#### 공개키 vs 대칭키 비교표

| 구분 | 공개키 알고리즘 | 대칭키 알고리즘 |
| --- | --- | --- |
| 키 사용 | 공개키와 개인키가 다름 | 암호화·복호화 키가 같음 |
| 속도 | 느림 | 빠름 |
| 키 분배 | 상대적으로 쉬움 | 안전한 키 전달이 어려움 |
| 대표 알고리즘 | RSA, DSA | AES, DES, RC4 |
| 주 용도 | 키 교환, 전자서명 | 대량 데이터 암호화 |

```text
공개키 암호화 흐름
송신자: 수신자의 공개키로 암호화
  ↓
네트워크 전송
  ↓
수신자: 자신의 개인키로 복호화

대칭키 암호화 흐름
송신자와 수신자: 같은 비밀키 공유
  ↓
같은 키로 암호화/복호화
```
- 개념 : 암호화와 복호화에 동일한 키를 사용하는 암호화 방식. 속도가 빠르고 효율적이지만,
  키 분배와 관리가 어려운 단점
- 주요 알고리즘
#### AES (Advanced Encryption Standard)
  설명: 매우 강력하고 효율적인 블록 암호 알고리즘으로, 미국 정부 표준으로 채택됨.
  특징: 빠르고 보안성이 높아 다양한 응용 분야에서 사용됨.
#### DES (Data Encryption Standard)
  설명: 과거에 널리 사용되었으나, 보안성이 약해짐에 따라 현재는 거의 사용되지 않음.
  특징: 짧은 키 길이로 인해 현재는 안전하지 않음.
#### RC4
  설명: 스트림 암호 알고리즘으로, 간단하고 빠른 암호화 방식.
  특징: 과거에는 널리 사용되었으나, 여러 보안 취약점이 발견됨.
- 대칭키 알고리즘의 장점
  속도: 암호화와 복호화가 빠름.
  효율성: 계산이 단순하여 자원이 적게 소모됨.
  안정성: 적절히 관리된 키를 사용하면 매우 안전함.
- 대칭키 알고리즘의 단점
  키 분배 문제: 안전한 채널을 통해 키를 교환해야 하는 어려움이 있음.
  확장성 부족: 다수의 사용자 간에 키를 관리하기가 어려움.
  키 관리: 각 통신 쌍마다 다른 키를 사용해야 하므로 키 관리가 복잡해짐.
- 대칭키 알고리즘의 응용
  파일 암호화: 개인 데이터와 파일을 안전하게 보호하기 위해 사용됨.
  네트워크 통신 보호: VPN, SSL/TLS 등에서 데이터를 안전하게 전송하기 위해 사용됨.
  디스크 암호화: 전체 디스크나 특정 파티션을 암호화하여 데이터 유출을 방지함.

사용되는 것은 무엇인가?

## 보안

> 중요도: **중** (★★)


![보안 공격과 방어 흐름](https://upload.wikimedia.org/wikipedia/commons/e/e8/Denial-of-service_attack.gif)
> 그림: 서비스 거부 공격 흐름 기반으로 보안 공격과 방어 흐름 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Denial-of-service_attack.gif

### 1. 공격 방법
- 디도스(DDoS): 여러 대의 컴퓨터를 통해 특정 서버나 네트워크에 과도한 트래픽을 유발시켜
  정상적인 서비스 운영을 방해하거나 마비시키는 사이버 공격
- 서비스 거부(Dos) : 무의미한 서비스 요청 등의 반복을 통해 특정 시스템의 가용자원을
  소모시켜 서비스 가용성을 저하시키는 공격기법
- SQL 인젝션 : 데이터베이스와 연동된 웹 애플리케이션에서 공격자가 입력 폼 및 URL
  입력란에 SQL 문을 삽입하여 DB 로부터 정보를 열람할 수 있는 공격기법
- 크로스 사이트 스크립팅(XSS) : 공격자가 게시판에 악성 스크립트를 작성, 삽입하여
  사용자가 그것을 보았을때 이벤트 발생을 통해 사용자의 쿠키정보, 개인정보 등을
  특정사이트로 전송하는 공격기법
- 트로이목마 : 악성 루틴이 숨어있는 프로글매으로 겉보기에는 정상적인 프로그램으로
  보이지만 실행하면 악성코드를 실행
- 스미싱 : 문자 메시지를 이용한 피싱 공격의 일종으로, 사용자의 개인정보나 금융 정보를
  탈취하기 위해 악성 링크가 포함된 SMS 를 전송함.
- 피싱 : 이메일, 메시지 등을 통해 사용자를 속여 사기 웹사이트로 유도하여 개인정보나 금융
  정보를 탈취하는 공격 방식임.
- 파밍 : 악성 코드를 이용해 사용자가 의도한 정상 웹사이트 대신 가짜 웹사이트로 유도하여
  개인정보를 탈취하는 공격 방식임.

#### 대표 공격 유형 비교표

| 공격 | 핵심 방식 | 주 피해 | 암기 키워드 |
| --- | --- | --- | --- |
| DoS | 한 공격자가 자원 고갈 유도 | 서비스 중단 | 단일 공격원 |
| DDoS | 여러 공격자가 대량 트래픽 발생 | 서비스 마비 | 분산 공격 |
| SQL Injection | SQL 문 삽입 | DB 정보 탈취·조작 | 입력값 검증 실패 |
| XSS | 악성 스크립트 삽입 | 쿠키·세션 탈취 | 게시판, 스크립트 |
| 피싱 | 가짜 메시지/사이트로 속임 | 계정·금융정보 탈취 | 이메일, 링크 |
| 파밍 | 정상 주소를 가짜 사이트로 유도 | 개인정보 탈취 | DNS/악성코드 |

```text
DDoS 흐름
[좀비 PC 다수] ──대량 요청──> [피해 서버]
[좀비 PC 다수] ──대량 요청──> [피해 서버]
[좀비 PC 다수] ──대량 요청──> [피해 서버]
```

> **출제 경향**   보통은 간단한 개념에 대한 객관식 문제가 출제되나 난이도가 높을시, 그림을 주고
해당 공격방법에 대한 설명으로 옳지 않은 것은? 식으로 나옵니다

### 2. 인증기술
- 지식기반 : ID/패스워드
- 소지기반 : 공인인증서, OTP
- 생체기반 : 홍채, 정맥, 얼굴, 지문
- 특징기반 : 서명, 발걸음, 몸짓

> **출제 경향**   거의 안나오는 문제지만, 은행 필기에 한번 출제되었습니다. 쉬운 개념이니 가볍게
숙지하기!

### 3. SSL

```text
SSL/TLS 핵심 흐름
1. 서버가 인증서를 제시
2. 클라이언트가 인증서로 서버 신원 확인
3. 공개키 방식으로 세션키를 안전하게 교환
4. 이후 데이터는 빠른 대칭키 방식으로 암호화
```

| 기능 | 의미 | 관련 기술 |
| --- | --- | --- |
| 기밀성 | 내용을 남이 볼 수 없게 함 | 대칭키 암호화 |
| 무결성 | 중간에 바뀌지 않았음을 확인 | 해시, MAC |
| 인증 | 통신 상대의 신원 확인 | 인증서, 공개키 |
**개념:** SSL(Secure Sockets Layer)은 인터넷을 통해 전송되는 데이터를 보호하기 위해 넷스케이프
(Netscape)에서 개발한 보안 프로토콜. 현재는 SSL 의 후속 버전인 TLS(Transport Layer Security)가
사용되고 있음.
주요기능
#### 기밀성 (Confidentiality)
- 암호화: 데이터를 암호화하여, 전송 중에 도청되더라도 내용을 알 수 없도록 보호함.
- 대칭 암호화: 세션 동안 데이터 전송에 사용되는 키를 생성하여 데이터를 암호화함.

#### 무결성 (Integrity)
- 해시 함수: 데이터가 전송되는 동안 변경되지 않았음을 보장하기 위해 해시 함수(MD5, SHA)
  를 사용하여 메시지 다이제스트를 생성함.
- 메시지 인증 코드 (MAC): 전송된 데이터가 수신자에게 도달할 때까지 변경되지 않았음을
  확인함.

#### 인증 (Authentication)
- 디지털 인증서: 서버와 클라이언트가 서로의 신원을 확인하기 위해 인증 기관(CA)이 발급한
  디지털 인증서를 사용함.
- 공개 키 암호화: SSL 핸드셰이크 동안 공개 키와 개인 키를 사용하여 상대방의 신원을
  확인하고 세션 키를 교환함.

> **출제 경향**   공기업 필기에서 자주 나오는 문제 재질. SSL 특징에 대해 묻는 문제가 종종 나옵니다.

## 해시함수

> 중요도: **중** (★★)


![해시함수 특성](https://upload.wikimedia.org/wikipedia/commons/c/c2/Hash_function.png)
> 그림: 해시 함수 구조 기반으로 해시함수 특성 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Hash_function.png

### 1. 개념
 임의의 입력 데이터를 고정된 크기의 해시 값(hash value) 또는 해시 코드(hash code)로 변환하는
함수.
### 2. 특징
- 고정된 크기 출력: 입력 데이터의 크기에 상관없이 항상 고정된 크기의 해시 값 출력
- 효율성: 데이터 검색, 삽입, 삭제를 빠르게 수행
- 충돌 가능성: 서로 다른 입력 데이터가 동일한 해시 값을 가질 수 있으며, 이를 해시 충돌
  (hash collision)이라고 함.
- 비가역성: 해시 값을 통해 원래의 입력 데이터를 복원하는 것이 거의 불가능

### 3. 해시함수 예시
- MD5: 128 비트 해시 값을 생성하는 해시 함수.
- SHA-1: 160 비트 해시 값을 생성하는 해시 함수.
- SHA-256: 256 비트 해시 값을 생성하는 해시 함수로, SHA-2 계열에 속함.

### 예시 문제

해시 함수의 주요 특징 중 하나는 무엇인가?
1. 입력 데이터의 크기에 따라 가변 크기의 해시 값을 생성한다
2. 데이터 검색, 삽입, 삭제를 효율적으로 수행할 수 있다
3. 해시 값을 통해 원래의 입력 데이터를 쉽게 복원할 수 있다
4. 해시 충돌이 발생하지 않는다

**정답:** 2. 데이터 검색, 삽입, 삭제를 효율적으로 수행할 수 있다

> **출제 경향**   은근 출제 되는 문제입니다. 해시함수 특징 또는 함수 예시(MD5 등)에 대한 설명을
물어보는 문제가 출제됩니다.

## TCP vs UDP

> 중요도: **중** (★★)


![TCP와 UDP 선택 기준](https://upload.wikimedia.org/wikipedia/commons/f/f8/Tcp_udp.jpg)
> 그림: TCP와 UDP 비교 기반으로 TCP와 UDP 선택 기준 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Tcp_udp.jpg

### 1. TCP(Transmission Control Protocol)

**개념:** 신뢰성 있고 순서가 보장된 데이터 전송을 제공함. TCP 는 인터넷과 대부분의 네트워크에서
데이터 패킷을 전송할 때 사용됨.

특징
- 연결 지향(Connection-oriented)
- 신뢰성 보장
- 패킷의 순서 보장
- 오류 검출 및 수정

장점

- 신뢰성: 데이터 전송의 신뢰성을 보장함.

- 순서 보장: 패킷이 올바른 순서로 전달됨.

- 흐름 제어 및 혼잡 제어: 네트워크 안정성을 유지함.

단점

- 오버헤드: 복잡한 헤더와 연결 설정으로 인해 오버헤드 발생.

- 지연 시간: 연결 설정과 확인 응답 과정으로 인해 지연 시간이 증가할 수 있음.

- 비용: 신뢰성을 보장하기 위해 더 많은 리소스 사용.

### 2. UDP(User Datagram Protocol)

#### TCP vs UDP 비교표

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 방식 | 연결 지향 | 비연결 지향 |
| 신뢰성 | 높음 | 낮음 |
| 순서 보장 | 보장 | 보장하지 않음 |
| 속도 | 상대적으로 느림 | 빠름 |
| 활용 | 웹, 파일 전송, 이메일 | 스트리밍, 게임, DNS |

```text
TCP: 연결 설정 → 데이터 전송 → 확인 응답 → 재전송 가능
UDP: 연결 없이 전송 → 빠르지만 손실 가능
```

**개념:** UDP 는 신뢰성이 낮고, 연결 지향적이지 않은 프로토콜로, 데이터그램을 사용하여 통신을
수행함. UDP 는 간단하고 빠르며, 실시간 응용 프로그램에서 자주 사용됨.

특징
- 비연결 지향(Connectionless)
- 신뢰성 없음
- 빠른 전송 속도
- 단순한 헤더 구조

장점
- 전송 속도: 오버헤드가 적어 전송 속도가 빠름.
- 낮은 오버헤드: 간단한 헤더 구조로 인해 오버헤드가 적음.
- 실시간 응용에 적합: 스트리밍, 온라인 게임 등 실시간 응용에 적합함.

단점
- 신뢰성 부족: 패킷 손실, 중복, 순서 오류를 감지하지 않음.
- 데이터 순서 보장 없음: 패킷이 순서대로 도착하는 것을 보장하지 않음.
- 오류 수정 없음: 오류 발생 시 재전송 등의 기능이 없음.

> **출제 경향**   TCP 와 UDP 차이점에 대해 묻는 문제가 종종 출제됩니다. 특히 공기업 필기에서 많이
출제되니 둘의 차이점은 꼭 알아두세요. 난이도가 쉬운편이라 꼭 맞춰야 하는 문제!

## HTTP 오류

> 중요도: **하** (★)


![HTTP 상태 코드 범주](https://upload.wikimedia.org/wikipedia/commons/thumb/8/88/Http-headers-status.png/960px-Http-headers-status.png)
> 그림: HTTP 상태 코드 처리 흐름 기반으로 HTTP 상태 코드 범주 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Http-headers-status.png

### 1. 1xx (정보 제공 응답)

: 정보 제공 응답을 의미하며, 요청이 수신되어 처리 중임을 나타냄

### 2. 2xx (성공)

: 요청이 성공적으로 수신되고 이해되었으며 처리되었음을 나타냄

### 3. 3xx (리다이렉션)
: 요청한 리소스가 다른 위치로 이동되었음을 나타내며, 클라이언트는 추가 작업을 수행

### 4. 4xx (클라이언트 오류)

: 클라이언트의 잘못된 요청으로 인해 서버가 요청을 처리할 수 없음을 나타냄

### 5. 5xx (서버 오류)

: 서버가 요청을 처리하는 과정에서 오류가 발생했음을 나타냄

> **출제 경향**   거의 출제되지 않지만 그래도 출제된 이력이 있기 때문에 다시 출제될 확률이
있습니다. 가볍게 알아보면 좋습니다.

## 중간자 공격

> 중요도: **하** (★)


![중간자 공격 흐름](https://upload.wikimedia.org/wikipedia/commons/thumb/e/e7/Man_in_the_middle_attack.svg/960px-Man_in_the_middle_attack.svg.png)
> 그림: 중간자 공격 구조 기반으로 중간자 공격 흐름 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Man_in_the_middle_attack.svg

### 1. 개념

: 중간자 공격(Man-in-the-Middle Attack, MITM)은 통신 중인 두 당사자 사이에 공격자가 몰래
개입하여 정보를 도청하거나 조작하는 사이버 공격 기법

### 2. 과정

가로채기 → 세션하이재킹(사용자가 인증된 후에 세션쿠키를 가로채서 사용자의 권한을 도용하는
 방식)→ 데이터 변조 → 데이터도청

```text
정상 통신
[사용자] ───────────────> [서버]

중간자 공격
[사용자] ──> [공격자] ──> [서버]
           도청/변조
```

> **암기 포인트**   MITM은 공격자가 양쪽 사이에 끼어들어 `도청` 또는 `변조`를 수행하는 구조입니다.

### 3. 유형
- Wi-Fi 핫스팟: 공격자는 공용 Wi-Fi 네트워크를 설정하여 사용자가 이를 통해 인터넷에
  접속하도록 유도함.
- IP 스푸핑: 공격자는 IP 주소를 위조하여 통신을 가로챔.
- ARP 스푸핑: 공격자는 ARP(주소 결정 프로토콜) 캐시를 조작하여 자신을 신뢰할 수 있는
  네트워크 장치로 가장함.
- DNS 스푸핑: 공격자는 DNS 서버를 조작하여 사용자가 악의적인 웹사이트에 접속하도록
  유도함.

### 예시 문제

다음 중 중간자 공격의 유형으로 올바르지 않은 것은 무엇인가요?
1. Wi-Fi 핫스팟을 설정하여 사용자를 유도함.
2. IP 주소를 위조하여 통신을 가로챔.
3. 공용 네트워크에서 VPN 을 사용함.
4. ARP 캐시를 조작하여 자신을 신뢰할 수 있는 네트워크 장치로 가장함.

**정답:** 3번

> **출제 경향**   중간자 공격이라는 말은 생소하지만 그 유형에 대해서는 익히 알고 있는 개념들입니다.
중간자 공격의 개념과 유형을 숙지하면 충분히 풀수있는 문제입니다!

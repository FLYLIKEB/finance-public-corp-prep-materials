# 06-01. 프로세스와 스레드

> 학습 목적: 프로세스와 스레드의 실행 단위 차이를 설명한다.
> 관련 기출: [05-9-운영체제-기출-모음](05-09-운영체제-기출-모음.md)
> 연결 핵심정리: [04-3-소프트웨어공학-운영체제-컴퓨터구조](04-03-소프트웨어공학-운영체제-컴퓨터구조.md)

## 핵심 개념

- 프로세스는 실행 중인 프로그램과 자원 묶음이다.
- 스레드는 프로세스 안에서 실행되는 흐름 단위다.
- PCB는 프로세스 상태와 문맥 정보를 저장한다.


### 서술형 확장 개념

- **시스템 콜**은 사용자 프로그램이 파일, 프로세스, 네트워크처럼 보호된 커널 자원을 요청하는 인터페이스다. 시스템 콜이 발생하면 CPU는 사용자 모드에서 커널 모드로 전환하고, 커널은 요청을 처리한 뒤 다시 사용자 모드로 복귀한다.
- **인터럽트, 트랩, 예외**는 모두 제어 흐름을 커널로 넘기지만 원인이 다르다. 인터럽트는 I/O 완료처럼 외부 장치가 일으키고, 트랩은 시스템 콜처럼 의도적으로 발생하며, 예외는 0으로 나누기나 페이지 폴트처럼 명령 실행 중 오류·특수 상황에서 발생한다.
- **IPC(Inter-Process Communication)**는 독립 주소 공간을 가진 프로세스들이 데이터를 주고받는 방법이다. 파이프와 메시지 큐는 커널 버퍼를 거치므로 구현이 단순하고, 공유 메모리는 복사 비용이 적지만 세마포어·뮤텍스 같은 동기화가 필요하며, 소켓은 네트워크를 넘는 프로세스 통신까지 확장된다.

| IPC 방식 | 핵심 특징 | 서술형 포인트 |
| --- | --- | --- |
| Pipe | 단방향 스트림 | 부모-자식 프로세스 간 간단한 통신에 적합 |
| Message Queue | 메시지 단위 전달 | 커널이 메시지를 보관하므로 비동기 통신 가능 |
| Shared Memory | 같은 메모리 영역 공유 | 가장 빠르지만 동기화 없이는 race condition 발생 |
| Socket | 주소와 포트 기반 통신 | 동일 호스트와 원격 호스트 모두 지원 |

## 쉽게 이해하기

- 프로세스는 “실행 중인 프로그램 한 벌”이라고 보면 된다. 크롬 창 하나가 여러 자원과 함께 움직이는 단위다.
- 스레드는 그 프로그램 안에서 실제로 일하는 작업자다. 한 크롬 창 안에서 화면 표시, 다운로드, 입력 처리가 동시에 되는 이유가 스레드 때문이다.
- 면접이나 필기에서는 “프로세스는 자원 단위, 스레드는 실행 흐름 단위”라고 잡으면 대부분의 비교 문제가 풀린다.

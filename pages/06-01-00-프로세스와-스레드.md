# 06-01. 프로세스와 스레드

> 학습 목적: 프로세스와 스레드의 실행 단위 차이를 설명한다.
> 관련 기출: [05-9-운영체제-기출-모음](05-09-운영체제-기출-모음.md)
> 연결 핵심정리: [04-3-소프트웨어공학-운영체제-컴퓨터구조](04-03-소프트웨어공학-운영체제-컴퓨터구조.md)

## 핵심 개념

- 프로세스: 실행 중인 프로그램과 그 프로그램이 사용하는 자원의 묶음(실행 단위).
- 스레드: 프로세스 내부에서 실제로 명령을 실행하는 흐름 단위(경량 실행 단위).
- PCB(Process Control Block): 프로세스의 상태와 문맥 정보를 저장하는 자료 구조.


### 서술형 확장 개념

- 시스템 콜
  - 사용자 영역의 프로그램이 파일, 프로세스 관리, 네트워크 등 보호된 커널 자원에 접근할 때 사용하는 인터페이스다.
  - 시스템 콜이 호출되면 CPU는 사용자 모드에서 커널 모드로 전환하고 요청을 처리한 뒤 사용자 모드로 복귀한다.

- 인터럽트, 트랩, 예외
  - 세 가지는 모두 제어 흐름을 커널로 넘긴다는 공통점이 있으나 발생 원인이 다르다.
  - 인터럽트: I/O 완료 등 외부 장치가 비동기적으로 발생시킴.
  - 트랩(Trap): 시스템 콜처럼 프로그램이 의도적으로 호출.
  - 예외(Exception): 0으로 나누기, 페이지 폴트 등 명령 실행 중 발생하는 오류나 특수 상황.

- IPC(Inter-Process Communication)
  - 서로 다른 주소 공간을 가진 프로세스들이 데이터를 주고받는 방법의 총칭이다.
  - 구현 방식에 따라 성능·동기화·범위(로컬/네트워크) 특성이 달라진다.

| IPC 방식 | 핵심 특징 | 서술형 포인트 |
| --- | --- | --- |
| Pipe | 단방향 스트림 | 부모-자식 같은 간단한 프로세스 간 통신에 적합 |
| Message Queue | 메시지 단위 전달 | 커널이 메시지를 보관하므로 비동기 통신 가능 |
| Shared Memory | 같은 메모리 영역 공유 | 복사 오버헤드가 적어 빠르지만 동기화 필요 |
| Socket | 주소와 포트 기반 통신 | 동일 호스트와 원격 호스트 통신 모두 지원 |

## 쉽게 이해하기

- 프로세스는 “실행 중인 프로그램 한 벌”이다. 예를 들어 브라우저 창 하나가 그 프로그램이 사용하는 메모리·파일 디스크립터·스레드 등을 포함하는 단위다.
- 스레드는 그 프로그램 안에서 실제로 일을 하는 작업자다. 하나의 프로세스 안에서 여러 스레드가 병렬로 동작하면 화면 표시·네트워크 처리·입력 처리 등이 동시에 일어난다.
- 실무·면접에서는 간단히 "프로세스는 자원 단위, 스레드는 실행 흐름 단위"로 기억하면 대부분의 비교 문제가 해결된다.

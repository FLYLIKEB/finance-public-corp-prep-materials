# 7월: 1회독 완료 이후 문제풀이 전환 + 공고 대응

> **7월 19일 기준**: 플래시카드로 전 범위 개념은 한 번 훑었고, 아직 직접 문항 풀이량은 적다. 남은 7월의 핵심은 `개념 복습 반복`이 아니라 **문제풀이량 확보와 서술형 답안 전환**이다.

## 현재 상태 진단

- [x] NotebookLM 과목별 생성 문제 반복 기반은 이미 만들었다.
- [ ] 한국은행 기출은 회차별 직접 풀이 대신 스타일 참고 소스로만 유지한다.
- 전공 개념의 큰 지도는 이미 한 번 본 상태다.
- 약점은 `아는 개념을 시험 답안으로 꺼내는 속도`와 `문항을 실제로 푼 양`이다.
- 따라서 7월 후반에는 하루 학습의 중심을 **NotebookLM 생성 문제 / 비한은 기출 / 국가직 기출 서술형 변환**에 둔다.

## 목표

- [ ] OS/DB/네트워크/보안 중심으로 **직접 푼 문제 수를 빠르게 늘리기**
- [ ] 한국은행 기출은 회차별 직접 풀이 대신 스타일 참고 소스로만 유지
- [ ] 비한은 금융공기업 기출과 국가직 전산직 7급 기출을 서술형으로 변환해 풀이
- [ ] 작년 한은 자소서를 **공고 문항만 반영하면 제출 가능한 상태**로 유지
- [ ] 자소서 문장별 예상 꼬리질문 작성
- [ ] 주요 기관 공통 자소서 소재 추출
- [ ] NCS/SQL/코딩은 감 유지 수준으로만 운영

## 7월 후반 세부 체크리스트

### 전공 문제풀이

- [ ] OS/DB/네트워크/보안에서 과목당 15~20문항 이상 직접 풀이
- [ ] `맞음 / 애매함 / 틀림 / 모름` 기준으로 채점
- [ ] 틀리거나 애매한 개념은 다음 날 재출제 목록으로 이월
- [ ] 자료구조·알고리즘은 프로그래머스/기출을 통해 **설명 가능한 풀이**로 정리

### 서술형 답안화

- [ ] 하루 최소 3문항 이상 5~7문장 서술형 답안 작성
- [ ] 객관식 기출도 “왜 정답인지 / 왜 오답인지”를 글로 변환
- [ ] 답안은 `정의 → 원리 → 비교/예외 → 금융IT 연결` 구조를 기본으로 사용

### 공고 대응

- [ ] 한국은행 세부 공고 오픈 여부 매일 확인
- [ ] 공고가 뜨면 문항 차이와 마감일만 우선 체크
- [ ] 자소서는 새로 쓰지 말고 작년 합격본 기반으로 반영 범위만 표시

## 자소서 수정 범위

| 구분 | 처리 |
|---|---|
| 구조 | 작년 합격본 유지 |
| 문항 | 올해 문항만 반영 |
| 경험 | 신규 경험/성과만 추가 |
| 표현 | 중앙은행 IT, 지급결제, 안정성, 보안 강화 |
| 방어 | 모든 문장을 면접에서 실제 경험으로 설명 가능하게 정리 |
| 연결 | 프로젝트/실무 경험을 지급결제·금융안정·통계/정책 분석 중 하나와 연결 |
| 검증 | 과장된 수치·검증 불가 사례 제거 |
| 시간 | 총 준비시간 5% 이내, 단 면접 방어 메모는 별도 누적 |

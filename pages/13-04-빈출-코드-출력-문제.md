# 13-04. 빈출 코드 출력 문제

> 학습 목적: 코드 실행 흐름을 손으로 추적하는 습관을 만든다.
> 관련 기출: [05-13-알고리즘-기출-모음](05-13-알고리즘-기출-모음.md)
> 연결 핵심정리: [04-2-프로그래밍-SQL-분산-클라우드](04-02-프로그래밍-SQL-분산-클라우드.md)

## 핵심 개념

- 반복문 변수 변화를 표로 적는다. (루프 진입 전/후, 반복마다 주요 변수 값을 적는다)
- 조건문 분기마다 출력 여부를 표시한다. (어떤 분기에서 출력이 발생하는지 표시)
- 재귀는 호출 스택과 반환값을 함께 추적한다. (호출 순서, 베이스 케이스, 반환 시점 표기)
- 스코프(전역/지역)와 변수 그림자(shadowing)를 구분한다. 로컬 변수는 전역 변수를 가릴 수 있다.
- 인자 전달 방식(pass-by-value vs pass-by-reference)을 확인한다. 값 복사가 일어나면 원본은 변하지 않는다.
- 출력 시점(표준 출력 버퍼링, print 위치 — 호출 전/후)을 명확히 한다.

추적을 체계화하면 오답 원인을 빨리 찾을 수 있다. 예를 들어 표 형태로 "라인 번호/변수 상태/출력 유무/메모"를 적어 가며 풀면 사람이 실수하는 부분을 줄일 수 있다.

### 풀이 팁 체크리스트

- [ ] 변수 선언 위치(전역 vs 지역)를 찾았는가?
- [ ] 함수 호출 시 인자가 값 복사인지 참조인지 확인했는가?
- [ ] ++, -- 연산이 전위인지 후위인지 구분했는가?
- [ ] 반복문의 초기값, 조건식, 증감식을 정확히 적었는가?
- [ ] 재귀의 베이스 케이스를 정확히 찾았는가?
- [ ] 출력문이 호출 전인지 후인지(혹은 반환 이후인지) 표시했는가?
- [ ] 표 또는 호출 스택을 그려 순서를 시각화했는가?


### 코드 추적 예제

```c
int x = 1;
void f(int a) { a++; x += a; }
int main() { int x = 3; f(x); printf("%d", x); }
```

`f(x)`의 인자 `a`는 값 복사이고, 함수 안의 `x`는 전역 변수다. 따라서 지역 변수 `x=3`은 바뀌지 않아 출력은 3이다. 전역/지역 scope와 pass-by-value를 분리해 추적해야 한다.

설명 보강:
- 전역 변수: 파일 최상단의 `int x = 1;`이 전역 변수다. 함수 `f`에서 `x += a;`는 이 전역 변수를 변경한다.
- 지역 변수: `main` 안의 `int x = 3;`은 main의 로컬 변수로 전역 변수와 이름이 같지만 다른 식별자다. 이를 변수 가림(shadowing)이라고 한다.
- 인자 전달: `f(x)`에서 전달되는 값은 main의 로컬 `x` 값(3)의 복사본이므로 `f` 내부에서 `a++`을 해도 main의 `x`는 변하지 않는다.


```python
def g(n):
    if n == 0: return 1
    print(n)
    return n * g(n-1)
print(g(3))
```

출력은 호출이 내려갈 때 `3, 2, 1`이 먼저 나오고, 반환이 올라오며 `6`이 마지막에 출력된다. 재귀 출력 문제는 “호출 전 출력인지, 반환 후 출력인지”가 핵심이다.

설명 보강:
- 호출 순서: g(3) 호출 → print(3) 출력 → g(2) 호출 → print(2) 출력 → g(1) 호출 → print(1) 출력 → g(0) 호출 → 1 반환
- 반환 순서: g(1)은 1 * 1 = 1 반환, g(2)는 2 * 1 = 2 반환, g(3)는 3 * 2 = 6 반환 → 최종적으로 print(g(3))이 6을 출력
- 시험에서 자주 나오는 실수: 재귀의 "출력 위치"(호출 전/후)와 "곱셈/증가 순서"를 혼동함. 출력 위치를 먼저 적어 두면 실수를 줄일 수 있다.

## 쉽게 이해하기

- 코드 출력 문제는 컴퓨터가 한 줄씩 실행하는 과정을 사람이 따라가는 문제다.
- 변수 값이 바뀔 때마다 표에 기록하면 반복문과 조건문 실수를 줄일 수 있다.
- 재귀나 중첩 반복문은 머리로만 풀지 말고 호출 순서와 출력 시점을 따로 표시한다.
- 간단한 디버깅 방법: 의사 코드(즉, 주요 변수만 적은 요약)를 먼저 쓰고, 각 단계마다 변수 상태를 갱신해 본다.

## 시험 포인트 (중요 빈출 유형)

- 스코프 관련: 동일 이름의 전역/지역 변수가 있을 때 어느 변수가 사용되는지 구분하라.
- 인자 전달: 값 복사(pass-by-value) vs 참조(pass-by-reference 혹은 포인터)를 확인하라.
- 증감 연산자: i++와 ++i는 사용 위치에 따라 값이 달라진다.
- 반복문 경계: 초기값, 조건식, 증감식의 관계로 인해 off-by-one 오류가 발생하기 쉽다.
- 출력 시점: 출력문이 호출 전인지 후인지(예: 재귀에서 print가 재귀 호출 앞/뒤에 있으면 결과가 완전히 달라진다).
- 함수 호출의 부작용(side effect): 함수 내부에서 전역 변수를 수정하는 경우 출력에 영향을 준다.

각 항목을 만났을 때는 문제에서 요구하는 출력 시점(실행 흐름의 어느 시점인지)을 먼저 마킹하고, 그에 따라 변수 표를 채워나가라.

## 실무 연결

- 디버깅 습관: 작은 입력으로 함수의 중간 상태를 출력하거나, 디버거로 스택 프레임을 하나씩 확인하면 문제 해결 속도가 빨라진다.
- 로깅 설계: 복잡한 재귀/반복 구조에서는 중간 상태를 로그로 남기는 패턴이 실무에서 유용하다(단, 성능 고려).
- 단위 테스트: 경계값(0, 1, 큰 값), 음수 입력(가능한 경우) 등으로 단위 테스트를 만들어 출력과 동작을 검증한다.
- 코드 리뷰 체크포인트: 인자 전달 방식, 전역 변수 사용, 부작용 여부를 리뷰 체크리스트에 넣어 실수 방지.

# 06-02. CPU 스케줄링

> 학습 목적: CPU 스케줄링이 **언제**, **무엇을 기준으로**, **어떤 비용을 감수하며** 실행 프로세스를 바꾸는지 이해한다.

> 연결 핵심정리: [04-3-소프트웨어공학-운영체제-컴퓨터구조](04-03-소프트웨어공학-운영체제-컴퓨터구조.md)

## 핵심 개념

CPU 스케줄링은 Ready Queue에 있는 프로세스 중 하나를 골라 CPU를 배정하는 운영체제의 정책이다. 프로세스는 생성 직후 바로 CPU를 쓰는 것이 아니라 `Ready → Running → Waiting/Ready/Terminated` 상태를 반복한다. 이때 스케줄러는 “누구에게 CPU를 줄 것인가”를 결정하고, Dispatcher는 실제 문맥교환을 수행한다.

![CPU 스케줄링 동작 흐름](https://raw.githubusercontent.com/FLYLIKEB/finance-public-corp-prep-materials/main/assets/downloaded-visual-aids/cpu-scheduling-dynamic-overview.svg)
> 그림: Ready Queue, Scheduler, CPU, I/O Wait, Exit 사이의 이동을 시간 흐름으로 보여준다. 핵심은 Ready Queue 안에서 선택 기준이 계속 적용된다는 점이다.

## 스케줄링이 일어나는 시점

| 시점 | 설명 | 선점 가능성 |
|---|---|---|
| Running → Waiting | 실행 중인 프로세스가 I/O를 요청해 CPU를 내려놓음 | 비선점 상황에서도 발생 |
| Running → Terminated | 프로세스가 끝남 | 비선점 상황에서도 발생 |
| Running → Ready | 타임 슬라이스 만료, 더 높은 우선순위 도착 등으로 CPU를 빼앗김 | 선점형에서 발생 |
| Waiting → Ready | I/O 완료 후 다시 Ready Queue로 들어옴 | 선점형이면 즉시 재평가 가능 |

시험에서는 “실행 중인 프로세스가 끝나지 않았는데 CPU가 바뀌었는가?”를 먼저 본다. 그렇다면 선점형 알고리즘이거나 인터럽트·타임퀀텀·우선순위 변화가 개입된 것이다.

## 평가 지표

| 지표 | 공식 | 의미 | 낮을수록 좋은가 |
|---|---|---|---|
| 대기시간 | Ready Queue에서 기다린 총 시간 | CPU를 받기 전까지 밀린 시간 | 예 |
| 반환시간 | 완료시간 - 도착시간 | 도착부터 종료까지 걸린 전체 시간 | 예 |
| 응답시간 | 최초 실행시각 - 도착시간 | 처음 반응하기까지의 시간 | 예 |
| 처리율 | 단위 시간당 완료한 프로세스 수 | 시스템이 일을 얼마나 많이 끝내는가 | 높을수록 좋음 |
| CPU 이용률 | CPU가 놀지 않고 일한 비율 | 유휴시간을 줄였는가 | 높을수록 좋음 |

대기시간 계산에서 가장 흔한 실수는 `대기시간 = 반환시간 - 실행시간`을 잊는 것이다. 선점형에서도 이 공식은 그대로 성립한다. 중간에 여러 번 기다렸더라도 총합은 반환시간에서 실제 CPU 사용시간을 빼면 된다.

## 스케줄링 정책의 큰 분류

| 분류 | 대표 알고리즘 | 핵심 아이디어 | 장점 | 위험 |
|---|---|---|---|---|
| 도착 순서 기반 | FCFS | 먼저 온 순서대로 처리 | 단순, 공정해 보임 | Convoy Effect |
| 실행시간 기반 | SJF, SRTF | 짧은 작업 우선 | 평균 대기시간 감소 | 긴 작업 기아 가능 |
| 대기시간 보정 | HRN | 오래 기다린 작업의 우선순위 상승 | SJF의 기아 완화 | 응답률 계산 필요 |
| 시간 분할 | RR | 시간 할당량만큼 번갈아 실행 | 응답성 좋음 | 문맥교환 오버헤드 |
| 우선순위 기반 | Priority | 중요도 높은 작업 우선 | 정책 반영 쉬움 | 낮은 우선순위 기아 가능 |

## 쉽게 이해하기

CPU를 한 명의 상담원이라고 보면, 스케줄링은 대기 고객을 어떤 순서로 상담할지 정하는 문제다.

- FCFS는 번호표 순서다. 앞 고객 상담이 길면 뒤 고객이 모두 밀린다.
- SJF는 짧은 상담부터 처리한다. 평균 대기시간은 줄지만 긴 상담은 계속 밀릴 수 있다.
- HRN은 “짧은 상담”뿐 아니라 “얼마나 오래 기다렸는가”도 반영한다.
- RR은 모든 고객에게 2분씩 마이크를 돌리는 방식이다. 반응은 빠르지만 자주 전환하면 오히려 손해다.

## 계산 문제 접근 순서

1. 프로세스별 `도착시간`, `실행시간`, `우선순위`, `time quantum`을 표로 정리한다.
2. 현재 시간마다 Ready Queue에 들어온 프로세스를 확인한다.
3. 알고리즘 기준을 적용해 실행할 프로세스를 고른다.
4. 선점형이면 새 프로세스 도착 또는 time quantum 만료 때마다 재평가한다.
5. 간트 차트에 시작·종료 시각을 표시한다.
6. 완료시간을 기준으로 반환시간과 대기시간을 계산한다.

## 약어 풀이

- CPU: Central Processing Unit, 중앙처리장치
- FCFS: First-Come, First-Served, 선입선처리
- HRN: Highest Response-ratio Next, 최고 응답률 우선
- I/O: Input/Output, 입출력
- RR: Round Robin, 라운드 로빈
- SJF: Shortest Job First, 최단 작업 우선
- SRTF: Shortest Remaining Time First, 최소 잔여시간 우선

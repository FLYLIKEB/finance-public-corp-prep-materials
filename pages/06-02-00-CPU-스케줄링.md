## 핵심 개념

CPU 스케줄링은 Ready Queue에 있는 프로세스 중 하나를 골라 CPU를 배정하는 운영체제의 정책이다. 프로세스는 생성 직후부터 항상 CPU를 바로 사용하지 않고 일반적으로 다음 상태를 반복한다: `Ready → Running → Waiting/Ready/Terminated`.

- 스케줄러(Scheduler): 누가 CPU를 얻을지 결정한다.
- 디스패처(Dispatcher): 결정에 따라 실제 문맥 전환(context switch)을 수행한다.

### 서술형 확장 개념

- 스케줄링 성능은 **CPU 이용률, 처리량, 반환시간( turnaround time ), 대기시간( waiting time ), 응답시간( response time )**으로 평가한다. 배치 작업(batch)은 반환시간과 처리량을, 대화형(interactive) 시스템은 응답시간을 더 중요하게 본다.
- **SRTF (Shortest Remaining Time First)**: 선점형 SJF로, 남은 실행 시간이 가장 짧은 프로세스를 우선 실행한다. 평균 대기시간을 줄이나 긴 작업이 계속 밀리는 starvation 문제가 발생할 수 있다.
- **Priority Scheduling**: 우선순위가 높은 작업을 먼저 실행한다. 낮은 우선순위의 기아(starvation)는 오래 기다린 프로세스의 우선순위를 올리는 "aging"으로 완화할 수 있다.
- **Multilevel Queue**: 시스템/대화형/배치 등 용도별로 큐를 나누고 큐별로 다른 정책을 적용한다.
- **Multilevel Feedback Queue**: 프로세스 행동(예: CPU 소비량)에 따라 큐를 이동시켜 짧은 대화형 작업과 긴 CPU-bound 작업을 균형 있게 처리한다.

| 지표 | 의미 | 작을수록/클수록 |
| --- | --- | --- |
| CPU 이용률 | CPU가 실제 작업한 비율 | 클수록 좋음 |
| 처리량 | 단위 시간당 완료 작업 수 | 클수록 좋음 |
| 반환시간 | 제출부터 완료까지 걸린 시간 | 작을수록 좋음 |
| 대기시간 | Ready Queue에서 기다린 시간 | 작을수록 좋음 |
| 응답시간 | 요청 후 첫 응답까지 시간 | 작을수록 좋음 |

## 스케줄링이 일어나는 시점

| 시점 | 설명 | 선점 가능성 |
|---|---|---|
| Running → Waiting | 실행 중인 프로세스가 I/O를 요청해 CPU를 내려놓음 | 비선점/선점 모두 발생 가능 |
| Running → Terminated | 프로세스가 종료됨 | 비선점/선점 모두 발생 가능 |
| Running → Ready | 타임 슬라이스 만료, 더 높은 우선순위 도착 등으로 CPU를 빼앗김 | 선점형에서 발생 |
| Waiting → Ready | I/O 완료 후 Ready Queue로 돌아옴 | 선점형이면 즉시 재평가 가능 |

시험에서 먼저 확인할 포인트: "실행 중인 프로세스가 끝나지 않았는데 CPU가 바뀌었는가?" 만약 그렇다면 선점형 알고리즘을 적용했거나 인터럽트·타임퀀텀·우선순위 변화 등이 개입한 것이다.

## 평가 지표

| 지표 | 공식 | 의미 | 낮을수록 좋은가 |
|---|---|---|---|
| 대기시간 | Ready Queue에서 기다린 총 시간 | CPU를 받기 전까지 밀린 시간 | 예 |
| 반환시간 | 완료시간 - 도착시간 | 도착부터 종료까지 걸린 전체 시간 | 예 |
| 응답시간 | 최초 실행시각 - 도착시간 | 처음 반응하기까지의 시간 | 예 |
| 처리율 | 단위 시간당 완료한 프로세스 수 | 시스템이 일을 얼마나 많이 끝내는가 | 높을수록 좋음 |
| CPU 이용률 | CPU가 놀지 않고 일한 비율 | 유휴시간을 줄였는가 | 높을수록 좋음 |

팁: 대기시간을 계산할 때 흔한 실수는 "대기시간 = 반환시간 - 실행시간" 공식을 잊는 것이다. 선점형에서도 이 관계는 성립한다. 여러 번 기다렸더라도 총 대기시간은 반환시간에서 실제 CPU 사용시간(총 실행시간)을 빼면 된다.

## 스케줄링 정책의 큰 분류

| 분류 | 대표 알고리즘 | 핵심 아이디어 | 장점 | 위험 |
|---|---|---|---|---|
| 도착 순서 기반 | FCFS | 먼저 온 순서대로 처리 | 단순, 공정해 보임 | Convoy Effect(짧은 작업이 뒤로 밀림) |
| 실행시간 기반 | SJF, SRTF | 짧은 작업 우선 | 평균 대기시간 감소 | 긴 작업 기아 가능 |
| 대기시간 보정 | HRN | 오래 기다린 작업의 우선순위 상승 | SJF의 기아 완화 | 응답률 계산 필요 |
| 시간 분할 | RR | 고정 time quantum만큼 번갈아 실행 | 응답성 좋음 | 문맥교환 오버헤드 증가 |
| 우선순위 기반 | Priority | 중요도 높은 작업 우선 | 정책 반영 쉬움 | 낮은 우선순위 기아 가능 |

## 쉽게 이해하기

CPU를 한 명의 상담원으로 비유하면 스케줄링은 대기 고객을 어떤 순서로 상담할지 정하는 문제다.

- FCFS: 번호표를 뽑고 순서대로 처리한다. 한 상담이 길면 뒤 고객이 모두 기다린다.
- SJF: 상담이 짧은 고객부터 처리한다. 평균 대기시간은 감소하지만 긴 상담은 계속 밀릴 수 있다.
- HRN: 기다린 시간도 고려해 우선순위를 보정한다(짧음·오래 기다림 모두 반영).
- RR: 모든 고객에게 일정 시간(예: 2분)씩 번갈아 제공한다. 반응성은 좋아지지만 자주 전환하면 오버헤드가 커진다.

## 계산 문제 접근 순서

1. 프로세스별 `도착시간`, `실행시간`, `우선순위`, `time quantum`을 표로 정리한다.
2. 현재 시간 기준으로 Ready Queue에 들어온 프로세스를 확인한다.
3. 선택 규칙(알고리즘 기준)을 적용해 실행할 프로세스를 결정한다.
4. 선점형이면 새 프로세스 도착 또는 time quantum 만료 시마다 재평가한다.
5. 간트 차트(Gantt chart)에 각 프로세스의 시작·종료 시각을 표시한다.
6. 완료시간을 기준으로 반환시간과 대기시간을 계산한다.

## 약어 풀이

- CPU: Central Processing Unit, 중앙처리장치
- FCFS: First-Come, First-Served, 선입선처리
- HRN: Highest Response-ratio Next, 최고 응답률 우선
- I/O: Input/Output, 입출력
- RR: Round Robin, 라운드 로빈
- SJF: Shortest Job First, 최단 작업 우선
- SRTF: Shortest Remaining Time First, 최소 잔여시간 우선

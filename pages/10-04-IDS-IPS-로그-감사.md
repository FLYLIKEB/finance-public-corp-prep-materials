# 10-04. IDS-IPS-로그-감사

> 학습 목적: 탐지, 차단, 감사의 역할을 구분한다.
> 관련 기출: [05-12-보안-기출-모음](05-12-보안-기출-모음.md)
> 연결 핵심정리: [04-4-네트워크-프로토콜-보안](04-04-네트워크-프로토콜-보안.md)

## 핵심 개념

- IDS는 침입을 탐지한다(알림/로그 생성, 수동 대응).
- IPS는 탐지 후 네트워크/호스트 수준에서 실시간 차단까지 수행한다(능동 대응).
- 로그 감사는 사건 발생 전·중·후의 기록을 보존하고, 사후 분석·책임 추적·내부통제 증빙을 제공한다.

### 비교 요약

| 항목 | IDS | IPS | 로그 감사 |
|---|---:|---:|---|
| 역할 | 탐지 및 알림 | 탐지 + 차단(실시간) | 기록, 사후분석, 증빙 |
| 배치 | 패시브(미러/SPAN) | 인라인(트래픽 경로) | 로그 수집기/SIEM |
| 위험 | 미탐 가능, 오탐 경고 | 네트워크 가용성 영향 가능 | 개인정보·무결성 관리 필요 |


## 서술형 확장 개념

- 탐지 기법
  - Signature(서명) 기반: 알려진 공격 패턴(시그니처)을 비교해 탐지. 장점: 명확한 식별, 낮은 오탐(정상 구성 시). 단점: 새로운 변종/제로데이에는 무력.
  - Anomaly(이상) 기반: 정상 행위를 학습해 이탈을 이상으로 판정. 장점: 알려지지 않은 공격 탐지 가능. 단점: 초기 베이스라인 확보와 오탐 관리가 중요.

- SIEM(로그 수집·상관분석)
  - 다양한 소스(방화벽, IDS/IPS, 서버, DB, 애플리케이션, 인증시스템)의 로그를 중앙으로 수집하고 상관분석해 보안 이벤트를 식별.
  - 실무에서는 계정활동, 권한변경, 대량 트래픽, 비정상적 DB 접근 등의 이벤트를 연계해 이상징후를 찾는다.

- 로그의 보존·무결성·동기화
  - 시간 동기화(NTP)는 여러 로그를 상관분석할 때 필수다.
  - 로그는 전송·저장 과정에서 위변조를 방지(예: 쓰기전용 저장소, 해시/서명)해야 하며, 접근권한을 엄격히 통제한다.
  - 보존기간·삭제 정책은 내부정책 및 규제(산업별 요구사항)에 따라 문서화한다.

- 보안관리 연결고리
  - 취약점 진단·패치 우선순위, 예외 승인 및 잔여 위험 수용 여부를 문서화한다.
  - 최소권한 원칙과 정기 권한검토는 사고 영향을 줄이는 기본 통제이다.


## 시험 포인트(핵심 암기사항)

- IDS와 IPS의 차이: IDS는 탐지(알림), IPS는 탐지 + 차단(실시간). 배치 방식(패시브 vs 인라인)을 함께 기억.
- 탐지 기법 구분: 시그니처 기반 vs 이상(행위) 기반—장단점을 서술할 수 있어야 함.
- 로그 감사의 필수 요소: 타임스탬프 동기화, 무결성(위변조 방지), 보존기간, 접근통제, 개인정보 마스킹.
- SIEM의 역할: 로그 수집, 정규화, 상관분석, 경보(알람) 및 조치 워크플로우 연계.


## 실무 적용 체크리스트

- IDS/IPS 도입 전
  - [ ] 보호 대상과 보호 범위를 정의(네트워크 구간, 중요 자산).
  - [ ] 트래픽 경로를 분석해 IPS를 인라인으로 둘 위치 선정.
  - [ ] 미러 포트(SPAN) 또는 탭을 통해 IDS 위치 선정.
  - [ ] 로그 저장소와 SIEM 연계 계획 수립(용량·보존정책 포함).

- 운영 중(정기)
  - [ ] 시그니처/룰 업데이트 주기 점검 및 테스트.
  - [ ] 오탐/미탐 발생 시 룰 튜닝 및 화이트리스트 적용 여부 검토.
  - [ ] NTP 동기화 상태 확인.
  - [ ] 로그 접근권한 및 감사로그 자체의 무결성 검토.

- 사고 대응 연결
  - [ ] 탐지->분석->격리->복구->사후보고 절차 매핑.
  - [ ] SIEM 알림 기준과 담당자(교대·연락망) 명확화.
  - [ ] 포렌식 보존을 위한 로그·이미지 보존 절차 확보.


## 로그 감사 상세 가이드

- 수집 및 중앙화
  - 가능한 모든 보안 장비와 시스템의 로그를 중앙 수집기로 전송(원본 로그 유지 원칙 권장).
  - 로그 포맷을 정규화(타입별 필드 정의)해 상관분석에 용이하도록 구성.

- 무결성 및 보존
  - 로그에 대한 변경 불가(append-only) 정책을 적용하거나 해시/디지털 서명을 사용해 위변조를 방지.
  - 보존기간은 규제와 내부정책을 반영해 문서화. 자동 삭제 정책과 보관 절차를 마련.

- 개인정보 처리
  - 로그에 포함된 개인정보는 저장 전 마스킹·익명화 고려.
  - 조사가 필요한 경우 절차에 따라 복원 또는 접근 허가를 시행.

- 분석 및 상관
  - 상관분석 룰은 단일 이벤트보다 연계 패턴(예: 다수 실패 로그인->성공 로그인->비정상적 데이터 추출)에 집중.
  - 통계·행위 기반 이상탐지와 룰 기반 탐지를 병행해 보완.

- 예시: 간단한 syslog 형식

```
<PRI>TIMESTAMP HOSTNAME APPNAME: MESSAGE
Feb 22 12:34:56 host1 sshd[1234]: Failed password for invalid user root from 203.0.113.45 port 42310
```


## IDS/IPS 설계·배치 고려사항

- 배치 위치
  - 경계(인터넷-내부)와 내부(서버 존, DB 존) 등 보호 필요 구간을 정의해 계층화 적용.
  - IPS는 인라인으로 동작하므로 장애 시 트래픽 차단(가용성 영향)을 고려한 이중화/패스스루 설계 필요.

- 암호화 트래픽
  - TLS 등 암호화 트래픽에 대해서는 복호화 장치(또는 종단에서의 로깅) 고려. 복호화는 개인정보·규제 측면에서 위험과 비용을 동반.

- 우회·회피 기법 대비
  - 패킷 분할, 비정형 포트 사용, 암호화, 프로토콜 모호성 등을 통한 회피 기법을 인지하고 탐지 룰을 보완.

- 성능과 스케일
  - 트래픽 볼륨에 따른 처리성능(초당 패킷 수, 세션 수) 요구 사항을 명확히 해 하드웨어/가상 자원 계획.


## 오탐·미탐 관리

- 오탐 줄이기
  - 룰·서명 튜닝, 임계값 조정, 화이트리스트 적용.
  - 상관분석으로 단일 이벤트의 의미를 재평가.

- 미탐 대응
  - 시그니처 기반 한계는 보안 운영(침해사고 대응, 취약점 패치)으로 보완.
  - 이상 기반 탐지를 통해 알려지지 않은 변종을 포착하고, 탐지 패턴을 시그니처로 전환하여 보강.

- 피드백 루프
  - 보안 운영팀과 로그·알림 소유자 간의 피드백 절차를 마련해 룰 정확도를 지속 개선.


## 사고 대응(톱레벨 절차)

1. 탐지: IDS/IPS 혹은 SIEM에서 경보 발생.
2. 분류: 이벤트의 심각도(우선순위)와 영향을 평가.
3. 격리: 필요 시 네트워크 세그멘테이션 또는 호스트 격리.
4. 조사: 관련 로그·패킷 캡처·시스템 이미지 확보 및 분석.
5. 복구: 패치, 계정 재설정, 서비스 재구성 등 실무 회복 절차 수행.
6. 사후보고: 원인분석, 영향도, 개선조치 및 정책 변경 반영.


## 쉽게 이해하기

- IDS는 CCTV처럼 수상한 행동을 발견해 알려 주는 장치다.
- IPS는 경비원처럼 수상한 행동을 발견하면 바로 막는 역할까지 한다.
- 로그 감사는 나중에 무슨 일이 있었는지 확인하는 출입기록부다.

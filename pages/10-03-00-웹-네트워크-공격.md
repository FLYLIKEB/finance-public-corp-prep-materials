# 10-03. 웹-네트워크 공격

> 학습 목적: 대표 공격 기법의 원리와 대응을 한 줄로 정리한다.
> 관련 기출: [05-12-보안-기출-모음](05-12-보안-기출-모음.md)
> 연결 핵심정리: [04-4-네트워크-프로토콜-보안](04-04-네트워크-프로토콜-보안.md)

## 핵심 개념

- 웹 공격은 입력값 검증 실패와 세션/권한 관리 취약점에서 자주 발생한다. 방어는 주로 입력값 검증, 출력 인코딩, 세션/권한 관리 강화로 접근한다.
- 네트워크 공격은 가용성(DoS/DDoS), 기밀성(패킷 스니핑, 세션 하이재킹), 무결성(패킷 변조)을 주로 침해한다. 계층(네트워크/전송/세션/응용)에 따른 방어 기법을 이해해야 한다.
- 공격명과 방어책은 "원리 → 영향 → 방어책" 순으로 정리해 암기하면 시험·실무 양쪽에서 유리하다.

### 시험 대비 포인트(요약)

- 공격 유형의 분류: XSS(Stored/Reflected/DOM), SQL Injection(In-band/Blind/OOB), CSRF, SSRF, 파일 업로드 취약점, 인증·세션 취약점.
- 각 공격의 "공격 벡터(어디에서 입력/요청이 들어오는가)"와 "영향(CIA 중 무엇을 침해하는가)"를 명확히 서술할 수 있어야 함.
- 방어책은 구체적으로 기술할 것: 예) SQLi는 prepared statement/parameterized query, 최소 권한의 DB 계정, 에러 메시지 숨김.
- 네트워크 관련은 방화벽(WAF 포함), VPN, IDS/IPS의 역할 차이를 설명할 수 있어야 함.

## 쉽게 이해하기

- 웹 공격은 사용자 입력이나 웹 동작 방식을 악용한다(예: 폼 입력, URL 파라미터, 파일 업로드, 쿠키/헤더 조작).
- 네트워크 공격은 통신 경로(패킷 흐름), 세션 토큰, 서버 자원(CPU/메모리/네트워크 대역폭)을 공격해 서비스 중단이나 정보 유출을 발생시킨다.
- 분류 팁: "무엇을 노리는가: 기밀성(Confidentiality), 무결성(Integrity), 가용성(Availability)"으로 먼저 분류하면 대응책이 보인다.

## 서술형 확장 개념 (공격별 정리)

### XSS (Cross-Site Scripting)
- 원리: 공격자가 악성 스크립트를 주입해 피해자 브라우저에서 실행되게 함.
- 유형: Stored(지속형), Reflected(반사형), DOM 기반.
- 영향: 세션 탈취, 화면 위변조, 피싱 화면 표시, 사용자 행위 조작(키 입력, 클릭 유도).
- 방어책(개발자 관점):
  - 출력 인코딩(context-aware): HTML escape, attribute escape, JavaScript escape 등 실행되는 컨텍스트에 맞춘 인코딩.
  - 입력 검증(보조 수단): 허용 화이트리스트 기반 필터링.
  - Content Security Policy(CSP): 스크립트 소스 제한 및 인라인 스크립트 금지.
  - HTTPOnly, Secure 쿠키 플래그로 자바스크립트에서 쿠키 접근 제한.
- 실무/테스트 포인트: 모든 사용자 입력이 출력되는 지점을 점검(로그, 프로필, 댓글, 검색결과 등).

### SQL Injection (SQLi)
- 원리: 외부 입력이 안전하게 처리되지 않아 쿼리 구조가 변조됨.
- 유형: In-band(에러/유니온), Blind(블라인드), OOB(Out-of-band).
- 영향: 인증 우회, 데이터 조회·유출, 데이터 변경(삭제·수정), 심지어 원격 명령 실행으로 연결될 수 있음.
- 방어책:
  - Prepared statement / Parameterized query 사용(ORM이나 DB API의 파라미터 바인딩).
  - 입력값 검증(화이트리스트), 출력 시 민감 정보 마스킹.
  - 최소 권한의 DB 계정 사용 및 데이터베이스 에러 메시지 노출 금지.
- 실무/테스트 포인트: 로그인, 검색, 파라미터로 SQL이 실행되는 엔드포인트에 대한 페이로드 테스트.

### CSRF (Cross-Site Request Forgery)
- 원리: 사용자가 인증된 상태를 이용해 공격자가 의도한 요청을 강제로 발생시킴.
- 영향: 사용자 권한으로 한 번 클릭으로 상태 변경(비밀번호 변경, 송금 등).
- 방어책:
  - CSRF 토큰을 폼/요청에 포함하고 서버에서 검증.
  - SameSite 쿠키 설정(Lax/Strict)를 통한 타 사이트 요청 시 쿠키 전송 제한.
  - 중요 작업은 재인증(비밀번호 입력) 요구.
  - Referer/Origin 검사 보조 사용(일부 환경에서 제한적).
- 실무/테스트 포인트: 상태 변경(POST/PUT/DELETE) 요청에 대해 CSRF 보호가 적용되는지 확인.

### SSRF (Server-Side Request Forgery)
- 원리: 서버가 외부 URL을 요청하는 기능(예: URL fetch, 이미지 가져오기)을 통해 공격자가 내부망 또는 메타데이터 엔드포인트를 호출하게 만듦.
- 영향: 내부 서비스 접근, 메타데이터(클라우드 자격증명) 탈취, 내부 포트 스캔.
- 방어책:
  - URL allowlist(허용 도메인) 사용 또는 denylist(내부 IP/루프백/링크 로컬 등) 차단.
  - 내부 IP(예: 127.0.0.1, 169.254.169.254 등) 및 프라이빗 네트워크 대역 접근 금지.
  - 외부 요청 시 IP 해석 후 차단(기본 도메인→다른 IP로 바뀌는 DNS 재바인딩 대응 포함).
  - 응답 크기/타입 제한, 타임아웃 설정, 요청 헤더·메소드 검증.
- 실무/테스트 포인트: 파일 임포트, URL 미리보기, 웹훅 등 외부 URL을 받아서 호출하는 모든 기능 점검.

### 파일 업로드 취약점
- 원리: 공격자가 악성 파일(웹쉘 등)을 업로드하거나, 콘텐츠형식/경로를 조작해 실행할 수 있게 만듦.
- 영향: 원격 코드 실행, 서비스 변조, 악성코드 확산.
- 방어책:
  - 업로드 파일의 확장자·MIME 타입 검사(둘 다), 가능하면 파일 시그니처(매직 바이트) 검사.
  - 저장 경로를 웹 루트 밖으로 분리하고 실행 권한 제거(chmod), 웹서버에서 직접 실행하지 않도록 설정.
  - 랜덤 파일명 사용, 디렉터리 탐색 공격(../) 방지, 파일명 검증.
  - 바이러스 스캔, 파일 크기 제한, 허용된 파일만 처리하도록 화이트리스트 적용.
  - 다운로드 시 Content-Disposition: attachment 헤더 사용.
- 실무/테스트 포인트: 업로드된 파일을 직접 브라우저로 접근해 실행 가능한지, MIME 스니핑 여부, 경로 조작 가능성 확인.

### 네트워크 방어 기술(방화벽/WAF/VPN 등)
- 방화벽(Firewall): 네트워크/전송 계층에서 IP, 포트, 프로토콜 기반 접근 제어를 수행. 내부·외부 트래픽을 필터링해 불필요한 서비스 노출을 줄인다.
- WAF(Web Application Firewall): HTTP/HTTPS 트래픽을 분석해 OWASP Top10 등 웹 취약점 패턴을 차단하거나 로깅. 애플리케이션 계층(레이어7)에 특화.
- IDS/IPS: 네트워크 트래픽에서 이상 패턴을 탐지(IDS)하고 자동 차단(IPS)할 수 있다.
- VPN: 원격 접속 시 통신 암호화와 접속 주체 통제(인증, 권한)를 제공. 내부 자원 접근 시 활용.
- 실무 팁: WAF는 완전한 방어 수단 아님(우회 페이로드 존재). 일차 방어는 코드 수준의 취약점 제거와 안전한 구성이다.

## 실무 연결 (개발자/운영자를 위한 체크리스트)

- 코드/리뷰 단계
  - 입력값은 가능한 한 화이트리스트로 검증한다.
  - 데이터베이스 쿼리는 항상 파라미터 바인딩으로 처리한다.
  - 출력은 컨텍스트에 맞게 인코딩(HTML, JS, URL 등).
  - 인증·세션 토큰은 안전한 쿠키 세팅(HTTPOnly, Secure, SameSite) 사용.
  - 중요한 작업은 CSRF 보호 및 재인증 요구.

- 배포/운영 단계
  - 최소 권한 원칙 적용(서비스 계정, DB 계정 등).
  - 업로드된 파일은 웹 루트 밖에 저장하고 실행 권한 제거.
  - 서버/애플리케이션 로그를 중앙집중화(SIEM)하여 의심스러운 요청을 모니터링.
  - WAF와 방화벽 설정은 기본 적용하되, 로그를 기반으로 정책 튜닝.
  - 백업 및 복구 절차 문서화, 정기 복구 연습 수행.

- 모니터링/탐지/대응
  - 비정상 트래픽(특정 IP/URI에 대한 고빈도 요청, 비정상적 User-Agent 등)을 탐지해 자동 차단/알림 설정.
  - 에러 응답(예: DB 에러)에서 민감 정보가 노출되지 않도록 처리.
  - 침해사고 발생 시 영향 범위 파악(로그, 백업), 우회 차단(예: 토큰 폐기), 취약점 패치/구성 변경 후 재발 검증.

## 체크리스트(면접/시험/실무 점검용)

- [ ] 입력값이 모두 서버 측에서 검증되는가? (화이트리스트 우선)
- [ ] 출력은 항상 컨텍스트별로 인코딩되는가? (HTML/Attribute/JS/URL)
- [ ] DB 쿼리는 파라미터화 되어 있는가? (Prepared statement 사용)
- [ ] 모든 상태 변경 요청에 CSRF 방어가 적용되어 있는가?
- [ ] 파일 업로드 기능이 있는 경우 파일 시그니처·MIME 검사 및 저장 정책이 안전한가?
- [ ] SSRF 취약점이 가능한 외부 URL 호출 지점이 있는가? 내부 IP 접근 차단 로직이 있는가?
- [ ] 민감 토큰(세션, API key) 관리는 안전한 쿠키 설정과 토큰 회전 정책이 있는가?
- [ ] WAF/방화벽/IDS 로그를 모니터링하고 비정상 징후에 알림이 설정되어 있는가?

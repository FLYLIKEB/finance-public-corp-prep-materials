# 09-04. 동적계획법과 재귀

> 학습 목적: 중복 부분 문제와 재귀 종료 조건을 정리한다.
> 관련 기출: [05-13-알고리즘-기출-모음](05-13-알고리즘-기출-모음.md)
> 연결 핵심정리: [04-5-자료구조-알고리즘-DB-금융IT](04-05-자료구조-알고리즘-DB-금융IT.md)

## 핵심 개념

- 재귀는 자기 자신을 호출하는 방식이다.
- 종료(기저) 조건이 없으면 무한 호출이 발생한다. 기저 경우(base case)를 명확히 정의해야 한다.
- DP(동적 계획법)는 중복 계산(subproblem overlap)을 발견했을 때, 그 결과를 저장해 다시 계산하지 않음으로써 시간 복잡도를 줄인다.

### 요약
- 재귀: 문제를 동일한 형태의 작은 문제들로 분해하고 재귀 호출로 해결.
- 메모이제이션(Memoization): 재귀 기반의 top-down DP. 계산한 결과를 저장(캐시)해서 동일한 하위 문제는 한 번만 계산.
- 테이블레이션(Tabulation): bottom-up DP. 작은 상태부터 표를 채워 최종 답을 얻음.


### 서술형 확장 개념

- DP를 적용하려면 두 성질을 만족해야 한다.
  1. 최적 부분 구조(optimal substructure): 큰 문제의 최적해가 작은 문제들의 최적해로 구성된다.
  2. 중복 부분 문제(overlapping subproblems): 동일한 하위 문제가 여러 번 재귀적으로 나타난다.

- Memoization은 재귀 호출의 결과를 해시나 배열에 저장하여 동일한 호출이 반복될 때 저장한 값을 반환한다. Tabulation은 반복문으로 상태 테이블을 채워 올라가는 방식으로, 보통 호출 오버헤드와 스택 사용이 적다.

- 상태(state)를 정의할 때는 "어떤 정보가 그 하위 문제를 완전히 결정하는가"를 기준으로 잡는다. 예: 0/1 Knapsack에서는 dp[i][w]를 "처음 i개의 물건을 고려했을 때 허용 무게 w에서의 최대 가치"로 정의한다. LIS는 각 위치를 마지막 원소로 하는 최장 증가 부분 수열의 길이로 상태를 정의하고, LCS는 두 문자열의 접두사(prefix) 길이를 상태로 둔다.

- 재귀 코드 추적 시 적어야 할 항목: 호출 스택(call stack)에서 각 호출의 매개변수, 지역 변수(특히 배열/리스트 같은 참조형), 반환값. 전역 변수나 누적값을 수정하는 시점이 결과에 영향을 준다.

```text
fib(4)
= fib(3) + fib(2)
= (fib(2)+fib(1)) + (fib(1)+fib(0))
```

위처럼 같은 `fib(2)`가 반복 계산되므로 저장하면 시간복잡도가 지수에서 O(n)으로 줄어든다.

## 예시: 피보나치 — 재귀 vs 메모이제이션 vs 탭뷸레이션

- 순수 재귀(비효율): 지수 시간. 많은 중복 호출 발생.
- 메모이제이션(Top-down): 재귀 코드를 유지하면서 결과를 저장. 호출 횟수가 줄고 시간 복잡도 O(n).
- 탭뷸레이션(Bottom-up): 반복문으로 작은 값부터 차례로 계산. 스택 사용 없음, 공간을 최적화하기 쉬움.

예시(Python 스타일 의사 코드):

```python
# 메모이제이션 (Top-down)
memo = {}

def fib(n):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib(n-1) + fib(n-2)
    return memo[n]
```

```python
# 탭뷸레이션 (Bottom-up)
def fib_tab(n):
    if n <= 1:
        return n
    dp = [0] * (n+1)
    dp[0], dp[1] = 0, 1
    for i in range(2, n+1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]

# 공간 최적화: O(1) 공간

def fib_opt(n):
    if n <= 1:
        return n
    a, b = 0, 1
    for _ in range(2, n+1):
        a, b = b, a + b
    return b
```

## 시간/공간 복잡도 정리

- 순수 재귀(피보나치): O(2^n) 시간, O(n) 재귀 깊이(스택).
- 메모이제이션/탭뷸레이션: O(n) 시간, 메모이제이션의 추가 공간은 캐시 크기 O(n), 탭뷸레이션은 테이블 크기 O(n) (또는 최적화를 통해 O(1)).

## 실무 연결 (어떤 상황에서 DP를 쓰는가)
- 자원 배분(problem of allocation, 예: 배낭(knapsack)): 유한한 자원(무게, 비용 등)을 어떻게 배분해 가치를 최대화할지.
- 문자열 비교/정렬 관련(예: LCS, Edit Distance): 텍스트 유사도, diff, 버전 관리에서 활용.
- 스케줄링/계획수립: 부분 문제의 최적해를 결합하는 문제들.
- 캐싱이 필요한 재귀적 계산(예: 복잡한 비용 함수/조합적 계산)에서는 메모이제이션으로 성능 개선.

> 실무 팁: 구현 시 상태와 전이(transition)를 명확히 정의하면 재현 가능한 테스트 케이스(기저 사례 포함)를 만들기 쉽다. 또한 실제 서비스에서는 메모리 사용량과 동시성(캐시 무효화 등)을 고려해야 한다.

## 시험(면접) 포인트 — 요약 체크리스트

- 문제를 DP로 풀 수 있는지 판단: 최적 부분 구조 + 중복 부분 문제 여부 확인.
- 상태 정의: 상태 변수에는 무엇을 포함해야 하는가? (인덱스, 남은 용량, 이전 선택 등)
- 전이식(점화식) 도출: 한 단계에서 다음 단계로의 관계를 수식으로 표현.
- 기저 사례(base cases) 설정: 재귀 종료 조건과 테이블 초기값을 정확히 정의.
- 구현 방식 선택: Top-down vs Bottom-up. 이유를 설명할 수 있어야 함.
- 복잡도 산정: 시간 복잡도, 공간 복잡도(테이블 크기, 스택 깊이).
- 답 복구 방법: 최적해 자체(예: 어떤 물건을 넣었는가)를 추적할 필요가 있으면 경로 복원 방법을 설계.
- 흔한 실수: 인덱스 범위 오류, 전역 변수 누적 시점 오류, 미정의 초기값 사용.

체크리스트 형태로 빠르게 확인:

- [ ] 하위 문제의 중복 여부 확인
- [ ] 상태(배열 차원) 정의 완료
- [ ] 점화식(전이식) 도출
- [ ] 기저 사례 명시
- [ ] Top-down/Bottom-up 중 구현 방식 선택
- [ ] 시간/공간 복잡도 계산
- [ ] 경로 복원(필요 시) 설계 및 검증

## 문제 풀이 프로세스 (권장 순서)
1. 작은 예제로 손으로 풀어보며 하위 문제를 식별한다.
2. 상태를 결정하고 점화식을 세운다.
3. 기저 사례와 테이블의 차원을 정한다.
4. 손으로 계산한 작은 예제를 코드로 구현해 결과를 비교한다.
5. 시간/공간 복잡도를 분석하고, 필요 시 공간 최적화를 적용한다.
6. 경로 복원 로직을 추가하고 검증한다.

## 대표 문제별 상태 정의(요약)
- 0/1 Knapsack: dp[i][w] = 처음 i개의 물건을 고려했을 때 무게 w에서의 최대 가치.
- LIS(가장 긴 증가 부분 수열): dp[i] = i번째 원소를 마지막으로 하는 LIS의 길이.
- LCS(최장 공통 부분 수열): dp[i][j] = 첫 문자열의 길이 i와 둘째 문자열의 길이 j의 접두사에 대한 LCS 길이.

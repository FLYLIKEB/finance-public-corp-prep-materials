# 14-4. 입출력 시스템

## 입출력의 역할

CPU가 아무리 빨라도 디스크, 네트워크, 외부 장치가 느리면 전체 시스템 성능은 입출력에서 제한됩니다. 금융 시스템에서는 파일 전문 처리, 네트워크 패킷, DB 디스크 접근이 모두 I/O와 연결됩니다.
![입출력 병목, 인터럽트, DMA 흐름 GIF](https://cs.chamung.com/public/wiki-assets/14-4-io-dma-interrupt-flow.gif)
> 장치 쪽 대기열이 쌓이는 모습과 CPU 폴링, 인터럽트 알림, DMA 전송이 어떻게 다른지 움직임으로 보여준다.


I/O 병목은 단순히 "장치가 느리다"로 끝나지 않고 CPU 유휴 시간 증가, 대기열 적체, 응답시간 변동성 확대까지 이어집니다. 그래서 시스템 문제를 볼 때는 CPU 사용률과 함께 I/O wait, 디스크/네트워크 큐 길이도 같이 확인해야 합니다.

## 폴링

폴링은 CPU가 장치 상태를 반복적으로 확인하는 방식입니다. 구현은 단순하지만 장치가 준비될 때까지 CPU 시간을 낭비할 수 있습니다.

- 짧은 시간 동안 매우 자주 상태를 봐야 할 때는 단순성과 예측 가능성이 장점이 될 수 있다.
- 반대로 이벤트가 드문 장치에서는 busy waiting 때문에 비효율이 크다.
- 시험에서는 "CPU를 놀리지 않고 계속 확인시키는 방식"이라는 표현을 기억하면 비교 설명이 쉬워진다.

## 인터럽트

인터럽트는 장치가 CPU에 이벤트 발생을 알려주는 방식입니다. CPU는 하던 작업을 잠시 멈추고 인터럽트 서비스 루틴(ISR)을 실행합니다. 많은 I/O 이벤트를 효율적으로 처리할 수 있지만, 인터럽트가 과도하면 컨텍스트 전환 비용이 커집니다.

- 장점: 이벤트가 생겼을 때만 CPU를 깨우므로 자원 효율이 높다.
- 단점: ISR 진입/복귀 오버헤드, 우선순위 관리, 인터럽트 폭주 문제가 있다.
- 실무에서는 네트워크 장치의 interrupt coalescing처럼 인터럽트 빈도를 조정해 처리량과 지연시간을 절충한다.

## DMA

DMA(Direct Memory Access)는 CPU 개입을 최소화하고 장치가 메모리와 직접 데이터를 주고받도록 하는 방식입니다. 대용량 데이터 전송에서 CPU 부담을 줄입니다.

- CPU는 전송 시작 조건과 버퍼 주소를 설정하고, 실제 복사는 DMA 컨트롤러가 담당한다.
- 대량 파일 복사, 디스크 블록 전송, 고속 네트워크 패킷 처리처럼 데이터 양이 클수록 장점이 커진다.
- 다만 캐시 일관성, 버퍼 정렬, 완료 시점 동기화까지 같이 설계해야 한다.

## 비교표

| 방식 | 장점 | 단점 |
|---|---|---|
| 폴링 | 단순, 예측 가능 | CPU 낭비 |
| 인터럽트 | 이벤트 기반, 효율적 | 빈번하면 오버헤드 |
| DMA | 대용량 전송 효율 | 설정 비용, 일관성 관리 필요 |

비교 답안에서는 "작고 빈번한 이벤트"와 "크고 연속적인 전송"을 구분해 쓰면 훨씬 명확해집니다.
![입출력 병목, 인터럽트, DMA 흐름 GIF](https://cs.chamung.com/public/wiki-assets/14-4-io-dma-interrupt-flow.gif)
> 느린 장치 앞에서 큐가 늘어나는 병목과 컨트롤러-메모리 전송, CPU 알림 경로를 함께 확인한다.

## 금융결제원·산업은행 연계

결제 전문 처리나 대용량 배치에서는 I/O 병목을 줄이는 설계가 중요합니다. DMA와 인터럽트의 차이, 비동기 I/O의 효과, 디스크·네트워크 병목 분석은 면접에서도 시스템 운영 역량을 보여주는 소재가 됩니다.

- 배치 정산은 대용량 파일을 연속적으로 읽고 쓰므로 디스크 처리량과 버퍼 설계가 중요하다.
- 실시간 전문 처리는 작은 I/O가 반복되므로 큐 관리, 인터럽트 오버헤드, 네트워크 지연을 함께 봐야 한다.
- RAID, 복제, 재시도 큐는 단순 저장 기술이 아니라 가용성과 장애 복구 전략으로 연결된다.

## 핵심 개념

- Polling은 CPU가 장치 상태를 반복 확인하는 방식이고, interrupt는 장치가 준비되었을 때 CPU에 알리는 방식이다. Polling은 단순하지만 CPU 낭비가 크고, interrupt는 효율적이지만 문맥 전환과 인터럽트 처리 오버헤드가 있다.
- DMA는 장치와 메모리가 CPU 개입을 최소화해 직접 데이터를 전송하게 한다. 대용량 I/O에서 CPU가 데이터 복사에 묶이지 않으므로 처리량이 높아진다.
- Memory-mapped I/O는 장치 레지스터를 메모리 주소 공간에 매핑해 일반 load/store 명령으로 제어한다. 별도 I/O 명령 방식보다 프로그래밍 모델이 단순해질 수 있다.
- RAID 0은 striping으로 성능을 높이지만 장애에 약하고, RAID 1은 mirroring으로 가용성을 높인다. RAID 5는 parity를 분산해 저장 효율과 장애 허용을 절충하고, RAID 6은 이중 parity로 두 디스크 장애까지 견딘다.
- SSD는 HDD보다 random access 지연이 작지만 erase-before-write와 wear leveling 같은 특성을 고려해야 한다.

- [ ] DMA가 왜 대용량 전송에서 유리한지 설명할 수 있다.
- [ ] memory-mapped I/O와 RAID 개념을 I/O 병목 문제와 연결할 수 있다.

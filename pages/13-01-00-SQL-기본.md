## 핵심 개념

- SELECT는 조회할 컬럼(또는 표현식)을 지정한다.
- FROM은 데이터를 가져올 테이블(또는 서브쿼리, 조인)을 지정한다.
- WHERE는 행 단위 조건을 필터링한다.
- GROUP BY는 집계(aggregation)를 적용할 그룹 기준을 만든다.
- HAVING은 그룹 단위의 필터링을 처리한다.
- ORDER BY는 결과 정렬, LIMIT/OFFSET은 결과 개수 제어(DBMS별 차이 있음).

### 실행(논리적) 순서 — 시험·학습 포인트

일반적으로 SQL 문은 작성된 순서와는 다른 논리적 평가 순서를 가진다. 이해하면 디버깅과 시험 문제 풀이에 도움이 된다.

1. FROM (테이블 접근, JOIN 수행)
2. WHERE (행 필터링)
3. GROUP BY (그룹화)
4. HAVING (그룹 필터링)
5. SELECT (컬럼/집계 계산, DISTINCT 적용)
6. ORDER BY (정렬)
7. LIMIT/OFFSET (결과 개수 제한)

- 실제 물리적 실행은 DBMS 옵티마이저가 결정한다(인덱스 사용, 조인 순서/알고리즘 등).
- 시험에서는 위 논리적 순서를 묻는 문제가 자주 출제된다.

## 서술형 확장 개념

- SQL은 선언형 언어이다. 사용자는 "무엇을" 원하는지(질의)를 표현하고 DBMS 옵티마이저는 "어떻게" 실행할지(물리 계획)를 결정한다. 성능 문제를 분석할 때는 EXPLAIN/실행계획을 보고 인덱스 사용 여부, 조인 순서, 예상 비용 등을 확인한다.
- ER 모델링에서는 엔터티, 속성, 관계(및 카디널리티)를 정리한 뒤 이를 릴레이션(테이블) 스키마로 변환한다. 약한 엔터티는 소유 엔터티의 기본키를 포함해 식별한다.
- 관계대수 관점에서 selection은 행 필터링(WHERE), projection은 열 선택(SELECT), join은 관련 튜플 결합, division은 특정 조건을 모두 만족하는 대상 검색과 연관된다.

## 쉽게 이해하기

- SQL은 데이터에게 질문하는 문장으로 읽으면 쉽다: "어디에서(WHERE), 어떤 조건으로, 무엇을 보여줘(SELECT), 어떻게 묶고(GROUP BY), 어떤 그룹만 보여줘(HAVING), 어떤 순서로 보여줘(ORDER BY)?"
- 초보자는 SELECT → FROM → WHERE 순으로 읽는 습관을 들이면 논리적 흐름을 이해하는 데 도움이 된다.

## 예시와 단계별 평가

다음 예시는 논리적 실행 순서를 이해하는 데 도움이 된다.

```sql
-- 예시 테이블: orders(order_id, customer_id, amount, order_date)
SELECT customer_id, COUNT(*) AS orders_cnt, SUM(amount) AS total
FROM orders
WHERE order_date >= '2023-01-01'
GROUP BY customer_id
HAVING SUM(amount) > 1000
ORDER BY total DESC
LIMIT 10;
```

논리적 평가 순서:
- FROM: orders 테이블을 읽음
- WHERE: 2023-01-01 이후의 행만 남김
- GROUP BY: customer_id로 그룹화
- HAVING: 그룹별 SUM(amount) > 1000인 그룹만 남김
- SELECT: customer_id, COUNT(*), SUM(amount)를 계산
- ORDER BY / LIMIT: total 기준 내림차순 정렬 후 상위 10개 반환

## 집계와 GROUP BY 규칙

- 집계 함수(예: COUNT, SUM, AVG, MIN, MAX)는 그룹 내에서 계산된다.
- 대부분의 DBMS에서는 SELECT 절에 있는 비집계 컬럼은 GROUP BY에 포함되어야 한다(또는 함수적 종속성이 있어야 함 — DBMS별 차이 존재).
- HAVING은 GROUP BY 이후에 그룹을 필터링하므로 집계 결과를 조건으로 걸 때 사용한다. WHERE는 집계 전 행 필터링에 사용한다.

## NULL 처리 핵심

- NULL은 값이 "없음"을 의미하며, 일반적인 비교 연산(=, <, >)에서 UNKNOWN으로 처리된다.
- NULL 비교는 IS NULL, IS NOT NULL을 사용해야 한다.
- 집계 함수는 NULL을 보통 무시한다(예: SUM은 NULL을 0으로 간주하지 않고 무시).

## 조인과 기본 개념

- 조인은 관계형 데이터 모델의 핵심으로, INNER JOIN, LEFT/RIGHT OUTER JOIN, CROSS JOIN 등이 있다.
- 조인 성능은 조인 조건의 컬럼에 인덱스가 있느냐, 조인 순서, 조인 알고리즘(중첩 루프, 해시 조인, 병합 조인) 등에 좌우된다.
- 실무에서는 불필요한 전체 테이블 스캔을 막기 위해 적절한 인덱싱과 필터링을 고려해야 한다.

## 실무 연결 — 성능 점검 체크리스트

- EXPLAIN 또는 실행계획을 통해 인덱스 사용 여부, 조인 순서를 확인한다.
- WHERE 절에 인덱스가 걸린 컬럼을 사용하되, 컬럼에 함수 적용을 피하면 인덱스가 무효화될 수 있다.
- SELECT * 는 필요한 컬럼만 명시하는 것이 네트워크와 I/O 비용을 줄인다.
- 큰 집계나 그룹화는 필요한 경우 사전 집계(요약 테이블)나 적절한 파티셔닝으로 성능을 개선한다.

## 시험 포인트 요약

- SQL의 논리적 실행 순서(FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY)를 정확히 쓰고 설명할 수 있어야 한다.
- GROUP BY와 HAVING의 차이, 집계 함수의 동작 원리, 비집계 컬럼의 GROUP BY 포함 조건 등을 설명할 수 있어야 한다.
- NULL 비교 방법(IS NULL / IS NOT NULL)과 NULL이 비교/집계에 미치는 영향을 설명할 수 있어야 한다.
- 실행계획(EXPLAIN)의 기본 의미(인덱스 사용 여부, 조인 순서 등)를 이해하고 성능 관련 판단 근거로 삼을 수 있어야 한다.

# 06-02-01. FCFS-SJF-HRN-RR

> 학습 목적: 대표 스케줄링 알고리즘의 선택 기준을 구분하고, 간트 차트로 대기시간·반환시간·응답률을 계산한다.

## 한눈에 비교

| 알고리즘 | 선택 기준 | 선점 여부 | 장점 | 단점 | 계산 포인트 |
|---|---|---|---|---|---|
| FCFS | 먼저 도착한 프로세스 | 비선점 | 단순, 구현 쉬움 | 긴 작업이 앞에 오면 전체 지연 (Convoy Effect) | 도착 순서 그대로 간트 차트 작성. 완료시간→반환→대기 순으로 계산 |
| SJF | 실행시간이 가장 짧은 프로세스 | 비선점(또는 선점형 SRTF로 변형 가능) | 평균 대기시간 감소 경향 | 긴 작업 기아 가능 | 현재 Ready Queue에 있는 프로세스들 중 실행시간(또는 남은시간)이 가장 짧은 것 선택 |
| HRN | `(대기시간 + 실행시간) / 실행시간` 최대 (응답률) | 비선점 | 오래 기다린 작업 보상, 기아 완화 | 매 선택 시 응답률 계산 필요 | 각 후보의 응답률 계산 — 대기시간 증가가 우선순위 상승으로 이어짐 |
| RR | time quantum마다 순환 | 선점 | 응답시간 개선, 인터랙티브 시스템에 적합 | 문맥교환 오버헤드 증가 가능 | 남은 실행시간과 Ready Queue 순서 관리. quantum 경계 처리 중요 |

## 예제 입력

| 프로세스 | 도착시간 | 실행시간 |
|---|---:|---:|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 2 |
| P4 | 3 | 1 |

이 예제에서 모든 알고리즘은 같은 입력을 받지만, CPU를 넘기는 기준이 달라 결과가 달라진다. 아래에서는 각 알고리즘에 대해 순서·간트·완료/반환/대기 시간을 단계별로 계산한다.

## FCFS: First-Come, First-Served

설명
- 도착 순서(Ready Queue에 들어온 순서)를 그대로 처리한다. 비선점 방식이다.
- 구현이 단순하지만 긴 작업이 앞에 오면 뒤의 짧은 작업들이 오래 기다리는 Convoy Effect가 발생한다.

간트 차트 (도착 순서: P1 → P2 → P3 → P4)

```text
0      8     12    14 15
|  P1  | P2  | P3 |P4|
```

계산 (완료시간 → 반환시간(=완료-도착) → 대기시간(=반환-실행))

| 프로세스 | 완료시간 | 반환시간 = 완료-도착 | 대기시간 = 반환-실행 |
|---|---:|---:|---:|
| P1 | 8 | 8 | 0 |
| P2 | 12 | 11 | 7 |
| P3 | 14 | 12 | 10 |
| P4 | 15 | 12 | 11 |

- 평균 대기시간: (0 + 7 + 10 + 11) / 4 = 7

시험 포인트 / 실무 연결
- 시험에서는 간트 차트에 각 구간의 시작·종료 시간을 정확히 표시하면 오류를 줄일 수 있다.
- 실무: 배치 처리(batch jobs)에서 단순 구현으로 사용 가능하나, 사용자 인터랙션이 중요한 시스템에는 부적절.

## SJF: Shortest Job First

설명
- Ready Queue에 있는 프로세스들 중 실행시간이 가장 짧은 것을 선택한다. 여기서는 비선점 SJF를 기준으로 설명한다.
- 평균 대기시간을 최소화하는 경향이 있지만 긴 작업이 계속해서 밀릴 수 있다(기아).
- 변형으로 SRTF(Shortest Remaining Time First)라는 선점형 버전이 있다(도중에 더 짧은 작업이 도착하면 선점).

간트 차트 (비선점 SJF, 초기에는 P1만 있음 → P1 실행 종료 시점에 후보들 중 선택)

```text
0      8 9   11    15
|  P1  |P4|P3| P2 |
```

선택 근거(시점별)
- t=0: P1만 존재 → P1 실행(0~8)
- t=8: P2(실행4), P3(2), P4(1)이 모두 도착해 있음 → 실행시간이 가장 짧은 P4 선택
- 이후 P3(2), P2(4) 순으로 실행

계산

| 프로세스 | 완료시간 | 반환시간 | 대기시간 |
|---|---:|---:|---:|
| P1 | 8 | 8 | 0 |
| P4 | 9 | 6 | 5 |
| P3 | 11 | 9 | 7 |
| P2 | 15 | 14 | 10 |

- 평균 대기시간: (0 + 5 + 7 + 10) / 4 = 5.5

시험 포인트 / 실무 연결
- SJF에서 중요한 것은 '그 시점(또는 간트 구간 시작 시점)에 Ready Queue에 누가 있는가'다. 아직 도착하지 않은 프로세스를 후보로 보지 않음.
- 기출·시험에서는 SJF와 SRTF를 혼동하기 쉬우니 문제 지문에서 ‘선점 여부’(preemptive/non-preemptive)를 반드시 확인하라.
- 실무: 짧은 작업들을 먼저 처리해 응답성이 좋은 배치/상태가 필요할 때 고려하나 기아 문제를 동반.

## HRN: Highest Response-ratio Next

설명
- SJF의 기아 문제를 완화하기 위해 대기시간을 반영한 응답률(Response Ratio)을 우선순위로 사용한다.

```text
응답률 = (대기시간 + 실행시간) / 실행시간 = 1 + 대기시간 / 실행시간
```

- 응답률이 클수록 우선순위가 높다. 즉, 기다리면 기다릴수록 우선순위가 올라간다.
- 일반적으로 비선점 방식으로 설명되며, 선택 시마다 후보들의 응답률을 새로 계산한다.

예제에서의 계산(주요 시점 t=8 이후)
- t=8 시점의 대기시간: P2는 7(=8-1), P3는 6(=8-2), P4는 5(=8-3)
- 응답률 계산:
  - P2: (7 + 4) / 4 = 2.75
  - P3: (6 + 2) / 2 = 4.00
  - P4: (5 + 1) / 1 = 6.00 → 가장 큼 → P4 선택
- P4가 끝난 t=9에서 다시 후보들의 대기시간·응답률 갱신 → P3 선택 등

시점별 요약

| 시점 | 후보 | 계산 | 선택 |
|---:|---|---|---:|
| 8 | P2 | (7+4)/4 = 2.75 |  |
| 8 | P3 | (6+2)/2 = 4.00 |  |
| 8 | P4 | (5+1)/1 = 6.00 | P4 |
| 9 | P2 | (8+4)/4 = 3.00 |  |
| 9 | P3 | (7+2)/2 = 4.50 | P3 |
| 11 | P2 | (10+4)/4 = 3.50 | P2 |

- 이 예제에서는 최종 실행 순서가 SJF와 같지만, 일반적으로는 오래 기다린 긴 작업이 HRN에서 먼저 선택되는 경우가 생긴다.

시험 포인트 / 실무 연결
- HRN 문제는 ‘각 선택 시점’마다 응답률을 계산하는 연습이 중요하다. 계산 착오를 줄이려면 각 프로세스의 대기시간(현재 시점 - 도착시간)을 먼저 기록하고 공식에 대입하라.
- 실무: 대기시간 보상을 통해 기아를 완화하려는 정책 설계에서 개념적으로 유용. 다만 운영체제 실제 스케줄러는 더 복잡한 페어링(예: 우선순위 + aging)을 사용.

## RR: Round Robin

설명
- 시간 할당량(time quantum, q)을 정하고 각 프로세스를 q만큼 순환 처리한다. 선점 스케줄링이다.
- 인터랙티브 시스템에서 사용자 응답성을 보장하기 위해 자주 사용된다.
- q가 너무 작으면 문맥교환 오버헤드가 커지고, q가 너무 크면 FCFS와 유사해진다.

예: q = 2 인 경우 간트 차트 (주요 구간 표시)

```text
0  2  4  6  8 9 11   15
|P1|P2|P3|P1|P4|P2| P1 |
```

동작 원칙 요약
1. 현재 실행 중인 프로세스가 quantum을 다 쓰면(또는 종료하면) 다음 Ready Queue 맨 뒤로 간다(종료면 제거).
2. quantum 중간에 새로운 프로세스가 도착하면 Ready Queue의 뒤에 추가한다.
3. 프로세스가 quantum보다 적게 남으면 남은 시간만 실행하고 종료한다.
4. 완료 시점을 정확히 기록하여 반환·대기 시간을 계산한다.

계산 결과

| 프로세스 | 완료시간 | 반환시간 | 대기시간 |
|---|---:|---:|---:|
| P1 | 15 | 15 | 7 |
| P2 | 11 | 10 | 6 |
| P3 | 6 | 4 | 2 |
| P4 | 9 | 6 | 5 |

- 평균 대기시간: (7 + 6 + 2 + 5) / 4 = 5

시험 포인트 / 실무 연결
- 문제 풀이 시 Ready Queue의 상태(시점별)를 표로 적어가며 처리하면 실수가 줄어든다.
- quantum 경계에서 도착한 프로세스의 enqueue 순서와, quantum 종료 시 재진입 순서를 헷갈리지 말자.
- 실무: 대화형/멀티유저 환경에서 응답성을 확보하기 위해 널리 사용. 하지만 우선순위가 필요한 워크로드에서는 보완 필요.

## 시험장에서 빠르게 푸는 법

1. 표 옆에 `남은 실행시간` 칸을 만든다. RR/SRTF에서 특히 중요하다.
2. 간트 차트 위에는 실행 구간을 쓰고, 아래에는 시간 눈금을 쓴다. (시작·종료 시간을 정확히 표기)
3. 완료시간을 먼저 구한 뒤 `반환시간 = 완료시간 - 도착시간`을 계산한다.
4. 마지막에 `대기시간 = 반환시간 - 실행시간`으로 계산한다.
5. 평균값은 마지막에 한 번만 구한다. 중간에 평균부터 내면 수정할 때 실수한다.
6. 문제에서 선점 여부(preemptive/non-preemptive)와 quantum(q) 값을 반드시 확인하라.
7. 동률(우선순위가 같은 경우)의 처리 규칙이 문제에 명시되어 있으면 그 규칙을 따르고, 명시되지 않으면 도착순으로 처리하는 경우가 많다.

체크리스트(문제 푸는 순서)
- [ ] 선점 여부/quantum 확인
- [ ] 간트 차트에 시간 눈금 및 구간 기록
- [ ] 각 프로세스의 완료시간 기록
- [ ] 반환시간 → 대기시간 순으로 계산
- [ ] 평균값은 마지막에 한 번 계산

## 약어 풀이

- FCFS: First-Come, First-Served, 선입선처리
- HRN: Highest Response-ratio Next, 최고 응답률 우선
- RR: Round Robin, 라운드 로빈
- SJF: Shortest Job First, 최단 작업 우선
- SRTF: Shortest Remaining Time First (SJF의 선점형 변형)

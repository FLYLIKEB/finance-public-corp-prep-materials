# 10-02. 인증-인가-접근통제

> 학습 목적: 인증과 인가, 접근통제 모델을 구분한다.
> 관련 기출: [05-12-보안-기출-모음](05-12-보안-기출-모음.md)
> 연결 핵심정리: [04-4-네트워크-프로토콜-보안](04-04-네트워크-프로토콜-보안.md)

## 핵심 개념

- 인증(Authentication): 사용자가 누구인지 확인하는 과정이다. 주로 ID/비밀번호, 토큰, 인증서, 생체정보 등을 통해 신원을 검증한다.
- 인가(Authorization): 인증된 주체가 어떤 리소스에 대해 어떤 행위를 할 수 있는지를 결정하는 과정이다. 권한이나 정책에 따라 접근을 허용하거나 거부한다.
- 접근통제(Access Control): 인증과 인가의 결정에 따라 실제로 자원에 대한 접근을 허용·차단하는 메커니즘이다.
- CA(인증기관): 공개키 기반구조(PKI)에서 인증서를 발급·관리·폐기(또는 폐기 상태 확인)하는 역할을 한다.

### 서술형 확장 개념

- PKI(공개키 기반구조): 공개키와 주체 정보를 결합한 인증서를 발급하고, 인증서의 신뢰연쇄(chain of trust)를 관리하여 공개키의 신뢰성을 확보한다. 역할별 요소는 다음과 같다.
  - CA(Certificate Authority): 인증서 발급과 발급자 신뢰의 핵심 역할.
  - RA(Registration Authority): 신청자 신원 확인 같은 등록절차를 보조.
  - CRL(Certificate Revocation List) / OCSP(Online Certificate Status Protocol): 인증서 폐기·취소 여부를 확인하는 수단. CRL은 목록 방식, OCSP는 실시간 질의 방식으로 이해한다.

- 접근통제 모델 요약
  - DAC(Discretionary Access Control): 자원 소유자가 접근권한을 제어. 장점은 유연성, 한계는 권한 전파 통제의 불투명성.
  - MAC(Mandatory Access Control): 중앙 관리자 또는 시스템이 보안등급·정책에 따라 강제적으로 접근을 통제. 군사·정부 등 고보안 환경에서 적합. 장점은 엄격한 통제, 단점은 운영 유연성 저하.
  - RBAC(Role-Based Access Control): 역할에 권한을 부여하고 사용자를 역할에 매핑. 조직 단위의 권한 관리를 단순화.
  - ABAC(Attribute-Based Access Control): 사용자·자원·환경·행위의 속성(attribute)을 조합해 세밀한 정책을 평가. 강력하지만 설계·운영이 복잡.

- 금융권 등 규제 환경에서의 적용 포인트
  - 최소권한 원칙(least privilege), 직무분리(Separation of Duties), 권한 승인·검토·회수 이력 관리가 필수적이다.
  - 운영자(관리자) 권한은 다중인증(MFA), 접근기록(감사로그), 세션 타임아웃, 정기적 권한검토로 통제한다.

| 모델 | 기준 | 장점 | 한계 |
| --- | --- | --- | --- |
| DAC | 소유자 재량 | 유연함 | 권한 전파 통제 약함 |
| MAC | 보안 등급 | 강한 통제 | 운영 유연성 낮음 |
| RBAC | 역할 | 조직 권한관리 적합 | 예외 정책 표현 한계 |
| ABAC | 속성/조건 | 세밀한 정책 | 정책 설계 복잡 |

## 쉽게 이해하기

- 인증: “당신이 누구인가?” — 예: 로그인 시 ID/비밀번호, OTP, 스마트카드, 인증서
- 인가: “당신이 이것을 할 수 있는가?” — 예: 로그인 후에도 특정 메뉴에 대한 권한이 없을 수 있음
- 접근통제: 인증·인가 결과로 문을 열어줄지 결정하는 경비 시스템

## 시험 포인트 (주요 확인 항목)

- 정의 구분: 인증 vs 인가 vs 접근통제의 차이를 명확히 설명할 수 있어야 한다.
- 접근통제 모델 비교: DAC/MAC/RBAC/ABAC의 기준, 장단점, 적용 사례(예: RBAC은 기업 인사 기반 권한 관리에 적합, MAC은 군사·정부 환경)
- PKI 구성요소: CA/RA/CRL/OCSP의 역할을 설명할 수 있어야 한다.
- 인증요소의 유형: 지식(비밀번호), 소유(토큰·스마트카드), 고유(생체) 등 3요소(MFA)의 의미와 실무 적용 이유
- 인증서 수명·폐기: 인증서 만료와 폐기 처리(자동 갱신, CRL/OCSP 확인)의 중요성
- 최소권한과 직무분리: 규제 환경에서 반드시 요구되는 통제(예: 금융결제, 내부 감사 요건)
- 세션 관리와 토큰: 세션 타임아웃, 재인증 정책, 접근 토큰의 발급·취소(토큰 만료·리프레시 전략) 기본 지식

## 실무 연결 (설계·운영 체크리스트 및 권장 관행)

- 인증 설계
  - 비밀번호 정책: 최소 길이, 복잡성, 최대 실패 시 잠금, 해시+솔트 저장(예: 강한 해시 알고리즘 권장)
  - MFA 도입: 관리자·특권사용자에 대해 강제. 가능하면 물리적 토큰 또는 앱 기반 OTP와 FIDO/WebAuthn 등 비밀번호 대체 기술 검토.
  - SSO 도입 시 보안 고려사항: 중앙 인증 실패 시 서비스 영향, 세션 전파·종료 정책, 단일 로그아웃 구현 여부 점검.

- 권한관리
  - RBAC 설계: 역할을 조직단위로 묶되, 역할표(role catalog)를 작성하고 표준화된 승인 절차를 둔다.
  - 권한 검토: 정기적(예: 분기별) 권한 검토 및 자동화된 권한 회수 프로세스 시행.
  - 직무분리 구현: 금융 트랜잭션 등 민감 작업에 대해 승인자와 실행자를 분리.

- PKI 및 인증서 운영
  - 인증서 생명주기 관리: 발급, 갱신, 폐기(교체) 절차 문서화 및 자동화(가능하면) 구현.
  - 인증서 상태 확인: 서비스는 OCSP/CRL 확인을 통해 폐기된 인증서를 거부하도록 구성.
  - 비밀키 보호: HSM 또는 보안 모듈을 사용해 개인키를 보호.

- 로깅·모니터링·감사
  - 인증·인가 관련 이벤트(로그인 실패, 권한 변경, 관리자 권한 사용 등)를 중앙로그시스템에 수집·보관.
  - 비정상 패턴(브루트포스, 권한 남용 등) 탐지 규칙을 마련하고 경보 체계를 운영.

- 긴급·예외 접근
  - 비상 접근(예: break-glass) 계정 정책과 사용 기록, 사후 감사 절차 수립.
  - 임시 권한 부여 시 만료 시각을 명시하고 자동 회수하도록 설정.

## 예시 흐름 (핵심 절차를 단계적으로 이해)

- 기본 로그인 + 권한부여 흐름
  1. 사용자가 자격증명 제출(ID/암호 등).
  2. 인증서버가 자격증명 검증(필요시 MFA 요구).
  3. 인증 성공 시 토큰(세션ID 또는 JWT 등) 발급.
  4. 클라이언트는 토큰으로 자원서버에 접근, 자원서버는 토큰·권한을 검증해 인가 결정.

- PKI 사용 시 인증서 검증 흐름(요약)
  1. 클라이언트/서버가 인증서 제출.
  2. 상대는 인증서의 서명 유효성, 유효기간, 신뢰연쇄(chain of trust)를 확인.
  3. CRL 또는 OCSP를 통해 폐기 여부를 검사.
  4. 모두 통과하면 TLS 핸드셰이크 완료 및 신원 확인.

- OAuth/OIDC(개념적) 적용 포인트
  - 인증과 인가를 분리: 인증은 OpenID Connect로, 권한(리소스 접근)은 OAuth 토큰으로 처리하는 패턴이 일반적.
  - 토큰 수명과 스코프(scope) 설계: 최소 권한 부여를 위해 스코프를 세분화하고 토큰 만료를 짧게 설정.

## 추가 학습 팁

- 정의 중심으로 외우되, 실무에서 어떻게 적용되는지(예: 권한 검토 주기, 인증서 자동 갱신, MFA 대상 구분)를 사례로 연결하면 서술형·실무형 문제에 대비하기 좋다.
- 접근통제 모델은 장단점·적용 사례를 1~2문장으로 요약해두면 기출 문제에서 빠르게 답변할 수 있다.

## 약어 풀이

- ABAC: Attribute-Based Access Control, 속성 기반 접근통제
- CA: Certificate Authority, 인증기관
- CRL: Certificate Revocation List, 인증서 폐기 목록
- MFA: Multi-Factor Authentication, 다중 인증
- OCSP: Online Certificate Status Protocol, 인증서 상태 확인 프로토콜
- PKI: Public Key Infrastructure, 공개키 기반 구조
- RA: Registration Authority, 등록기관
- RBAC: Role-Based Access Control, 역할 기반 접근통제

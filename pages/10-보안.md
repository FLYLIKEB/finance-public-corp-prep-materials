## 핵심 개념 요약

- 암호화 vs 해시
  - 암호화: 원본을 복원할 수 있도록 설계(대칭/비대칭). 기밀성 확보에 사용.
  - 해시: 입력으로부터 고정 길이 출력 생성, 역산이 사실상 불가능. 무결성 검증·비밀번호 저장 등.
- 인증(Identity) vs 인가(Authorization)
  - 인증: 사용자가 주장하는 정체성을 확인(로그인, MFA 등).
  - 인가: 인증된 주체가 어떤 자원·행위를 수행할 수 있는지 결정(권한, ACL, 역할기반 접근제어).
- 접근통제 모델
  - DAC, MAC, RBAC 등의 기본 모델과 실제 서비스에서의 적용(예: 최소 권한 원칙).
- TLS·인증서·CA 체계
  - 서버 인증과 연결 암호화의 흐름(인증서 체인, 신뢰의 근원인 CA 개념).
- 웹 공격(주요 유형과 방어)
  - 입력 검증 실패로 인한 SQL Injection, XSS 등. 방어는 입력 검증, 출력 인코딩, 파라미터화된 쿼리, CSP 등.
- 네트워크 공격
  - DDoS, 패킷 스니핑, 세션 하이재킹 등. 방어는 네트워크 레벨의 필터링·레이트 리미팅·암호화.
- 로깅과 감사
  - 보안 사고 대응을 위한 로그의 적절한 수집·보존·분석(정합성, 타임스탬프, 접근 제어).

---

## 시험 포인트 (짧게 정리)

- 암호화와 해시를 한 문장으로 구분해서 설명할 수 있어야 한다.
- 대칭/비대칭 암호화의 용도(성능 vs 키분배)와 TLS에서의 역할을 이해한다.
- 인증서 체인의 기본 흐름(서버 → 중간 CA → 루트 CA)과 신뢰의 의미를 설명할 수 있다.
- SQL Injection과 XSS의 원리와 각 공격에 대한 대표적인 방어 기법을 한 줄로 정리한다.
- DDoS 방어의 기본 전략(레이트 리미팅·CDN·필터링)과 로그 기반의 침입 탐지의 차이를 이해한다.
- IDS와 IPS의 역할 차이(탐지 vs 실시간 차단)를 구분한다.

---

## 실무 연결 포인트 (면접/실무 질문 대비)

- 비밀번호 저장 설계: 평문 저장은 금지, 해시 + 솔트 적용, 필요시 키 도입 및 재해 복구 계획을 설명할 수 있어야 한다.
- TLS 적용 시 체크리스트: 최신 프로토콜 사용, 안전한 암호 스위트 선택, 인증서 유효성·자동 갱신(예: ACME 방식 설명은 금지하지 않음) 등을 검토한다.
- 입력 검증 전략: 서버 측 검증 우선, 화이트리스트 방식 권장, 파라미터화된 쿼리를 통한 DB 접근, 출력 시 인코딩 적용.
- 로깅 체계 설계: 보안 관련 이벤트(인증 실패, 권한 변경, 관리자 행위) 우선 로깅, 로그의 무결성 확보, 보존 기간과 접근 통제 정책.
- 네트워크 보안 운영: 분산 공격에 대비한 스케일링/레이트 리미팅, WAF 설정, 내부망과 외부망 분리(망분리) 사례 설명.

---

## 학습 팁 및 권장 순서

1. 개념 기반(암호화/해시/인증·인가)을 먼저 확실히 한다. 핵심 용어를 한 문장으로 요약해보라.
2. 웹·네트워크 공격 사례를 통해 원리(취약점)→공격 절차→대응책(우선순위) 순으로 학습한다.
3. 로그/IDS/IPS 등 모니터링 시스템은 실제 사고 대응 시나리오(예: 인증 우회 탐지)로 연습한다.
4. 실무 연계: 간단한 토이 프로젝트에 TLS 적용, 안전한 비밀번호 저장, 간단한 WAF 룰 테스트를 해보면 이해도가 높아진다.

---

## 복습 포인트

- 공격명은 원리와 대응을 한 줄로 정리한다.
- 인증서·CA·TLS는 네트워크와 함께 복습한다.
- DDoS, XSS, SQL Injection은 기출 연결이 많다.

---

## 약어 풀이

- CA: Certificate Authority, 인증기관
- DDoS: Distributed Denial of Service, 분산 서비스 거부 공격
- IDS: Intrusion Detection System, 침입 탐지 시스템
- IPS: Intrusion Prevention System, 침입 방지 시스템
- SQL: Structured Query Language, 구조화 질의어
- XSS: Cross-Site Scripting, 교차 사이트 스크립팅

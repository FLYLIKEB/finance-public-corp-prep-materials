## 프로그래밍 언어

> 중요도: **상** (★★★)


![프로그래밍 언어 실행 방식](https://raw.githubusercontent.com/FLYLIKEB/finance-public-corp-prep-materials/main/assets/downloaded-visual-aids/programming-interpreter.png)
> 그림: 인터프리터 실행 구조 기반으로 프로그래밍 언어 실행 방식 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Interpreter-executed-on-hardware-i-diagram.svg

### 1. 출력값 구하기

C 언어, 파이썬, 자바

> **출제 경향**   정말 많이 나옵니다. 많이 나오는 곳은 3-4 문제가 출제될정도로 많이 나오니,
기본언어인 C,자바,파이썬의 간단한 출력값정도는 알수있을정도로 공부해야합니다!

### 2. 스크립트언어 vs 컴파일언어

스크립트 언어 : 특정 작업이나 애플리케이션의 제어 및 자동화를 위해 설계된 프로그래밍 언어임.
일반적으로 해석기(인터프리터)를 통해 실행되며, 컴파일 과정을 거치지 않기 때문에 개발 및 실행
속도가 빠름.

(JavaScript, Python, Ruby, PHP, Perl)

#### 장점
- 빠른 개발 속도
- 즉시 실행 가능
- 동적 수정 용이

#### 단점
- 상대적으로 낮은 성능
- 코드가 실행 환경에 노출됨

컴파일 언어 : 소스 코드를 기계어로 번역하여 실행 파일을 생성한 후, 실행 파일을 실행하는 방식의
프로그래밍 언어

(C, C++, Java, C#, Swift, Go, Rust, Fortran, COBOL)

#### 스크립트 언어 vs 컴파일 언어 비교표

| 구분 | 스크립트 언어 | 컴파일 언어 |
| --- | --- | --- |
| 실행 방식 | 인터프리터가 해석하며 실행 | 컴파일 후 실행 파일 실행 |
| 장점 | 개발·수정이 빠름 | 실행 속도와 최적화에 유리 |
| 단점 | 성능이 상대적으로 낮음 | 컴파일 과정 필요 |
| 예시 | Python, JavaScript, Ruby, PHP | C, C++, Java, Go, Rust |

> **암기 포인트**   `즉시 실행·인터프리터`는 스크립트, `기계어 번역·실행 파일`은 컴파일입니다.

#### 장점
- 높은 실행 속도
- 최적화된 실행 파일 생성
- 오류 검사 가능

#### 단점
- 개발 및 수정이 번거로움
- 컴파일 과정이 필요함

> **출제 경향**   보통 스크립트, 컴파일언어의 예시를 물어보거나, 둘의 차이점에 대한 설명 문제가
많이 출제됩니다.

### 3. 오버로딩 vs 오버라이딩

오버로딩(Overloading)
- **정의:** 같은 이름을 가진 메서드를 여러 개 정의하되, 각 메서드는 서로 다른 매개변수를 가짐.
- **특징:**
  메서드 이름은 같음
  매개변수의 타입, 개수 또는 순서가 다름
  컴파일 타임에 어떤 메서드가 호출될지 결정됨

오버라이딩(Overriding)
- **정의:** 상위 클래스의 메서드를 하위 클래스에서 재정의하여 사용하는 것.
- **특징:**
  메서드 이름, 매개변수, 반환 타입 모두 같음
  상위 클래스의 메서드를 덮어씀
  런타임에 어떤 메서드가 호출될지 결정됨

#### 오버로딩 vs 오버라이딩 비교표

| 구분 | 오버로딩 | 오버라이딩 |
| --- | --- | --- |
| 관계 | 같은 클래스 안에서도 가능 | 상속 관계 필요 |
| 메서드 이름 | 같음 | 같음 |
| 매개변수 | 타입·개수·순서 중 하나가 달라야 함 | 같아야 함 |
| 결정 시점 | 컴파일 타임 | 런타임 |
| 핵심 표현 | 같은 이름, 다른 매개변수 | 부모 메서드 재정의 |

> **출제 경향**   객체지향 프로그래밍의 기초로 실제 필기에서 많이 출제되는 편은 아니나 코드를
주면서 오버로딩 되는지 안되는지 등 같은 문제를 내는 경우가 있습니다.

### 4. 그 외 문법

> **출제 경향**   그 외 문법으로 상속과 배열에 대한 문제가 종종 출제됩니다. 상속 코드를 주면서
출력값을 묻거나 자바 배열을 선지선다형으로 나열하면서 올바른 배열방식을 묻는 문제가 출제되니
꼭 알아둬야하니다.

## SQL 문법

> 중요도: **상** (★★★)


![SQL 명령어 분류](https://raw.githubusercontent.com/FLYLIKEB/finance-public-corp-prep-materials/main/assets/downloaded-visual-aids/sql-sample-table.png)
> 그림: SQL 테이블 예시 기반으로 SQL 명령어 분류 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:SQL_Inventory_Simple_Example_Table.png

### 1. DDL (Data Definition Language)
- CREATE: 데이터베이스 객체(테이블, 인덱스, 뷰 등)를 생성함.
- ALTER: 기존의 데이터베이스 객체를 수정함.
- DROP: 데이터베이스 객체를 삭제함.
- TRUNCATE: 테이블의 모든 데이터를 삭제함(구조는 유지)

### 2. DML (Data Manipulation Language)

- SELECT: 데이터를 조회함.

- INSERT: 데이터를 삽입함.

- UPDATE: 기존 데이터를 수정함.

- DELETE: 데이터를 삭제함

### 3. DCL (Data Control Language)

- GRANT: 사용자에게 특정 권한을 부여함.

- REVOKE: 사용자에게 부여된 권한을 회수함.
  Ex) GRANT SELECT, INSERT ONEmployees TOuser_name;
  * Cascade : 권한을 회수할 때 그 권한에 의존하는 다른 권한도 함께 회수함.

#### SQL 명령어 암기표

| 분류 | 의미 | 대표 명령어 | 선지 판단 포인트 |
| --- | --- | --- | --- |
| DDL | 구조 정의 | CREATE, ALTER, DROP, TRUNCATE | 테이블·인덱스·뷰 구조 변경 |
| DML | 데이터 조작 | SELECT, INSERT, UPDATE, DELETE | 행 데이터를 조회·삽입·수정·삭제 |
| DCL | 권한 제어 | GRANT, REVOKE | 사용자 권한 부여·회수 |

```text
DDL = Definition = 구조
DML = Manipulation = 데이터
DCL = Control = 권한
```

> **출제 경향**   아무리 강조해도 아깝지 않은 SQL 문법! 대부분의 필기에 SQL 은 한문제씩 꼭
껴있습니다.
위에 있는 모든 함수의 기능을 알고 실제 예시도 잘 숙지해야합니다. 심지어 약술문제도 출제된적이
있으니 SQL 은 꼼꼼히 공부해야합니다.
’DDL 에 포함되지 않은 함수는?’ 또는 ‘아래 SQL 문에서 빈칸에 들어갈 함수는?’식으로 많이 출제됨

## 분산처리시스템

> 중요도: **상** (★★★)


![분산처리시스템 구조](https://raw.githubusercontent.com/FLYLIKEB/finance-public-corp-prep-materials/main/assets/downloaded-visual-aids/distributed-system-model.png)
> 그림: 분산 시스템 모델 기반으로 분산처리시스템 구조 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Ubiquitous_-_Distributed_System_Model.png

### 1. 분산처리시스템 개념

  여러 독립적인 컴퓨터들이 네트워크를 통해 연결되어 하나의 시스템처럼 동작하는 시스템

### 2. 특징
- 분산된 자원: 여러 컴퓨터가 네트워크를 통해 연결되어 자원을 분산하여 사용함.
- 병렬 처리: 작업을 여러 컴퓨터에 분산시켜 병렬로 처리하여 성능을 향상시킴.
- 확장성: 새로운 컴퓨터를 추가하여 시스템 성능을 확장할 수 있음.
- 고가용성: 일부 컴퓨터가 고장 나더라도 다른 컴퓨터들이 작업을 이어받아 시스템의
  가용성을 높임.
- 투명성: 사용자에게는 단일 시스템처럼 보이지만, 내부적으로는 여러 컴퓨터가 협력하여
  작업을 처리함.

```text
사용자
  ↓
[단일 시스템처럼 보이는 서비스]
  ↓
[노드 A] + [노드 B] + [노드 C]
  ↓         ↓         ↓
저장/계산   저장/계산   저장/계산
```

| 특징 | 의미 | 시험 포인트 |
| --- | --- | --- |
| 분산 자원 | 여러 컴퓨터의 자원을 함께 사용 | 하나의 컴퓨터가 아님 |
| 병렬 처리 | 작업을 나누어 동시에 처리 | 성능 향상 |
| 확장성 | 노드를 추가해 성능 확장 | Scale-out |
| 고가용성 | 일부 장애에도 서비스 지속 | 장애 대응 |
| 투명성 | 사용자는 하나의 시스템처럼 인식 | 내부 분산을 숨김 |

### 3. 장점
- 성능 향상: 병렬 처리와 자원 분산으로 인해 성능이 향상됨.
- 확장성: 필요에 따라 시스템 용량을 쉽게 확장할 수 있음.
- 유연성: 다양한 하드웨어와 소프트웨어를 통합하여 사용할 수 있음.
- 고가용성: 장애 발생 시에도 시스템의 일부가 계속 작동하여 높은 가용성을 유지함.

### 4. 단점
- 복잡성: 시스템 설계 및 관리가 복잡하며, 네트워크 통신 지연 등의 문제를 해결해야 함.
- 데이터 일관성: 여러 컴퓨터 간의 데이터 일관성을 유지하는 것이 어려움.
- 보안 문제: 네트워크를 통해 연결된 시스템이므로 보안 위협에 노출될 가능성이 있음.

### 5. 예시
- 클러스터 컴퓨팅: 여러 대의 컴퓨터를 하나의 고성능 시스템처럼 사용하는 방식. 주로
  과학적 계산, 시뮬레이션 등에 사용됨.
- 그리드 컴퓨팅: 지리적으로 분산된 컴퓨터 자원을 연결하여 대규모 연산 작업을 수행하는
  방식.
- 클라우드 컴퓨팅: 인터넷을 통해 분산된 컴퓨터 자원을 제공하여 사용자가 필요에 따라
  자원을 사용할 수 있게 함.

> **출제 경향**   기업은행에서 분산처리시스템에 대한 설명에 대한 문제가 출제됩니다. 특징과
장단점을 숙지해야합니다.

## 클라우딩 컴퓨팅

> 중요도: **상** (★★★)


![클라우드 서비스 모델](https://raw.githubusercontent.com/FLYLIKEB/finance-public-corp-prep-materials/main/assets/downloaded-visual-aids/cloud-computing.svg)
> 그림: 클라우드 컴퓨팅 개념 기반으로 클라우드 서비스 모델 개념을 시각적으로 확인한다.
> 출처: https://commons.wikimedia.org/wiki/File:Cloud_computing.svg

### 1. 정의

인터넷을 통해 IT 자원(서버, 스토리지, 데이터베이스, 네트워크, 소프트웨어 등)을 필요에 따라
제공하고, 사용자가 이러한 자원을 즉시 사용할 수 있도록 하는 서비스 모델

### 2. 특징
- 온디맨드 자원 제공: 사용자가 필요할 때 필요한 자원을 즉시 할당받아 사용할 수 있음.
- 확장성: 필요에 따라 자원을 쉽게 확장하거나 축소할 수 있음.
- 유연한 비용 구조: 사용한 만큼만 비용을 지불하는 모델로, 초기 투자 비용을 줄일 수 있음.
- 관리 및 유지보수: 클라우드 서비스 제공자가 인프라를 관리하고 유지보수함으로써,
  사용자는 핵심 비즈니스에 집중할 수 있음.
- 전 세계 접근성: 인터넷이 연결된 곳이라면 어디서나 접근 가능함.

### 3. 서비스 모델

```text
SaaS  ┌────────────────────┐  사용자는 완성된 소프트웨어 사용
PaaS  ├────────────────────┤  개발자는 플랫폼 위에 앱 배포
IaaS  ├────────────────────┤  서버·스토리지·네트워크 임대
      └────────────────────┘
```

| 구분 | 제공 범위 | 사용자가 주로 관리 | 예시 |
| --- | --- | --- | --- |
| IaaS | 인프라 | OS, 미들웨어, 애플리케이션 | EC2, Compute Engine |
| PaaS | 개발·배포 플랫폼 | 애플리케이션 코드 | Heroku, App Engine |
| SaaS | 완성 소프트웨어 | 설정과 데이터 사용 | Google Workspace, Salesforce |

#### IaaS (Infrastructure as a Service)
- **정의:** 가상화된 컴퓨팅 자원(서버, 스토리지, 네트워크 등)을 제공하는 서비스.
- **예시:** Amazon Web Services(AWS) EC2, Microsoft Azure, Google Cloud Platform(GCP)
  Compute Engine.
- **사용 사례:** 데이터 센터 확장, 백업 및 복구, 개발 및 테스트 환경

#### PaaS (Platform as a Service)
- **정의:** 애플리케이션 개발 및 배포를 위한 플랫폼을 제공하는 서비스.
- **예시:** Google App Engine, Microsoft Azure App Service, Heroku.
- **사용 사례:** 애플리케이션 개발, 웹 애플리케이션 호스팅, 데이터베이스 관리.

#### SaaS (Software as a Service)
- **정의:** 소프트웨어 애플리케이션을 서비스로 제공하여, 사용자가 인터넷을 통해 접근하고
  사용할 수 있는 모델.
- **예시:** Google Workspace, Microsoft Office 365, Salesforce.
- **사용 사례:** 이메일 서비스, 고객 관계 관리(CRM), 협업 도구.

### 4. 배포모델

#### 퍼블릭 클라우드
- **정의:** 여러 사용자가 공유하는 클라우드 환경으로, 클라우드 서비스 제공자가 소유하고
  운영함.
- **예시:** Amazon Web Services, Microsoft Azure, Google Cloud Platform.
- **장점:** 비용 효율성, 확장성, 관리 용이성.

#### 프라이빗 클라우드
- **정의:** 특정 조직을 위해 전용으로 제공되는 클라우드 환경으로, 조직 내부에서 관리하거나
  서드파티가 운영함.
- **예시:** 기업 내부 데이터 센터, 전용 클라우드 인프라.
- **장점:** 보안성, 커스터마이징, 데이터 통제.

#### 하이브리드 클라우드
- **정의:** 퍼블릭 클라우드와 프라이빗 클라우드를 결합하여 사용하는 모델.
- **예시:** 데이터가 민감한 부분은 프라이빗 클라우드에, 일반적인 워크로드는 퍼블릭
  클라우드에 배포.
- **장점:** 유연성, 비용 효율성, 데이터 보안 및 통제.

#### 클라우드 배포모델 비교표

| 구분 | 소유·운영 | 장점 | 적합한 경우 |
| --- | --- | --- | --- |
| 퍼블릭 | 클라우드 사업자 | 비용 효율, 확장성 | 일반 서비스, 빠른 확장 |
| 프라이빗 | 특정 조직 전용 | 보안, 통제, 맞춤화 | 민감 데이터, 내부 시스템 |
| 하이브리드 | 퍼블릭+프라이빗 혼합 | 유연성, 비용·보안 균형 | 민감 영역과 일반 워크로드 분리 |

> **출제 경향**   정~말 많이 나오는 단골문제인 만큼 확실히 공부하고 무조건 맞혀야하는 문제입니다.
서비스모델(IaaS, SaaS, PaaS) 특징 뿐만 아니라 예시도 확실히 암기해야하고,. 배포모델(퍼블릭/
프라이빗/하이브리드)도 정말 많이 나오니 꼭 알아둬야합니다.

## 약어 풀이

- DCL: Data Control Language, 데이터 제어어
- DDL: Data Definition Language, 데이터 정의어
- DELETE: SQL 삭제 명령
- DML: Data Manipulation Language, 데이터 조작어
- INSERT: SQL 삽입 명령
- IT: Information Technology, 정보기술
- OS: Operating System, 운영체제
- SELECT: SQL 조회 명령
- SQL: Structured Query Language, 구조화 질의어
- UPDATE: SQL 수정 명령

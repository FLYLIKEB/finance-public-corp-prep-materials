## 복습 포인트 (시험 대비형 체크리스트)

- [ ] 계층별 역할을 외운다: 물리→데이터링크→네트워크→전송→세션→표현→응용
- [ ] 계층별 대표 프로토콜을 암기한다(예: IP는 네트워크, TCP/UDP는 전송, Ethernet은 데이터링크, HTTP는 응용)
- [ ] TCP와 UDP의 차이(연결성, 신뢰성, 순서보장, 흐름/혼잡 제어)를 사례로 설명할 수 있다
- [ ] TLS 핸드셰이크의 기본 흐름(클라이언트 헬로 → 서버 헬로/인증서 → 키 교환 → 암호화된 세션)과 목적을 설명한다
- [ ] DNS 동작(호스트이름→IP 변환), 레코드 종류(A, CNAME 등), 재귀/비재귀 조회 개념을 이해한다
- [ ] 서브넷 마스크와 CIDR 표기(/n)의 의미, 네트워크/브로드캐스트/사용가능 호스트 범위 계산 연습을 한다
- [ ] 라우팅 기초(정적 vs 동적, 라우팅 테이블의 목적)를 실제 예제로 설명할 수 있다

## OSI 7계층 요약 (시험 핵심 정리)

| 계층 번호 | 이름 | 주요 역할 | 예시 프로토콜/장치 |
|---:|---|---|---|
| 7 | 응용(Application) | 사용자와 가장 가까운 인터페이스, 애플리케이션 서비스 제공 | HTTP, FTP, SMTP |
| 6 | 표현(Presentation) | 데이터 표현, 인코딩/암호화/압축 | SSL/TLS(일부 개념) |
| 5 | 세션(Session) | 통신 세션 관리, 대화 제어 | 세션 관리 프로토콜/플랫폼 API |
| 4 | 전송(Transport) | 종단간 신뢰성, 흐름/혼잡 제어, 포트 번호 | TCP, UDP |
| 3 | 네트워크(Network) | 논리적 주소 지정, 경로 선택 | IP, ICMP, 라우터 |
| 2 | 데이터링크(Data Link) | 프레임화, 물리주소(MAC), 오류검출/재전송 | Ethernet, 스위치 |
| 1 | 물리(Physical) | 비트 전송, 전기/광 신호 | 케이블, 리피터 |

시험 포인트: "어떤 기능(예: 흐름제어, 라우팅, 포트번호)이 어느 계층에 속하는가" 문제를 자주 출제함.

## TCP vs UDP: 핵심 비교 및 시험 유형 문제

- TCP
  - 연결형(3-way handshake), 신뢰성(재전송·ACK), 순서 보장, 흐름·혼잡 제어
  - 헤더 주요 필드: 시퀀스 번호, ACK 번호, 윈도우 크기, 플래그(SYN, ACK, FIN)
  - 용도: 파일 전송(FTP), 웹(HTTP/1.1), 이메일 전송 등 신뢰성이 필요한 서비스
- UDP
  - 비연결형, 헤더가 작음(오버헤드 낮음), 순서/신뢰성 보장 없음
  - 용도: 실시간 스트리밍, DNS 쿼리, VoIP 등 지연이 더 중요한 경우

시험 문제 예시:
- "TCP의 3-way handshake 과정과 각 단계에서 사용되는 플래그를 쓰시오."
- "UDP가 적합한 서비스 사례를 두 가지 서술하고 이유를 설명하시오."

## HTTP · DNS · TLS 핵심 요약 (핵심 키워드 위주)

- HTTP
  - 무상태(stateless), 요청-응답 모델
  - 주요 메서드: GET, POST, PUT, DELETE, HEAD
  - 상태 코드 분류: 1xx(정보), 2xx(성공), 3xx(리다이렉트), 4xx(클라이언트 오류), 5xx(서버 오류)
  - 시험 포인트: 요청/응답 헤더의 역할(Cookie, Content-Type, Host 등)
- DNS
  - 도메인 이름을 IP로 변환하는 시스템
  - 레코드 예: A(IPv4), AAAA(IPv6), CNAME(별칭), MX(메일)
  - 질의 방식: 재귀적 조회 vs 반복적 조회의 차이(클라이언트/리졸버/권한서버 역할)
- TLS
  - 목적: 전송 계층에서의 기밀성·무결성·서버(및 옵션으로 클라이언트) 인증
  - 기본 흐름(요약): ClientHello → ServerHello(+Certificate) → 키 교환 → Finished → 암호화된 응용데이터
  - 시험 포인트: 공개키/대칭키의 역할 분담(핸드셰이크에서 인증·키 교환, 이후 데이터 암호화는 대칭키)

## 라우팅과 서브넷 (계산 연습 포함)

- CIDR 표기: 예) 192.168.1.0/24 → 프리픽스 길이 24, 호스트 비트 8
- 서브넷 마스크: /n → 32비트 중 왼쪽 n비트가 네트워크
- 서브넷 계산 예제(시험에서 자주 출제되는 유형)
  - 문제: IP 192.168.1.10/28의 네트워크 주소, 브로드캐스트 주소, 사용 가능한 호스트 범위를 구하시오.
  - 풀이 요점: /28 => 호스트 비트 4 → 블록 크기 16
    - 네트워크 주소: 192.168.1.0
    - 브로드캐스트: 192.168.1.15
    - 사용 가능 호스트: 192.168.1.1 ~ 192.168.1.14 (총 14개)
- 라우팅 기본
  - 정적 라우팅: 관리자가 직접 경로 설정(단순·예측 가능)
  - 동적 라우팅: 라우팅 프로토콜(OSPF, BGP 등)을 통해 경로 학습(규모 확장성)
  - 시험 포인트: 라우팅 테이블의 목적과 목적지/넥스트홉(next-hop) 개념 설명

## 연습문제 (간단)

1) OSI 7계층에서 "포트 번호"가 속하는 계층은?
   - 정답: 전송 계층(Transport)

2) TCP 연결 해제를 위한 플래그 순서(일반적 흐름)를 쓰시오.
   - 정답(요약): FIN/ACK 흐름(양쪽에서 FIN 교환 후 각자 ACK)

3) /26 서브넷에서 호스트당 IP 개수는?
   - 풀이: /26 → 호스트 비트 6 → 2^6 = 64 주소 → 사용 가능 호스트 62

## 시험 대비 팁

- 계층별로 "무엇을 하는가"를 한 문장으로 요약해두면 문제 풀이 속도가 빨라진다.
- 서브넷 계산은 손으로 여러 번 풀어 실수를 줄인다(다양한 /n으로 연습).
- TCP의 플래그와 헤더 필드(시퀀스/ACK/윈도우)는 작은 도표로 정리해서 암기.
- HTTP 요청/응답의 흐름을 curl 예제나 브라우저 개발자 도구로 직접 확인해보면 이해가 빠르다.

## 약어 풀이

- DNS: Domain Name System, 도메인 이름 시스템
- HTTP: HyperText Transfer Protocol, 하이퍼텍스트 전송 프로토콜
- IP: Internet Protocol, 인터넷 프로토콜
- OSI: Open Systems Interconnection, 개방형 시스템 상호연결
- TCP: Transmission Control Protocol, 전송 제어 프로토콜
- TLS: Transport Layer Security, 전송 계층 보안
- UDP: User Datagram Protocol, 사용자 데이터그램 프로토콜

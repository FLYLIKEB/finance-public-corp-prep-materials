# 17-5. 마이크로서비스

## 핵심 개념

- MSA(마이크로서비스 아키텍처)는 시스템을 비즈니스 역량 단위로 작은 서비스들로 분리하여 각 서비스가 독립적으로 개발·배포·확장되도록 설계하는 아키텍처다. 서비스는 잘 정의된 API로 통신한다.
- 모놀리식 아키텍처는 배포·트랜잭션 관리가 단순하고 개발 초기 비용이 적지만, 규모가 커지면 변경 영향 범위가 넓어지고 배포 위험과 팀 간 충돌이 증가한다.
- 통신 방식: 동기(HTTP/REST, gRPC)와 비동기(메시지 큐, 이벤트)가 병행 사용된다. 비동기는 결합도를 낮추고 확장성을 높이지만 일관성 모델이 약해진다.
- 데이터 관리: 서비스별 DB(Database per Service)가 권장되며, 분산 트랜잭션 대신 saga 패턴, 이벤트 소싱, 최종적 일관성(eventual consistency)을 설계해 일관성을 확보한다.
- API Gateway는 인증·인가, 라우팅, rate limiting, 로깅, 프로토콜 변환(예: HTTP ↔ gRPC) 등을 중앙에서 처리하는 진입점이다.
- Service mesh는 애플리케이션 코드 변경 없이 서비스 간 통신의 mTLS, 재시도(retry), 서킷 브레이커, 로드밸런싱, 분산 추적/메트릭 수집 같은 기능을 제공하여 observability와 보안·복원력을 향상시킨다.
- 배포·운영: 컨테이너화(Docker), 오케스트레이션(Kubernetes), CI/CD 파이프라인, 블루/그린·카나리 배포가 일반적이다.
- 관측성: 로깅, 지표(metric), 분산 트레이싱이 필수이며, 장애 원인 파악과 SLA 충족을 위해 자동화된 알람과 대시보드가 필요하다.

## 시험 답안용 핵심 개념

- 정의 한 문장: MSA는 비즈니스 기능별로 작게 나누어 독립 배포·확장이 가능한 서비스 단위의 아키텍처이다.
- 핵심 장점: 빠른 배포 주기, 독립 확장, 팀 단위 자율성.
- 핵심 단점: 분산 트랜잭션·데이터 일관성 관리가 어려움, 운영·관측 복잡도 증가.
- 대표 패턴/구성요소: API Gateway, 서비스 레지스트리, 메시지 큐, saga, service mesh, 분산 트레이싱.

## 비교 포인트(짧게)

- 배포: 모놀리는 단일 배포, MSA는 빈번하고 부분적 배포 가능.
- 확장성: 모놀리는 수직 확장, MSA는 서비스별 수평 확장.
- 일관성: 모놀리는 단일 트랜잭션 가능, MSA는 최종적 일관성 및 보상 트랜잭션 필요.
- 운영비용: 모놀리식은 낮은 운영오버헤드, MSA는 관측성·자동화 비용 증가.
- 장애 격리: MSA가 우수하나 네트워크·상태 관리에서 새로운 실패 모드 발생.

## 실무 / 금융권 관점

- 핵심 원장(ledger)과 주변 서비스(알림, 리포팅 등)를 명확히 분리하라. 핵심 원장은 강한 일관성(동기식 처리) 요구, 주변 서비스는 이벤트 기반 비동기 처리로 설계하라.
- 분산 트랜잭션 대신 saga 패턴과 보상 트랜잭션을 사용하되, 감사(audit) 로그와 트랜잭션 추적을 철저히 기록해 규제 대응력을 확보해야 한다.
- 보안: 서비스 간 통신은 mTLS로 암호화하고, 중앙 인증·인가(예: OAuth 2.0, JWT)와 API Gateway의 정책 적용으로 권한 관리를 강화하라.
- 감사·컴플라이언스: 모든 금융 트랜잭션은 비가역 로그와 타임스탬프, 변경 이력(trace)을 남겨야 하며, 장애 복구 시 로그 기반 재생(replay) 전략을 마련해야 한다.
- 운영 SLA와 인시던트 대응: 장애 격리, 롤백 절차, 서비스 의존성 맵 및 카오스 엔지니어링으로 복원력(Resilience)을 검증하라.
- 성능·비용: 마이크로서비스는 세밀한 리소스 할당으로 비용 최적화가 가능하나, 네트워크 비용 및 운영 자동화 비용을 고려해야 한다.

## 면접 답변 팁 (짧고 밀도 있게)

- 시작은 정의 한 문장으로: "MSA는..."으로 명확히 요약하라.
- 핵심 장단점을 빠르게 제시: 개발·배포 속도와 운영 복잡도의 트레이드오프를 말하라.
- 구체적 패턴 언급: API Gateway, service mesh, saga, 이벤트 큐 등 최소 2~3개를 예로 들라.
- 금융권이면 바로 규제·감사·일관성 대책 한 줄로 연결: "핵심 원장은 강한 일관성, 주변 서비스는 이벤트 기반으로 설계합니다." 등.
- 실무 경험이 있다면 한 가지 사례(문제 → 선택한 패턴 → 결과)를 30~60초 안에 요약하라.
- 마무리는 모니터링·자동화·보안으로: "관측성과 자동화가 MSA 성공의 핵심입니다." 라고 정리하라.

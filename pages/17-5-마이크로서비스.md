# 17-5. 마이크로서비스

## 핵심 개념

- MSA는 서비스를 업무 능력 단위로 작게 나누고 각 서비스가 독립적으로 배포·확장되도록 하는 아키텍처다.
- 모놀리식은 배포와 트랜잭션이 단순하지만 규모가 커지면 변경 영향과 배포 위험이 커진다.
- API Gateway는 인증, 라우팅, rate limit, 로깅, protocol translation을 담당하는 진입점이다.
- Service mesh는 서비스 간 통신의 mTLS, retry, circuit breaker, observability를 애플리케이션 코드 밖에서 제공한다.

| 비교 | 모놀리식 | MSA |
| --- | --- | --- |
| 배포 | 전체 배포 | 서비스별 배포 |
| 데이터 | 단일 DB가 쉬움 | 서비스별 DB와 일관성 설계 필요 |
| 장애 | 내부 전파 가능 | 격리 가능하지만 네트워크 장애 증가 |
| 운영 | 단순 | 관측성·자동화 필요 |

## 금융권 답안 포인트

MSA는 빠른 변경과 독립 확장에 유리하지만 분산 트랜잭션, 장애 추적, 인증 전파, 데이터 정합성이 어려워진다. 금융권에서는 핵심 원장과 주변 서비스를 구분하고, 장애 격리·감사 로그·보안 정책을 설계해야 한다.

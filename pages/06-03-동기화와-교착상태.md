# 06-03. 동기화와 교착상태

> 학습 목적: 동기화 필요성과 교착상태 해결 방법을 연결한다.
> 관련 기출: [05-9-운영체제-기출-모음](05-09-운영체제-기출-모음.md)
> 연결 핵심정리: [04-3-소프트웨어공학-운영체제-컴퓨터구조](04-03-소프트웨어공학-운영체제-컴퓨터구조.md)

## 핵심 개념

- 임계구역(critical section)은 동시에 접근하면 안 되는 공유 자원에 접근하는 코드 영역이다. 임계구역의 목적은 데이터 일관성 유지와 경쟁 상태(race condition) 방지이다.
- 교착상태(deadlock)는 프로세스/스레드들이 서로 상대가 가진 자원을 기다리며 영원히 진행하지 못하는 상태다. 교착상태가 발생하려면 다음 네 가지 조건이 모두 만족되어야 한다: 상호배제(Mutual Exclusion), 점유-대기(Hold and Wait), 비선점(No Preemption), 순환대기(Circular Wait).
- 해결 전략은 크게 예방(prevention), 회피(avoidance), 탐지 및 복구(detection & recovery), 무시(ostrich)를 포함한다. 실무에서는 피해 가능한 경우 예방/회피, 불가피한 경우 탐지+복구 또는 설계 변경을 선호한다.

### 서술형 확장 개념

- 뮤텍스(Mutex)
  - 목적: 임계구역을 한 번에 하나의 스레드만 실행하게 한다.
  - 주의점: 소유한 스레드가 반드시 해제해야 하며, 예외(예: 스레드가 죽음)가 발생하면 교착이나 자원 고착(resource leak)을 유발할 수 있다.

- 세마포어(Semaphore)
  - 정수 카운터로 자원 개수 기반 동기화를 구현한다. 카운터가 0이면 대기해야 하고, 0보다 크면 진입 가능하다.
  - P(wait) 연산은 카운터를 감소시키고 필요 시 블록, V(signal) 연산은 카운터를 증가시켜 대기 중인 프로세스를 깨운다.
  - 종류: 바이너리(semaphore=0/1, 뮤텍스와 유사)와 카운팅 세마포어(여러 동시 접근 허용).
  - 잘못된 사용(예: V와 P의 짝이 맞지 않음)은 교착뿐 아니라 starvation(기아)도 발생시킨다.

- 모니터(Monitor)
  - 언어 수준의 고수준 동기화 추상화로, 공유 데이터와 그 데이터에 접근하는 연산, 조건변수를 하나로 묶는다.
  - 조건변수(condition variable)를 통해 프로세스는 특정 상태(예: 버퍼 비어 있음)를 기다리며, 깨어났을 때는 항상 상태를 재검사(while 루프)해야 한다.

- Banker's Algorithm (교착 회피)
  - 각 프로세스의 최대 요구량(Max)을 알고 있다고 가정하고, 자원을 할당한 뒤 시스템이 safe state인지 검사한다.
  - safe state란 모든 프로세스가 어떤 순서로든 완료될 수 있어 자원 해제가 진행되어 최종적으로 모든 프로세스가 종료될 수 있는 상태를 말한다.
  - unsafe state는 즉시 교착상태를 의미하지 않지만, 이후의 어떤 할당으로 교착에 이를 수 있으므로 보수적으로 할당을 거부한다.

| 개념 | 목적 | 주의점 |
| --- | --- | --- |
| Mutex | 임계구역 1개 소유권 보호 | 소유한 스레드가 해제해야 함 |
| Semaphore | 자원 개수 기반 동기화 | 잘못 쓰면 deadlock 또는 starvation 발생 |
| Monitor | 고수준 상호배제와 조건 대기 | 언어/런타임 지원 필요 |
| Banker | 교착상태 회피 | 최대 요구량을 미리 알아야 함 |

## 쉽게 이해하기 (비유와 직관)

- 동기화는 여러 사람이 같은 문서를 고칠 때 '편집 권한'을 주고받는 규칙과 같다. 규칙(잠금)이 없으면 마지막 저장이 앞선 수정을 덮어쓴다(데이터 손실/경쟁 상태).
- 교착상태는 서로가 가진 키를 놓지 않은 채 상대 키를 기다리는 상황이다. A는 프린터 키를 잡고 스캐너 키를 기다리고, B는 스캐너 키를 잡고 프린터 키를 기다리는 식으로 계속 기다리게 된다.
- 문제 해결 관점: 조건 하나라도 제거하면 교착은 발생하지 않는다. 설계에서 어떤 조건을 제거할지(예: 점유-대기 제거 또는 순환대기 파괴) 결정하는 것이 핵심이다.

## 실무 적용 팁

- 고수준 동기화 프리미티브(예: language-provided mutex, condition variable, concurrent collections)를 우선 사용하라. 직접 락 구현은 버그를 낳기 쉽다.
- 락 그레인(Granularity): 큰 락(코드 전체를 잠그는 것)은 단순하지만 성능 저하를 초래한다. 가능한 한 락 범위를 최소화하되, 복잡성 때문에 교착 위험이 커지면 설계를 단순히 하는 편이 낫다.
- 일관된 락 순서(Lock Ordering): 다중 락을 사용할 때 항상 같은 순서로 획득하면 순환대기 조건을 예방할 수 있다.
- I/O를 수행하는 동안 락을 보유하지 마라. 장시간 락 보유는 다른 스레드의 지연과 시스템 병목을 초래한다.
- 타임아웃/try-lock 사용: 무한 대기를 피하기 위해 일정 시간 후 실패를 반환하고 재시도하거나 대체 경로를 마련한다.
- 조건변수 사용 시 항상 while 루프로 재검사하라(스풀리어스 웨이크up 방지).
- 불변 객체(immutable data)와 원자적(atomic) 연산을 활용하면 락을 줄일 수 있다.

## 탐지와 복구(알고리즘 중심)

- 탐지 방법
  - 자원 할당 그래프(Resource Allocation Graph): 자원과 프로세스를 노드로 해서 할당/요청 간선을 그려 사이클을 찾는다. 단일 인스턴스 자원의 경우 사이클이 교착을 의미한다.
  - 대기-포(Wait-for) 그래프: 프로세스들만으로 구성되며, 사이클이면 교착상태 존재.
  - 주기적 검사: 운영체제가 주기적으로 그래프를 검사하여 사이클을 탐지.

- 복구 방법
  - 프로세스 종료(비수용적): 교착에 관련된 프로세스 중 일부를 종료하여 자원 회수.
  - 자원 선점(Preemption): 일부 자원을 강제로 빼앗아 다른 프로세스에 할당. 이때 상태 복구(rollback)가 필요할 수 있다.
  - 우선순위 기반 정책 또는 비용 기반 선택: 어떤 프로세스를 죽일지 결정할 때 비용(작업 재시작 비용, 중요도 등)을 고려한다.

## 자주 묻는 실수와 주의 포인트

- 조건변수를 사용할 때 if 대신 while을 써야 한다(재검사 필요).
- 뮤텍스를 해제하지 못하면 deadlock나 자원 고착이 발생한다. 예외 발생 경로에서도 해제를 보장해야 한다(try/finally 등).
- 세마포어의 P/V 호출 순서가 잘못되면 카운터 불일치로 논리 오류가 생긴다.
- Banker's Algorithm은 이론적으로 유용하지만 실제 시스템에서는 최대 요구량을 미리 알기 어렵고 오버헤드가 크다.

## 간단한 코드 예시(의사코드)

- 뮤텍스 사용 패턴

```pseudo
mutex.lock()
try:
    // 임계구역: 공유 데이터 접근
    critical_section()
finally:
    mutex.unlock()
```

- 생산자-소비자 (세마포어와 뮤텍스)

```pseudo
semaphore empty = N    // 초기 빈 슬롯 수
semaphore full = 0     // 초기 채워진 슬롯 수
mutex m                // 버퍼 접근 보호

producer():
    item = produce()
    empty.P()          // 빈 슬롯 하나 빼기
    m.lock()
    buffer.add(item)
    m.unlock()
    full.V()           // 채워진 슬롯 하나 추가

consumer():
    full.P()           // 채워진 슬롯 하나 빼기
    m.lock()
    item = buffer.remove()
    m.unlock()
    empty.V()          // 빈 슬롯 하나 추가
    consume(item)
```

- 조건변수 사용 예 (모니터 스타일)

```pseudo
monitor BoundedBuffer:
    buffer
    condition notEmpty, notFull

    put(item):
        while buffer.isFull():
            wait(notFull)
        buffer.add(item)
        signal(notEmpty)

    get():
        while buffer.isEmpty():
            wait(notEmpty)
        item = buffer.remove()
        signal(notFull)
        return item
```

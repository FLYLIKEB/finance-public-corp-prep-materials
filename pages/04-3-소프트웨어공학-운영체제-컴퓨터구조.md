## 프로세스 스케줄링

> 중요도: **상** (★★★)

### 1. 개념

: 운영체제가 CPU 시간을 여러 프로세스에 효율적으로 분배하는 메커니즘

### 2. 프로세스 스케줄링 유형

선점형 스케줄링 (Preemptive Scheduling)

정의:

선점형 스케줄링은 실행 중인 프로세스가 특정 조건을 만족할 때, 운영체제가 강제로 CPU 를 다른
프로세스에게 할당하는 방식임. 이를 통해 CPU 시간을 보다 공정하고 효율적으로 분배할 수 있음.

EX.
- Round Robin (RR): 각 프로세스에 일정 시간(Time Quantum)을 할당하고 순환하며 CPU 를
  할당함.
- Shortest Remaining Time First (SRT): 남은 실행 시간이 가장 짧은 프로세스에게 CPU 를
  할당함.

장점:
- 응답 시간 최소화: 중요한 작업이 빠르게 처리될 수 있음.
- 공정성: 모든 프로세스가 CPU 시간을 공정하게 분배받을 수 있음.

단점:
- 오버헤드 증가: 잦은 컨텍스트 스위칭으로 인해 시스템 오버헤드가 증가함.
- 복잡성: 스케줄링 알고리즘의 구현이 복잡함.

비선점형 스케줄링 (Non-Preemptive Scheduling)

정의:

비선점형 스케줄링은 프로세스가 한 번 CPU 를 할당받으면, 자발적으로 CPU 를 반납하거나 종료될
때까지 CPU 를 계속 사용하는 방식임. 운영체제가 실행 중인 프로세스를 강제로 중단하지 않음.

Ex.
- First-Come, First-Served (FCFS): 먼저 도착한 프로세스부터 순서대로 CPU 를 할당함.
- Shortest Job First (SJF): 실행 시간이 가장 짧은 프로세스에게 CPU 를 할당함. 프로세스가
  자발적으로 종료될 때까지 CPU 를 사용함.
- HRN (Highest Response Ratio Next): 작업의 우선순위를 결정할 때, 대기 시간과 실행
  시간을 모두 고려하여 응답 비율을 계산하는 스케줄링 방식

장점:
- 오버헤드 최소화: 컨텍스트 스위칭이 적어 시스템 오버헤드가 작음.
- 단순성: 스케줄링 알고리즘이 단순하여 구현이 쉬움.

단점:
- 응답 시간 지연: 긴 실행 시간을 가지는 프로세스가 CPU 를 독점할 경우, 다른 프로세스의
  응답 시간이 길어질 수 있음.
- 비공정성: 높은 우선순위의 프로세스가 대기 상태가 되는 경우가 발생할 수 있음.

**출제경향** : 선점형/비선점형 스케줄링의 특징을 물어보는것보다는 SJF 대기시간, 반환시간, HRN
계산 문제가 압도적으로 많이 출제됩니다.

## 운영체제

> 중요도: **중** (★★)

### 1. 저장위치
RAM (Random Access Memory)
- 정의: 컴퓨터의 주기억 장치로, 데이터와 프로그램 명령어를 일시적으로 저장하고, 현재
  실행 중인 프로세스들이 필요로 하는 데이터를 빠르게 접근할 수 있게 하는 메모리
- 주요 특징:
  휘발성: 전원이 꺼지면 저장된 모든 데이터가 사라짐.
  고속 접근: 데이터를 매우 빠르게 읽고 쓸 수 있음.
  일시적 저장: 현재 사용 중인 데이터와 프로그램을 일시적으로 저장.

ROM (Read-Only Memory)
- 정의: 읽기 전용 메모리로, 컴퓨터 부팅 과정에서 필요한 펌웨어나 시스템 소프트웨어를
  저장하는 비휘발성 메모리임
- 주요 특징:
  비휘발성: 전원이 꺼져도 데이터가 유지됨.
  읽기 전용: 일반적으로 데이터를 읽기만 할 수 있고, 쓰기는 제한적임.
  영구적 저장: 시스템 부팅에 필요한 데이터를 영구적으로 저장.

**출제경향** : 자주 나오지는 않지만 특히 공기업 필기에서 출제되는 경향이 있습니다. RAM 과 ROM
에 대한 특징을 물어봅니다.

## GPU

> 중요도: **중** (★★)

### 1. GPU 개념
 GPU(Graphics Processing Unit)는 그래픽 처리를 전문으로 하는 프로세서로, 이미지와 비디오
렌더링을 신속하게 처리하기 위해 설계됨. GPU 는 병렬 처리 능력이 뛰어나며, 복잡한 계산을 동시에
수행할 수 있는 능력을 갖추고 있음.
### 2. 특징
- 병렬 처리: GPU 는 다수의 코어를 이용해 데이터를 병렬로 처리함으로써, 그래픽과 계산
  작업을 매우 빠르게 수행할 수 있음.
- 높은 처리 성능: 수천 개의 작은 코어를 통해 복잡한 그래픽 연산을 효율적으로 처리할 수
  있음.
- 전용 메모리: GPU 는 자체 메모리(GDDR)를 가지고 있어, 데이터 전송 속도가 매우 빠름.
- 다양한 활용: 게임 그래픽 렌더링, 비디오 편집, 인공지능 및 딥러닝 모델 훈련 등 다양한
  분야에서 사용됨.

### 3. 주요 용도
- 그래픽 및 비디오 렌더링
- 과학적 계산 및 시뮬레이션
- 인공지능 및 머신러닝

### 4. GPU vs CPU:

·    CPU(Central Processing Unit):

o    설계 목적: 다양한 작업을 순차적으로 처리하는 범용 프로세서.

o    코어 수: 적은 수의 강력한 코어(보통 4~16 개).

o    작업 특성: 순차 처리에 최적화.

·    GPU:

o    설계 목적: 그래픽 및 병렬 연산 작업을 전문적으로 처리.

o    코어 수: 수천 개의 작은 코어.

o    작업 특성: 병렬 처리에 최적화.

**출제경향** : GPU 자체 특징 또는 CPU 와 비교하는 문제가 종종 출제됩니다.

## 병행기법(Concurrency Control)

> 중요도: **중** (★★)

### 1. 개념

: 데이터베이스 시스템에서 여러 트랜잭션이 동시에 실행될 때 데이터의 일관성과 무결성을 유지하기
위해 사용되는 기술. 트랜잭션이 동시에 수행되더라도 데이터의 충돌이나 불일치를 방지하는 데 목적

### 2. 종류
- 로킹(Locking) 기법:
  2 단계 잠금(2-Phase Locking, 2PL): 트랜잭션이 잠금 설정과 해제 단계를 분리하여
  순차적으로 수행함으로써 직렬 가능성을 보장함.
  (2PL 단계)
- 확장 단계(Growing Phase):
  트랜잭션이 잠금을 설정할 수만 있음.
  잠금을 해제할 수 없음.
  트랜잭션이 필요로 하는 모든 잠금을 설정할 때까지 이 단계가 지속됨.
- 축소 단계(Shrinking Phase):
  트랜잭션이 잠금을 해제할 수만 있음.
  새로운 잠금을 설정할 수 없음.
  트랜잭션이 첫 번째 잠금을 해제하는 순간 이 단계로 전환됨.
- 타임스탬프(Time Stamp) 기법:
  각 트랜잭션에 고유한 타임스탬프를 부여하여, 트랜잭션의 순서를 결정함.
  타임스탬프 순서(Time Stamp Ordering): 트랜잭션의 타임스탬프를 기반으로 읽기 및 쓰기
  작업의 순서를 결정함.

**출제경향** : 어려운 개념이지만 종종 나오는 개념. 병행기법 종류와 그 중 2PL 에 대해 출제된 바가
있습니다.

## RISC/CISC

> 중요도: **중** (★★)

### 1. 개념

: RISC(Reduced Instruction Set Computer)와 CISC(Complex Instruction Set Computer)는 컴퓨터
프로세서 설계의 두 가지 주요 접근 방식

### 2. 특징 비교

 특징            RISC                                 CISC
 명령어 세트        간단하고 적은 수의 명령어                       복잡하고 많은 수의 명령어
 명령어 길이        고정길이                                 가변 길이
 연산 중심         레지스터 중심                              메모리 중심
 명령어 실행        대부분의 명령어가 하나의 클럭 사이클 내에              많은 명령어가 여러 클럭 사이클에 걸쳐
  실행                                   실행
 파이프라이닝        효율적                                  상대적으로 비효율적
 장점            높은 실행 속도, 효율적인 파이프라이닝                코드 길이가 짧고 유연성이 높음
 단점            복잡한 작업을 위해 많은 명령어 필요                 명령어 디코딩과 실행이 복잡,
  실행속도가 느릴 수 있음

**출제경향** : 생소한 개념이지만 금융공기업에서 정말 자주 출제되는 문제입니다. 생소하더라도 각
개념별 특징을 꼭 숙지하여 남들보다 1 문제 더 맞히도록 해보세요!

## 단편화

> 중요도: **하** (★)

### 1. 내부단편화
- 정의: 할당된 메모리 블록 내에 사용되지 않고 남아있는 공간. 메모리 블록이 고정 크기로
  할당될 때, 요청된 메모리 크기보다 큰 블록이 할당되면서 사용되지 않는 공간이 생기는
  현상
- 예시: 한 프로그램이 60KB 의 메모리를 요청했을 때, 시스템이 고정된 64KB 블록을
  할당하면, 4KB 의 공간이 낭비됨. 이 4KB 가 내부 단편화임
- -   특징:
  고정된 크기의 메모리 할당 방식에서 주로 발생
  할당된 블록 내에서 낭비되는 공간

### 2. 외부단편화
- 정의: 메모리 블록들이 할당과 해제를 반복하면서, 사용 가능한 메모리가 여러 조각으로
  나뉘어져 필요한 크기의 연속된 메모리 블록을 할당할 수 없는 상태
- 예시: 여러 프로그램이 메모리를 요청하고 해제하면서, 메모리의 빈 공간이 여기저기 흩어져
  있음. 예를 들어, 100KB 의 연속된 메모리 공간이 필요하지만, 20KB, 30KB, 50KB 의 조각난
  빈 공간만 존재하는 상황.
- 특징:
  메모리 할당과 해제 과정에서 발생
  전체 빈 공간의 합은 충분하지만, 연속된 큰 메모리 블록을 할당할 수 없는 문제

(예시문제)

### 1. 외부 단편화의 주요 특징은 무엇인가?
- ① 할당된 블록 내에서 낭비되는 공간
- ② 연속된 큰 메모리 블록을 할당할 수 없는 문제
- ③ 고정된 크기의 메모리 할당 방식에서 발생
- ④ 사용되지 않고 남아있는 공간

정**답:** ② 연속된 큰 메모리 블록을 할당할 수 없는 문제.

**출제경향** : 각 단편화별 특징을 물어보는 문제 출제됩니다. 단편화별 그림을 제시하고 해당
단편화의 특징은? 이라는 문제도 출제될 수 있으니 내부/외부 단편화 이미지를 숙지하는게 좋습니다.

## 페이징 vs 세그먼트

> 중요도: **하** (★)

### 1. 페이징 (Paging)

정의:

페이징은 메모리를 동일한 크기의 블록(페이지)으로 나누어 관리하는 메모리 관리 기법

주요 특징:
- 고정 크기 블록: 페이지와 프레임은 고정된 크기(일반적으로 4KB)를 가짐.
- 단순한 메모리 할당: 모든 페이지가 동일한 크기를 가지므로, 빈 프레임에 페이지를 쉽게
  할당할 수 있음.
- 내부 단편화: 페이지 내의 사용되지 않는 메모리 공간이 생길 수 있음.

장점:
- 단순한 메모리 관리: 고정된 크기의 블록으로 인해 메모리 관리가 간단해짐.
- 빠른 메모리 접근: 페이지 테이블을 통해 빠르게 메모리 접근이 가능함.

단점:
- 내부 단편화: 페이지 크기와 실제 데이터 크기가 맞지 않을 경우, 내부 단편화가 발생함.

예시:
- 페이지 테이블: 각 프로세스는 자신의 페이지 테이블을 가지고 있으며, 이를 통해 논리적
  주소를 물리적 주소로 변환함.

### 2. 세그먼트 (Segmentation)

정의:

세그먼트는 메모리를 가변 크기의 논리적 단위(세그먼트)로 나누어 관리하는 메모리 관리 기법임

주요 특징:
- 가변 크기 블록: 세그먼트는 가변적인 크기를 가짐.
- 논리적 단위: 세그먼트는 논리적으로 관련된 데이터(예: 코드, 데이터, 스택)를 포함함.
- 외부 단편화: 가변 크기의 세그먼트로 인해 외부 단편화가 발생할 수 있음.

장점:
- 논리적 그룹화: 프로그램의 논리적 구조에 따라 메모리를 그룹화할 수 있음.
- 효율적 메모리 사용: 필요한 만큼의 메모리만 할당하여 메모리 사용 효율성을 높임.

단점:
- 외부 단편화: 가변 크기의 블록으로 인해 외부 단편화가 발생할 수 있음.
- 복잡한 메모리 관리: 가변 크기의 세그먼트를 관리하기 위해 더 복잡한 메모리 관리가 필요함.

예시:
- 세그먼트 테이블: 각 프로세스는 자신의 세그먼트 테이블을 가지고 있으며, 이를 통해 논리적
  주소를 물리적 주소로 변환함.

비교

특성                       페이징(Paging)          세그먼트(Segmentation)
블록크기                     고정크기                 가변크기
단편화 종류                   내부단편화                외부단편화
주소변환방식                   페이지 테이블 사용           세그먼트 테이블 사용
용도                       단순한 메모리 관리           논리적 구조를 반영한 메모리
  관리

이와 같이, 페이징과 세그먼트는 각각의 장단점을 가지고 있으며, 현대의 많은 운영체제는 두 가지
방법을 조합한 세그먼트-페이징(Segment-Paging) 기법을 사용하여 메모리를 관리함.

**출제경향** : 내부/외부단편화와 mix 해서 문제가 출제되기도 합니다. 보통은 페이징과 세그먼트의
차이점에 대한 설명을 묻는 문제가 출제. 거의 출제가 되지는 않지만 대학교 교육과정에 있는
개념으로써 나오면 풀수있을정도가 되어야합니다..

## 교착상태(Deadlock)

> 중요도: **하** (★)

### 1. 개념

: 두 개 이상의 프로세스가 서로 상대방의 자원을 기다리면서 무한히 대기하는 상황을 의미.

### 2. 해결방법

  사전에 제거하여 방지

  예측하고 피함                                   사전 지식 필요

  해결                        해결가능            데이터 손상가능

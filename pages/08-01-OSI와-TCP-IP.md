# 08-01. OSI와 TCP-IP

> 학습 목적: OSI 7계층과 TCP/IP 계층을 대응한다.
> 관련 기출: [05-11-네트워크-기출-모음](05-11-네트워크-기출-모음.md)
> 연결 핵심정리: [04-4-네트워크-프로토콜-보안](04-04-네트워크-프로토콜-보안.md)

## 핵심 개념

- OSI 모델: 물리(1), 데이터링크(2), 네트워크(3), 전송(4), 세션(5), 표현(6), 응용(7) 계층으로 구분한다. 각각의 계층은 특정한 기능과 "주소 단위"를 가지고 있다.
- TCP/IP 모델(실무/시험 관점): 네트워크 접근(링크), 인터넷(네트워크), 전송(트랜스포트), 응용으로 구분한다. OSI의 여러 계층이 TCP/IP의 한 계층에 통합되는 경우가 많다.
- 계층별 대표 프로토콜·장비를 암기하라. 시험에서는 계층과 프로토콜/장비를 연결하는 문제가 자주 출제된다.

### 시험 포인트 요약
- 문제 해결형 서술에서는 "어떤 주소(주소 단위)를 사용하는가"를 명확히 적어야 한다(예: MAC 주소/프레임, IP 주소/패킷, 포트/세그먼트 등).
- 구현·동작 설명에서는 데이터가 캡슐화(encapsulation)·역캡슐화(decapsulation) 되는 과정을 계층별로 기술하면 점수를 얻기 쉽다.
- 주요 프로토콜의 핵심 필드(예: IP의 TTL, TCP의 포트·시퀀스·ACK·플래그)는 반드시 언급해야 한다.


### 서술형 확장 개념 (계층별 핵심 설명)

- 데이터링크 계층(OSI 2)
  - 역할: 동일한 물리적 링크 내에서 프레임 전달, 오류 검출/제거(예: CRC), 흐름제어 일부 담당.
  - 주소 단위: MAC 주소 (하드웨어 주소).
  - 대표 기술/장비: Ethernet(프레임 구조), switch(스위칭, MAC 주소 테이블 학습), ARP(주소 해석).
  - 시험 메모: ARP는 IP→MAC 해석 프로토콜로, IP 패킷을 전송하기 전에 목적지 MAC을 알아내어 프레임에 담는다.

- 네트워크 계층(OSI 3)
  - 역할: 다른 네트워크까지 패킷을 전달(라우팅), 경로 선택, 분할·조립 관여(패킷 단편화).
  - 주소 단위: IP 주소.
  - 대표 기술/장비: IPv4/IPv6, router, ICMP(네트워크 오류·진단), NAT(주소 변환), DHCP(주소 할당 보조 역할으로 동작은 응용/네트워크 경계의 서비스 측면).
  - 핵심 필드: IP 헤더의 TTL(Time To Live) — 라우팅 루프 방지용으로 홉마다 1씩 감소. TTL이 0이 되면 패킷 폐기 및 ICMP Time Exceeded 전송.
  - ICMP 주요 타입: Echo Request/Reply(ping), Destination Unreachable, Time Exceeded(트레이서트 관련).

- 전송 계층(OSI 4)
  - 역할: 종단간(end-to-end) 통신, 프로세스 식별(포트), 신뢰성·흐름·혼잡 제어.
  - 주소 단위: 포트 번호(포트), 세그먼트(또는 데이터그램).
  - 대표 프로토콜: TCP(연결형, 신뢰성 보장, 흐름·혼잡 제어), UDP(비연결형, 낮은 오버헤드, 실시간 트래픽에 유리).
  - TCP 핵심 요소: 소스/목적 포트, 시퀀스 번호, ACK 번호, 제어 플래그(SYN, ACK, FIN, RST), 윈도우 크기.
  - 시험 메모: 3-way handshake(SYN→SYN+ACK→ACK)와 연결 종료 절차(4단계 FIN/ACK 시퀀스)는 자주 출제.

- 응용 계층(OSI 7 / TCP/IP 응용)
  - 역할: 사용자 서비스와 네트워크 서비스(예: HTTP, DNS, SMTP) 제공.
  - 주소 단위: URL·도메인·메시지(프로토콜에 따라 다름).
  - 대표 프로토콜: HTTP(웹), DNS(이름 해석), SMTP(이메일 전송), TLS(보안 계층, 암호화)
  - 시험 포인트: DNS의 동작(조회 과정: 재귀/반복 조회, 레코드 유형 A/AAAA/CNAME 등)과 HTTPS에서 TLS의 역할(암호화·인증)을 구분하여 설명.


| 계층 | 주소/단위 | 장비·프로토콜 예시 |
| --- | --- | --- |
| 데이터링크 | MAC / frame | Ethernet, switch, ARP, CRC |
| 네트워크 | IP / packet | IP, ICMP, router, NAT, DHCP |
| 전송 | Port / segment·datagram | TCP, UDP |
| 응용 | URL·도메인·메시지 | HTTP, DNS, SMTP, TLS |

## 쉽게 이해하기(비유와 점검 포인트)

- 편지 비유: 작성(응용) → 봉투·주소작성(데이터링크/네트워크) → 배송(네트워크/전송) → 수신자 확인(응용).
- 하향식 설명(발신 측): 응용에서 메시지 생성 → 전송층에서 포트·세그먼트화 → 네트워크층에서 IP주소 부여·라우팅 → 데이터링크에서 프레임화·MAC주소로 전달 → 물리 전송.
- 상향식 설명(수신 측): 물리 수신 → 데이터링크 프레임 해석 → 네트워크 패킷 수신(목적지 IP 확인) → 전송 계층에서 포트 기반 전달 → 응용으로 메시지 인계.

시험에서는 "어떤 계층에서 어떤 주소를 사용하는가"와 "어느 계층에서 어떤 문제가 발생하는가(예: ping이 실패할 때 ARP/ICMP/TCP 어디에 원인이 있는가)"를 묻는 문항이 자주 등장한다.

## 약어 풀이

- IP: Internet Protocol, 인터넷 프로토콜
- OSI: Open Systems Interconnection, 개방형 시스템 상호연결
- TCP: Transmission Control Protocol, 전송 제어 프로토콜
- UDP: User Datagram Protocol, 비연결형 전송 프로토콜
- ARP: Address Resolution Protocol, IP→MAC 변환 프로토콜
- ICMP: Internet Control Message Protocol, 네트워크 진단 및 오류 보고 프로토콜
- NAT: Network Address Translation, 사설↔공인 주소 변환
- DHCP: Dynamic Host Configuration Protocol, 동적 IP 할당

## 기출형 문제 예시 및 모범 답안(시험 대비)

Q1. "ARP의 역할을 설명하고, ARP가 실패했을 때 나타나는 증상을 기술하시오."
- 모범 답안 포인트: ARP는 IP 주소를 MAC 주소로 변환하여 같은 링크 내에서 프레임 전달이 가능하도록 한다. ARP가 실패하면 같은 서브넷 내 호스트 간 통신이 이루어지지 않으며(패킷을 전송할 MAC 주소를 모르므로), 보통 목적지에 대한 ARP 요청이 반복되거나 ARP 캐시에 없음으로 인해 통신 실패(핑 실패)가 발생한다.

Q2. "IP 패킷의 TTL이 줄어드는 이유와 TTL이 0이 되었을 때의 처리 과정을 서술하시오."
- 모범 답안 포인트: TTL은 라우팅 루프를 방지하기 위해 홉마다 1씩 감소하는 필드이다. TTL이 0이 되면 해당 패킷은 폐기되고, 송신지에게 ICMP Time Exceeded 메시지가 전송되어 경로 문제를 알린다.

Q3. "TCP와 UDP의 차이점을 3가지로 비교하시오."
- 모범 답안 포인트: (1) 연결성: TCP는 연결형, UDP는 비연결형. (2) 신뢰성: TCP는 재전송·ACK·시퀀스 등을 통한 신뢰성 제공, UDP는 신뢰성 제공 없음(애플리케이션에 위임). (3) 오버헤드/지연: TCP는 제어 정보로 오버헤드가 크고 지연이 발생할 수 있으나 신뢰성 제공, UDP는 오버헤드 작고 실시간성에 유리.

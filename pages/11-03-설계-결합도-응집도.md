# 11-03. 설계-결합도-응집도

> 학습 목적: 좋은 모듈 설계 기준을 암기한다.
> 관련 기출: [05-13-알고리즘-기출-모음](05-13-알고리즘-기출-모음.md)
> 연결 핵심정리: [04-3-소프트웨어공학-운영체제-컴퓨터구조](04-03-소프트웨어공학-운영체제-컴퓨터구조.md)

## 핵심 개념

- 결합도는 모듈 간 의존 정도다.
- 응집도는 모듈 내부 기능 관련성이다.
- 좋은 설계는 낮은 결합도와 높은 응집도를 지향한다.


### 서술형 확장 개념

- 좋은 설계는 정보은닉, 추상화, 모듈화로 변경 영향을 줄인다. SOLID 원칙은 단일 책임, 개방-폐쇄, 리스코프 치환, 인터페이스 분리, 의존성 역전을 통해 객체지향 설계의 변경 용이성을 높인다.
- 결합도는 자료 결합이 가장 낮고 내용 결합이 가장 높다. 응집도는 기능적 응집이 가장 좋고 우연적 응집이 가장 나쁘다. 서술형에서는 “결합도는 낮게, 응집도는 높게”와 함께 단계 예시를 들어야 한다.
- 디자인 패턴은 반복되는 설계 문제의 재사용 가능한 해법이다. Singleton은 인스턴스 하나를 보장하고, Factory는 객체 생성 책임을 분리하며, Adapter는 인터페이스 불일치를 맞추고, Observer는 상태 변화를 구독자에게 알린다. MVC는 모델, 화면, 제어 흐름을 분리해 유지보수성을 높인다.

| 원칙/패턴 | 핵심 의도 |
| --- | --- |
| 정보은닉 | 내부 구현 변경이 외부에 퍼지지 않게 함 |
| SOLID | 변경에 강한 객체지향 의존관계 구성 |
| Factory | 생성 로직을 캡슐화 |
| Observer | 이벤트 기반 통지 |
| MVC | 관심사 분리 |

## 쉽게 이해하기

- 결합도는 모듈끼리 얼마나 서로 의존하는지를 뜻한다. 서로 많이 얽혀 있으면 하나를 고칠 때 다른 곳도 흔들린다.
- 응집도는 한 모듈 안의 기능들이 얼마나 같은 목적을 향하는지를 뜻한다.
- 좋은 설계는 모듈끼리는 덜 얽히고, 모듈 내부는 한 가지 목적에 잘 모이는 상태다.

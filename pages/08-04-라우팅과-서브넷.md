# 08-04. 라우팅과 서브넷

> 학습 목적: 라우팅과 서브넷 계산의 기본을 정리한다.
> 관련 기출: [05-11-네트워크-기출-모음](05-11-네트워크-기출-모음.md)
> 연결 핵심정리: [04-4-네트워크-프로토콜-보안](04-04-네트워크-프로토콜-보안.md)

## 핵심 개념

- 라우팅은 목적지까지 경로를 선택하는 과정이다. 라우터는 목적지 IP에 따라 가장 적절한 다음 홉(next hop)을 결정해 패킷을 전달한다.
- 서브넷은 네트워크를 더 작은 단위로 나누는 방식이다. 효율적 주소 할당, 보안 분리, 브로드캐스트 도메인 분할이 목적이다.
- CIDR 표기와 호스트 수 계산을 함께 연습한다. CIDR `/n`에서 네트워크 비트는 n개, 호스트 비트는 `32-n`개다.

### 라우팅 기본 용어

- 라우팅 테이블: 목적지 네트워크, 넥스트홉, 메트릭/관리 거리(Administrative Distance)가 적힌 표.
- 넥스트 홉(next hop): 패킷을 다음으로 보낼 라우터 또는 인터페이스.
- Longest Prefix Match: 여러 후보 경로가 있을 때 가장 구체적인(긴 프리픽스) 경로를 선택.
- 정적 라우트: 관리자가 직접 입력한 경로. 단순하고 예측 가능하지만 확장성 낮음.
- 동적 라우팅: 라우팅 프로토콜(RIP, OSPF, BGP 등)을 통해 자동으로 경로 학습. 확장성과 자동화 장점.

### 라우팅 프로토콜 요약

- Distance Vector (예: RIP): 이웃 간 거리 정보를 주고받아 경로를 갱신. 간단하지만 count-to-infinity 문제가 있음.
- Link State (예: OSPF): 각 라우터가 전체 네트워크의 링크 상태 정보를 전파하고 Dijkstra로 최단 경로 계산. 수렴 빠름.
- BGP: AS 간 경로 교환 및 정책 기반 경로 선택. 인터넷 백본에서 사용되며, 정책과 경로 속성으로 라우트를 선택.

### 라우팅 결정 과정(인터뷰 포인트)

1. 목적지 IP를 라우팅 테이블의 여러 엔트리와 비교한다.
2. Longest Prefix Match(가장 긴 서브넷 마스크)가 우선한다.
3. 동일한 프리픽스가 여러 개면 관리 거리(AD)가 낮은 것이 우선.
4. AD가 같으면 각 프로토콜의 메트릭(e.g., OSPF cost, RIP hop count)을 비교한다.

## CIDR 및 서브넷 계산(실전 팁)

- 호스트 수 계산: 호스트 비트 m = 32 - n, 가능한 주소 수 = 2^m, 사용 가능한 호스트 = 2^m - 2 (네트워크 주소와 브로드캐스트 제외, 단점호험 상황에 따라 /31 및 /32 예외 있음).
- 서브넷 마스크: `/n` -> 마스크는 상위 n비트가 1인 32비트 값. 예: `/26` -> 255.255.255.192
- 네트워크 주소 계산: IP의 호스트 비트를 0으로 만들면 네트워크 주소가 된다.
- 브로드캐스트 주소 계산: IP의 호스트 비트를 1로 만들면 브로드캐스트 주소가 된다.

예시 계산(면접에서 자주 묻는 유형):

- 예: 192.168.10.66/26
  - 서브넷 마스크: 255.255.255.192 (/26)
  - 호스트 비트: 6 (32-26)
  - 서브넷 블록 크기: 2^6 = 64
  - 가능한 서브넷: 192.168.10.0/26, 192.168.10.64/26, 192.168.10.128/26...
  - 주어진 IP가 속한 서브넷: 192.168.10.64/26
  - 네트워크 주소: 192.168.10.64
  - 브로드캐스트 주소: 192.168.10.127
  - 사용 가능한 호스트 범위: 192.168.10.65 ~ 192.168.10.126 (62 hosts)

- 자주 나오는 범위(즉시 외우기 유용):
  - /24 -> 256 주소, 사용 가능 호스트 254
  - /25 -> 블록 크기 128, 사용 가능 호스트 126
  - /26 -> 블록 크기 64, 사용 가능 호스트 62
  - /29 -> 블록 크기 8, 사용 가능 호스트 6
  - /30 -> 블록 크기 4, 사용 가능 호스트 2 (주로 포인트 투 포인트)

실제 계산 예시는 다음 명령처럼 도구를 사용하면 빠르게 확인 가능:

```
# 예: ipcalc이 설치된 환경에서
ipcalc 192.168.10.66/26
```

(면접에서는 도구 없이 손으로 빠르게 계산하는 연습이 중요합니다.)

### VLSM(Variable Length Subnet Mask)

- 하나의 네트워크에서 서로 다른 길이의 서브넷 마스크를 사용해 주소를 효율적으로 배분.
- 인터뷰에서는 부서별로 필요한 호스트 수가 다를 때 VLSM으로 설계하라는 문제가 자주 출제됩니다. 큰 서브넷부터 먼저 할당하는 그리디 방식으로 계산하세요.

## 라우팅 테이블 예시 및 Longest Prefix Match

예시 라우팅 테이블:

```
Destination        Mask           Next Hop     Interface
10.0.0.0           255.0.0.0      10.1.1.2     eth0
10.1.0.0           255.255.0.0    10.1.1.3     eth1
10.1.5.0           255.255.255.0  10.1.1.4     eth2
0.0.0.0            0.0.0.0        192.0.2.1    eth3 (default)
```

- 목적지 IP 10.1.5.45를 보낼 때 위의 세 엔트리 중 가장 긴 프리픽스는 10.1.5.0/24이므로 해당 엔트리 선택.
- Longest Prefix Match 개념을 면접에서 명확히 설명할 수 있어야 합니다.

## 추가 네트워크 개념(면접 체크포인트)

- NAT 유형: SNAT, DNAT, PAT(포트 기반 NAT) 기본 역할과 작동 원리 설명 가능해야 함.
- ACL(Access Control List): 기본 흐름(permit/deny), 순서의 중요성, 라우터/스위치에서의 적용 차이.
- MTU와 단편화: 패킷 분할이 발생하는 상황과 Path MTU Discovery의 역할.
- ARP: IP -> MAC 매핑, ARP 캐시의 역할과 ARP 스푸핑 위험성.

## 실전 인터뷰 체크리스트

- [ ] CIDR 기본 개념과 서브넷 마스크 변환을 설명할 수 있다.
- [ ] 네트워크/브로드캐스트/첫번째/마지막 사용가능 주소를 손으로 계산할 수 있다.
- [ ] Longest Prefix Match와 라우팅 테이블 검색 과정을 설명할 수 있다.
- [ ] 정적/동적 라우팅, 주요 라우팅 프로토콜(RIP/OSPF/BGP)의 차이를 말할 수 있다.
- [ ] 라우팅 메트릭과 관리 거리(Administrative Distance) 개념을 이해하고 예를 들 수 있다.
- [ ] VLSM 설계 문제를 풀 수 있다(큰 블록부터 할당).
- [ ] NAT, ACL, MTU/단편화, ARP 기본 동작을 설명할 수 있다.

## 자주 묻는 면접 질문(예시) 및 간략 답변

- 질문: /26 서브넷이 주어졌을 때 사용 가능한 호스트 수는?
  - 답변: 호스트 비트 6 -> 2^6 - 2 = 62

- 질문: 라우터가 목적지에 대해 여러 경로를 가지고 있다면 어떤 기준으로 선택하나?
  - 답변: Longest Prefix Match -> 관리 거리(AD) -> 메트릭 순으로 결정.

- 질문: OSPF와 BGP의 주요 차이점은?
  - 답변: OSPF는 내부 라우팅 프로토콜(IGP)으로 링크 상태 기반, 빠른 수렴; BGP는 AS 간 경로 교환용(외부)으로 정책 기반 경로 선택.

- 질문: /30 서브넷은 주로 어떤 용도로 쓰이나?
  - 답변: 포인트 투 포인트 연결(2개의 usable IP)에서 자주 사용.

## 쉽게 이해하기

- 라우팅은 목적지까지 어떤 길로 갈지 정하는 내비게이션 역할이다.
- 서브넷은 큰 사무실을 팀별 구역으로 나누는 것과 비슷하다. 네트워크를 작게 나누면 관리와 보안이 쉬워진다.
- CIDR 문제는 주소 범위와 사용 가능한 호스트 수를 손으로 빠르게 계산하는 연습이 중요하다.

# 07-05. 인덱스와 동시성

> 학습 목적: 인덱스 장단점과 동시성 제어를 정리한다.
> 관련 기출: [05-10-데이터베이스-기출-모음](05-10-데이터베이스-기출-모음.md)
> 연결 핵심정리: [04-5-자료구조-알고리즘-DB-금융IT](04-05-자료구조-알고리즘-DB-금융IT.md)

## 핵심 개념

- 인덱스는 검색 속도를 높이지만 쓰기 비용을 늘린다.
- 동시성 제어는 여러 트랜잭션의 일관성을 지킨다.
- 로킹과 타임스탬프 기법을 구분한다.


### 서술형 확장 개념

- **B+Tree 인덱스**는 범위 검색과 정렬된 순회에 강하다. 내부 노드는 탐색 키를, 리프 노드는 실제 레코드 포인터 또는 데이터 위치를 담고 리프끼리 연결되어 range scan이 빠르다.
- **Hash 인덱스**는 동등 조건 검색에 강하지만 범위 검색과 정렬에는 부적합하다. 따라서 `WHERE id = ?`에는 유리하지만 `BETWEEN`, `ORDER BY`에는 B+Tree가 일반적으로 적합하다.
- **클러스터드 인덱스**는 데이터의 물리적 저장 순서와 인덱스 순서가 연결되어 범위 검색에 유리하지만 테이블당 보통 하나만 가능하다. 논클러스터드 인덱스는 별도 구조에서 데이터 위치를 가리킨다.
- **2PL(Two-Phase Locking)**은 lock을 획득하는 growing phase와 해제하는 shrinking phase로 나뉘며 conflict-serializable을 보장한다. strict 2PL은 exclusive lock을 commit/abort까지 유지해 cascading abort를 줄인다.
- **Timestamp ordering**은 먼저 시작한 트랜잭션이 논리적으로 먼저 실행된 것처럼 읽기/쓰기 순서를 통제한다. **MVCC**는 여러 버전을 유지해 읽기와 쓰기의 충돌을 줄이고 읽기 일관성을 높인다.

| Join 알고리즘 | 적합한 상황 | 핵심 비용 요인 |
| --- | --- | --- |
| Nested Loop Join | 한쪽 입력이 작거나 인덱스가 있음 | 반복 탐색 횟수 |
| Hash Join | 동등 조인, 메모리 충분 | 해시 테이블 구축/탐색 |
| Sort-Merge Join | 양쪽이 정렬되어 있거나 범위 처리 | 정렬 비용 |

## 쉽게 이해하기

- 인덱스는 책 뒤의 찾아보기와 같다. 원하는 내용을 빨리 찾게 해 주지만, 책 내용이 바뀔 때 찾아보기도 함께 고쳐야 한다.
- 동시성은 여러 사용자가 동시에 DB를 써도 결과가 꼬이지 않게 하는 문제다.
- 잠금은 한 사람이 수정하는 동안 다른 사람이 건드리지 못하게 하는 표시라고 보면 된다.

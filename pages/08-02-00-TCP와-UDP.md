# 08-02. TCP와 UDP

> 학습 목적: TCP와 UDP의 연결성, 신뢰성, 속도를 비교한다.
> 관련 기출: [05-11-네트워크-기출-모음](05-11-네트워크-기출-모음.md)
> 연결 핵심정리: [04-4-네트워크-프로토콜-보안](04-04-네트워크-프로토콜-보안.md)

## 핵심 개념

- TCP는 연결형(connection-oriented) 전송 프로토콜로, 신뢰성(reliability)과 데이터의 순서 보장(in-order delivery)을 제공한다.
  - 흐름 제어(flow control)와 혼잡 제어(congestion control)를 통해 수신자와 네트워크 상태에 맞춰 전송률을 조절한다.
  - 주요 특징: 연결 설정(3-way handshake), 순서 번호(sequence number), ACK 응답, 재전송, 연결 종료(4-way handshake)와 TIME_WAIT 상태.
- UDP는 비연결형(connectionless) 전송 프로토콜로 헤더가 단순하고 지연(latency)이 작아 빠른 전송에 유리하지만 신뢰성 보장 기능을 제공하지 않는다.
  - 애플리케이션 레벨에서 필요 시 재전송이나 오류 정정을 직접 구현해야 한다.
  - 주요 사용 사례: DNS, 실시간 스트리밍(예: VoIP/영상 스트리밍), 온라인 게임 등 지연이 중요한 서비스.
- 성능/특성 비교(요약):

| 항목 | TCP | UDP |
|---|---:|---:|
| 연결 | 연결형 | 비연결형 |
| 신뢰성 | 있음(재전송, ACK) | 없음(애플리케이션 책임) |
| 순서 보장 | 보장 | 보장하지 않음 |
| 헤더 크기 | 최소 20바이트 | 8바이트 |
| 적합한 서비스 | 파일 전송, 웹(HTTP), 이메일 | DNS, 스트리밍, 실시간 게임 |

### 요점(시험용 암기 포인트)
- TCP는 '신뢰성', '순서 보장', '연결 지향' 키워드로 기억.
- UDP는 '속도', '간단한 헤더', '비연결'로 기억.
- TIME_WAIT는 지연된 패킷 혼입 방지와 마지막 ACK 재전송을 위한 상태라는 점을 반드시 설명할 수 있어야 함.


### 서술형 확장 개념

1. 시퀀스 번호와 ACK
   - TCP는 바이트 스트림 단위로 데이터를 분할하여 각 세그먼트에 시퀀스 번호를 붙인다. 수신자는 다음 기대 바이트를 ACK로 응답한다.
   - 중복 수신, 손실, 순서 뒤바뀜을 시퀀스 번호와 ACK로 검출하고 복구한다.

2. 재전송(RTO)과 RTT
   - 송신자는 수신 ACK를 기다리다가 일정 시간(RTO, retransmission timeout) 후 ACK가 도착하지 않으면 재전송한다.
   - RTT(round-trip time) 측정값을 기반으로 RTO를 계산·조정한다. 적절한 RTT 추정은 불필요한 재전송을 줄이는 데 중요하다.

3. TIME_WAIT의 의미
   - 연결 종료 후에 한쪽(일반적으로 연결을 종료한 쪽)이 TIME_WAIT 상태로 들어간다. 목적은 네트워크에 남아있을 수 있는 지연된 패킷이 이후의 새 연결에 혼입되는 것을 방지하고, 마지막 FIN/ACK이 손실되었을 때 재전송할 수 있도록 하기 위함이다.
   - 시험에서는 "왜 TIME_WAIT이 필요한가"를 짧고 명확히 답할 수 있어야 한다(지연 패킷의 격리 + 마지막 ACK 대응).

4. 흐름 제어 vs 혼잡 제어(요약)
   - 흐름 제어(flow control): 수신자의 처리능력에 맞춰 송신 윈도우를 조절한다(수신 윈도우 광고).
   - 혼잡 제어(congestion control): 네트워크 혼잡을 감지하고 혼잡 윈도우(cwnd)를 통해 전송률을 조절한다(예: 증가·감소 전략 개념 이해 필요).

5. UDP의 특징 심화
   - 헤더가 단순하고 오버헤드가 작아 실시간 전송에서 유리하다.
   - 다만 신뢰성이 필요하면 애플리케이션 계층에서 ARQ(자동 재전송)나 FEC(순방향 오류 정정) 등을 구현해야 한다.


## 쉽게 이해하기(비유·핵심 비교)

- TCP: 등기우편(수취 확인을 받고, 분실 시 재전송하며 순서대로 정리).
- UDP: 일반 소포나 방송(빠르게 보내지만 하나하나 확인하지 않음).
- 구분 체크포인트: 연결 여부, 신뢰성(재전송/ACK), 순서 보장, 헤더 크기/오버헤드, 적합한 사용 사례.



## 실무/설정 관련 한줄 요약
- 서버에서 TIME_WAIT가 과다하면 포트 재사용 관련 설정(예: 소켓 옵션)이나 동시 연결 처리 설계를 점검해야 한다(서버 소켓/포트 자원 문제 관점).
- 지연이 민감한 서비스는 UDP를 기본으로 하되, 신뢰성이 필요한 경우 애플리케이션 레벨에서 보완한다.

## 예상 문제와 모범 답안(연습)

Q1. TCP와 UDP의 차이를 3문장 이내로 요약하시오.
A1. TCP는 연결형으로 신뢰성과 순서 보장을 제공하며 재전송·흐름·혼잡 제어를 수행한다. UDP는 비연결형으로 헤더가 단순하고 지연이 작아 실시간 서비스에 유리하지만 신뢰성은 애플리케이션이 책임진다. 따라서 파일 전송·웹 트래픽 등에는 TCP, DNS·스트리밍·게임 등에는 UDP가 주로 사용된다.

Q2. TIME_WAIT이 필요한 이유를 기술하시오.
A2. 네트워크에 지연되어 남아있는 패킷이 이후의 새 연결에 혼입되는 것을 방지하고, 연결 종료 과정에서 마지막 ACK가 손실되었을 때 재전송을 처리하기 위해 일정 시간 동안 소켓을 유지하는 상태이다.

Q3. UDP를 사용할 때 애플리케이션에서 보완해야 할 점 2가지를 쓰시오.
A3. 패킷 손실에 대한 재전송 또는 복원 전략(예: ARQ)과 순서 보장이 필요하면 순서 재정렬 또는 시퀀싱을 구현해야 한다. 또한 패킷 무결성 검증(체크섬 등)과 흐름 제어/혼잡 제어를 별도로 고려해야 한다.

## 약어 풀이

- TCP: Transmission Control Protocol, 전송 제어 프로토콜

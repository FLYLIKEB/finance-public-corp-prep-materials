# 16-2. 학습·검증·전처리

## 학습 절차 개요

| 단계 | 목적 | 주의점 |
| --- | --- | --- |
| Train | 모델 파라미터 학습 | 훈련 데이터만 사용 |
| Validation | 하이퍼파라미터 선택 | 테스트셋 반복 사용 금지 |
| Test | 최종 일반화 성능 확인 | 학습 종료 후 한 번만 사용 |
| Cross-validation | 데이터가 적을 때 안정적 평가 | fold 분포 차이와 시간 순서 확인 |

## 데이터 전처리 핵심

- 결측치 처리, 이상치 점검, 중복 제거, 범주형 인코딩, 정규화·표준화가 기본 작업이다.
- 전처리는 모델 뒤가 아니라 학습 파이프라인 안에서 재현 가능하게 관리해야 한다.
- 금융 데이터는 휴일, 취소 거래, 지점 코드 변경, 사후 정정처럼 업무 문맥을 모르면 잘못 전처리하기 쉽다.

## 데이터 누수

- 데이터 누수는 실제 운영 시점에는 알 수 없는 정보가 학습 과정에 들어가 성능이 과대평가되는 문제다.
- 금융 예시로는 승인 이후에만 확정되는 변수, 미래 기간 거래 정보, 전체 데이터 기준 정규화 통계 사용이 있다.
- 시계열 데이터는 무작위 분할보다 시간 순 분할이 기본이다.

## 실무 체크포인트

- 피처 생성 시점과 라벨 생성 시점을 같이 적어 둔다.
- 훈련·검증·테스트를 나누기 전에 전체 데이터로 스케일링 통계를 계산하지 않는다.
- 시드 고정, 데이터 버전 관리, 파이프라인 코드화를 통해 재현성을 확보한다.
- 라벨이 늦게 확정되는 업무는 label latency를 고려해 검증 구간을 잡는다.

## 면접 포인트

- “전처리가 알고리즘보다 성능에 더 큰 영향을 줄 때가 많다”는 문장은 실무 감각을 보여 준다.
- “데이터 누수는 모델이 똑똑해서가 아니라 평가가 잘못된 것”이라고 정리하면 차이가 선명하다.
- 검증 절차는 train/validation/test를 외우는 데서 끝내지 말고 왜 나누는지까지 설명해야 한다.

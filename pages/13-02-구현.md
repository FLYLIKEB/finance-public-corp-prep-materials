## 핵심 개념

- 입력 형식과 출력 형식을 먼저 고정한다.
- 조건 분기와 반복문 경계를 확인한다.
- 작은 예제로 상태 변화를 추적한다.


### 서술형 확장 개념

- 구현형 문제는 입력 크기를 먼저 보고 O(n²)이 가능한지, O(nlogn) 또는 O(n)이 필요한지 판단한다. 시간 제한이 1초이고 n이 100,000이면 이중 반복문은 대개 위험하다.
- Amortized analysis는 한 연산의 최악 비용이 크더라도 여러 번 수행했을 때 평균 비용이 작다는 분석이다. 동적 배열 append는 가끔 resize로 O(n)이지만, 여러 번의 append를 평균하면 O(1)로 설명한다.
- 해시 테이블은 평균 O(1) 조회를 제공하지만 충돌 처리 방식과 load factor에 따라 성능이 달라진다. Chaining은 같은 버킷에 리스트를 두고, open addressing은 다른 빈 칸을 탐사한다.

## 학습 포인트 (학습 친화적 요약)

- 입력 파싱 우선:
  - 입력에 공백, 개행, 불필요한 문자가 있는지 확인.
  - 여러 줄 입력/한 줄에 여러 값 등 입력 포맷에 맞춰 안전하게 파싱.
- 경계 조건(Edge cases) 확인:
  - 빈 입력, 최소/최대값, 단일 원소, 동률/동일한 값들.
- 반복문 경계와 인덱스:
  - inclusive/exclusive 경계(off-by-one 오류 주의).
- 자료구조 선택 근거:
  - 배열/리스트, 집합/맵, 큐/스택, 우선순위큐 등 시간/공간 복잡도 기준으로 선택.
- 시간 복잡도 판단:
  - n ≤ 1e5: O(nlogn) 또는 O(n) 권장, O(n²)은 위험.
  - n ≤ 1e4: 구현에 따라 O(n²)도 가능.
- 수치 안전성:
  - 합이 커질 가능성 있으면 정수형 크기(long/long long) 사용.
- 출력 형식 정확성:
  - 공백, 개행, 소수점 자리수, 부호 등 문제 요구와 정확히 일치시킬 것.

## 시험 포인트 (흔히 출제되는 체크리스트)

- 입력 제약을 기반으로 알고리즘 복잡도 요구를 말할 수 있는가?
- 오프바이원(off-by-one), 빈 배열, 한 원소인 경우를 고려했는가?
- 정수 오버플로우 가능성 및 모듈러 연산 요구를 파악했는가?
- 빠른 입출력(언어별 stdin/stdout 최적화)이 필요한지 판단했는가?
- 자료 구조의 평균/최악 시간 복잡도 차이를 이해하고 선택했는가?

## 실무 연결 (면접/업무에서의 확장)

- 견고한 입력 검증: 외부 API나 파일에서 온 입력은 형식이 항상 깔끔하지 않다. 방어적 코딩(예: null/빈값 체크, 예외 처리)을 습관화한다.
- 로그와 단위 테스트: 기능을 작은 단위로 나누고 단위 테스트 케이스를 만들어 경계값에 대한 자동 검증을 둔다.
- 성능 측정: 실제 데이터로 프로파일링하여 병목을 찾는다(알고리즘 교체, 캐시 사용, I/O 최소화).
- 라이브 환경 고려: 메모리 제약, 멀티스레드 접근, 동시성 문제(락, 원자성) 등을 검토한다.

## 예제: 작은 상태 전이 추적 (설명 + 코드)

- 문제 유형: 여러 명령어를 받아 상태를 전이시키고 최종 상태 출력
- 접근법:
  1. 입력 형식(명령 수, 명령 리스트) 고정
  2. 상태 변수 초기화
  3. 명령 순차 처리(경계/예외 확인)
  4. 출력

예시(Python 스타일 의사 코드):

```python
# 입력 예: 첫 줄 n, 다음 n줄에 명령어
# 명령어 예: "PUSH x", "POP", "INC k v"
import sys
input = sys.stdin.readline

n = int(input())
stack = []
for _ in range(n):
    parts = input().split()
    cmd = parts[0]
    if cmd == 'PUSH':
        x = int(parts[1])
        stack.append(x)
    elif cmd == 'POP':
        if stack:           # 빈 상태 체크
            stack.pop()
        else:
            # 문제에 따라 무시하거나 에러 처리
            pass
    elif cmd == 'INC':
        k = int(parts[1])
        v = int(parts[2])
        # 작은 예제에서는 O(k)로 처리하되, 큰 k가 반복되면 누적 방식 필요
        for i in range(min(k, len(stack))):
            stack[i] += v

# 출력: 문제 요구 포맷에 맞게
print(' '.join(map(str, stack)) if stack else 'EMPTY')
```

- 위 코드에서 주의할 점:
  - 빈 스택에서 POP을 호출할 수 있으므로 조건 검사 필요.
  - INC 구현은 직관적이나 k가 커지고 반복 호출 빈도가 높으면 비효율적 -> 누적 배열 또는 차분 기법 고려.

## 테스트 케이스 설계 팁

- 기본 동작: 예시 입력/출력 그대로 통과하는지 확인.
- 경계값:
  - n = 0 또는 명령이 없는 경우
  - n = 1 (단일 명령)
  - 최대 n에서의 수행 시간
- 랜덤/스트레스 테스트: 간단한(그러나 느린) 브루트포스 해법과 출력 비교.
- 특수 케이스: 동일한 값이 여러 개 연속으로 오는 경우, 정렬/순서 의존성 있는 경우.

## 자주 하는 실수와 방지책

- 입력 형식 오독: 문제의 공백/개행 규칙을 잘못 해석하여 WA 발생 — 입력 예시를 여러 가지로 직접 파싱해보라.
- 오프바이원: 반복문의 시작/끝 조건을 손으로 작은 예제에 대해 체크.
- 자료형 부족: 합/곱이 32비트 범위를 초과할 수 있는지 항상 검토.
- 불필요한 시간낭비: 간단한 문제에 복잡한 구조 도입 — 문제의 요구 수준에 맞춰 단순하게 유지.

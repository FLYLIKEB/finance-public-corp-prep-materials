# 18-3. 양자컴퓨팅과 보안

## 핵심 개념

- 양자컴퓨팅은 특정 문제 영역에서 고전적(클래식) 컴퓨팅 대비 큰 속도 우위를 제공할 수 있다. 이로 인해 RSA, ECC 같은 현재 널리 쓰이는 공개키 암호는 장기적으로 위험에 처할 수 있다.
  - 특히 소인수분해(정수 분해)와 이산대수 문제를 효율적으로 푸는 양자 알고리즘이 등장하면 현재의 공개키 기반 보안이 약화된다.
- 양자 키 분배(QKD, Quantum Key Distribution)
  - 양자 상태의 측정 특성을 이용해 키 분배 도중의 도청을 탐지하려는 물리적(하드웨어) 기반 기술이다.
  - 장점: 도청 시도 탐지 가능성(정보 이득 대 파괴의 원리)으로 이론적 보안성 제공.
  - 단점/제약: 전용 광학 장비 필요, 거리 및 중계 제한, 비용·운영 복잡성. 모든 환경의 일괄 대체재는 아니다.
- 포스트양자암호(PQC, Post-Quantum Cryptography)
  - 양자컴퓨터에 대해서도 안전하다고 여겨지는 수학적 문제에 근거한 소프트웨어 기반 암호 알고리즘을 말한다.
  - 목적: 기존 통신·저장 환경에서 하드웨어 변경 없이도 적용 가능한 대체 알고리즘 확보.
- 표준화 동향(문서 기반 요약)
  - NIST는 2024년에 ML-KEM(FIPS 203), ML-DSA(FIPS 204), SLH-DSA(FIPS 205)를 첫 PQC 표준으로 발표했다.
  - ML-KEM은 키 교환/키 캡슐화(KEM) 용도, ML-DSA와 SLH-DSA는 전자서명(DSA) 용도이다.
- 운영·리스크 관점 핵심 메시지
  - "Harvest now, decrypt later" 위협: 공격자가 현재의 통신을 수집해 장기 저장한 뒤 양자컴퓨터가 등장하면 나중에 복호화할 수 있다. 따라서 장기 보존되는 데이터(금융·의료 기록 등)는 우선 식별·우선순위화해야 한다.
  - 현실적 대응은 전부를 즉시 바꾸는 것이 아니라, crypto-agility(암호전환 유연성)를 확보하고 위험 기반 우선순위에 따라 점진 전환을 수행하는 것이다.

## QKD vs PQC 요약 비교

| 항목 | QKD | PQC |
|---|---:|---:|
| 접근 방식 | 물리적(광학·양자 상태) | 수학적(알고리즘·프로토콜) |
| 장점 | 도청 시도 탐지 가능성 | 기존 인프라에 소프트웨어로 적용 가능(대체 경로) |
| 제약 | 전용 장비·거리·비용 | 표준화·상호운용성·성능(키·서명 크기 등) 이슈 |
| 적합 대상 | 보안이 극히 중요한 지점간 링크(예: 핵심 백본) | 광범위한 응용(웹·VPN·PKI 등)의 대체/보완 |

## 실무 적용 체크리스트

- [ ] 자산 식별: 어떤 시스템이 어떤 공개키 알고리즘(RSA, ECC 등)을 사용 중인지 목록화
- [ ] 데이터 분류: 얼마나 오래 보존되는 데이터(장기 기밀성 필요)를 우선 식별
- [ ] 우선순위 설정: 장기 보존·민감성·법규 요구사항을 기준으로 전환 우선순위 결정
- [ ] 테스트 환경 구축: PQC 알고리즘/하이브리드 모드(기존 알고리즘 + PQC) 적용을 위한 검증 환경 마련
- [ ] 암호전환 계획(crypto-agility): 알고리즘 교체 시나리오, 롤백 절차, 호환성 테스트 포함
- [ ] 키·인증서 관리: 키 교체 주기, CA 정책, 인증서 체인 영향 분석
- [ ] 운영 절차: 장애·상호운용성 문제 발생 시 대응 매뉴얼 준비
- [ ] 규정·컴플라이언스 검토: 표준 변화(FIPS 등)에 따른 규정 준수 계획 수립

## 면접 답변 포인트 (간결한 요지)

- 핵심 메시지: "양자보안은 지금 당장 모든 암호를 교체하는 문제가 아니라, crypto-agility를 갖추고 위험 기반으로 전환을 실행하는 문제입니다."
- 짧은 예시 답변(30–60초):
  - "우선적으로 장기 보존되는 데이터와 인증서·키를 식별했습니다. 그런 자산부터 PQC 전환 혹은 하이브리드 모드로의 테스트를 진행하고, 전체 인프라에 대해서는 단계적으로 교체하는 계획을 수립합니다. 또 표준화 동향을 모니터링하며 FIPS(예: ML-KEM, ML-DSA, SLH-DSA)의 권고에 따라 호환성 테스트를 수행합니다."
- 추가로 면접관이 묻는 예상 질문과 준비 포인트:
  - "우리 조직에서 어디부터 시작할까요?" → 장기 보존·고민감 데이터, 공개키 인프라(PKI)·TLS 인증서·백업 암호화를 우선 식별
  - "QKD를 도입해야 할까요?" → 비용·운영 제약을 고려해 핵심 링크(백본 등) 용도로만 검토하고, 일반 서비스에는 PQC 우선 적용을 권장

## 실무 예시(간단한 절차 템플릿)

```
# 자산 인벤토리 생성(의사코드)
assets = scan_infrastructure_for_algorithms()
for a in assets:
  if a.algorithm in ['RSA', 'ECC']:
    record(a.id, a.algorithm, a.key_expiry, a.data_retention_period)

# 우선순위: 장기보존 및 고민감 데이터 먼저
high_priority = filter(assets, lambda x: x.data_retention_period > YEARS(5) or x.is_high_confidentiality)
```

위 템플릿은 개념 수준의 흐름을 보여주며, 실제 도구·스크립트는 조직 환경에 맞춰 작성해야 한다.

## 시험·학습 포인트

- 왜 양자컴퓨팅이 RSA/ECC에 위협이 되는지(문제 유형: 소인수분해·이산대수 문제 관련 양자 알고리즘의 영향)를 설명할 수 있어야 한다.
- QKD와 PQC의 차이(물리적 접근 vs 수학적 접근)와 각 접근의 현실적 제약을 비교 설명할 수 있어야 한다.
- "harvest now, decrypt later" 위협의 의미와 조직 내 우선순위(장기 보존 데이터, 인증서 관리)의 실무적 함의를 설명할 수 있어야 한다.
- PQC로의 전환에서의 핵심 개념: crypto-agility, 하이브리드 전환 전략, 테스트·상호운용성 검증, 키·인증서 수명관리

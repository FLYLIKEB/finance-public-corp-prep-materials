# 10-03-02. DDoS-스머프-SYN-Flood

> 학습 목적: 가용성을 침해하는 네트워크 공격을 비교한다.
> 관련 기출: [05-12-보안-기출-모음](05-12-보안-기출-모음.md)
> 연결 핵심정리: [04-4-네트워크-프로토콜-보안](04-04-네트워크-프로토콜-보안.md)

## 핵심 개념

- DDoS는 여러 위치의 다수 장비(봇넷 등)에서 대량 트래픽을 보내 서비스의 정상 제공을 방해하는 공격이다.
- 스머프(Smurf) 공격은 IP 브로드캐스트와 ICMP 응답의 특성을 이용해 트래픽을 증폭시키는 공격이다.
- SYN Flood는 TCP 3-way handshake 과정에서 SYN 요청만 대량으로 보내 서버의 연결 대기(half-open) 자원을 고갈시키는 공격이다.

## 쉽게 이해하기

- DDoS: 동시에 많은 사람이 가게 문 앞에 몰려들어 정상 고객이 들어갈 수 없는 상태로 만드는 것과 유사하다.
- 스머프: 공격자가 작은 요청을 보내면 여러 제3자(브로드캐스트 대상)가 큰 응답을 피해 대상에게 보내 결과적으로 공격 트래픽이 증폭되는 구조이다.
- SYN Flood: 연결을 맺기 위한 ‘악수(SYN)’만 반복해서 보내 서버가 응답을 대기 상태로 유지하게 하고, 새로운 정상 연결을 수락할 수 없게 만든다.

## 공격 유형 비교

| 항목 | DDoS(일반) | 스머프(증폭형) | SYN Flood(자원고갈형) |
|---|---:|---:|---:|
| 기본 목표 | 서비스 가용성 저하 | 소수의 요청을 증폭해 목표로 대량 트래픽 전달 | TCP 연결 대기 큐 고갈로 신규 연결 차단 |
| 주 사용 프로토콜 | 여러(UDP, ICMP, HTTP 등) | ICMP(에코 요청/응답) 기반 | TCP (SYN 플래그) |
| 증폭 가능성 | 상황에 따라 다름 | 높음(브로드캐스트 + 반사) | 낮음(증폭보다는 연결 상태 소모) |
| 방어 핵심 | 트래픽 분산·필터링·스케일링 | 브로드캐스트 차단, 반사 소스 차단 | SYN cookie, 접속 제한, 방화벽/IPS 설정 |

## 공격 원리 상세

### 스머프(Smurf)
- 공격자는 출발지 주소를 희생자(IP spoofing)로 위조해, 브로드캐스트 주소로 ICMP Echo Request(핑)를 보낸다.
- 브로드캐스트를 받은 여러 호스트가 희생자 주소로 ICMP Echo Reply를 보내 결과적으로 작은 요청이 여러 배의 응답으로 증폭되어 희생자에게 전달된다.
- 방어 포인트: 네트워크 경계에서 IP-directed broadcast를 차단하고, 내부 호스트에서 브로드캐스트에 대한 응답을 제한한다.

### SYN Flood
- TCP 연결 수립 시 서버는 SYN을 받고 SYN-ACK을 보내며 연결 정보를 반영하여 half-open 상태로 일정 시간 대기(리소스 점유)한다.
- 공격자는 ACK를 보내지 않거나 스푸핑된 출처로 SYN을 지속 전송해 서버의 half-open 큐를 채운다.
- 결과적으로 정상 클라이언트의 연결 수립이 실패한다.
- 방어 포인트: SYN cookies, 백로그 큐 크기 조정, 접속 속도 제한(rate limiting), 방화벽/로드밸런서 차단 등.

## 탐지(시그니처) 및 실무적 방어책

- 탐지(예시 시그니처)
  - 트래픽의 비정상적 급증(특정 포트 또는 ICMP 유형) 관찰
  - 많은 수의 SYN 패킷이 있으나 ACK 응답이 거의 없음(또는 ICMP echo replies가 갑자기 급증)
  - 다수의 서로 다른 출발지(또는 스푸핑된 동일한 출발지)에서 오는 트래픽

- 실무 방어(중복·계층적 적용 권장)
  - 네트워크 경계·라우터에서 ACL로 IP Directed Broadcast 차단 (스머프 완화)
  - 방화벽/IPS에서 비정상 트래픽 패턴 차단 및 rate limiting 적용
  - SYN Flood 대응: SYN cookies 활성화, TCP 접속 백로그(queue) 확장, 접속 속도 제한
  - CDN/로드밸런서/클라우드 기반 흡수(대규모 공격 시 트래픽 분산)
  - 블랙홀(Null) 라우팅으로 피해 IP/포트 일시 차단(서비스 중단을 감수할 수 있을 때)
  - 로그/메트릭 기반의 빠른 알람 및 트래픽 소스 분석

## 실무 명령/예시

- SYN 패킷 모니터링(tcpdump 예시)

```
# SYN만 필터(ACK 없는 SYN): tcp[13]의 0x02(SYN) 비트만 세트되고 0x10(ACK) 비트는 0
tcpdump -n -i any 'tcp[13] & 2 != 0 and tcp[13] & 16 == 0'
```

- iptables로 SYN rate-limit 예시(서버 보호용, 예시일 뿐 운영 환경에 맞게 조정 필요)

```
# 초당/분 단위 제한 적용 예시
iptables -A INPUT -p tcp --syn -m limit --limit 25/min --limit-burst 100 -j ACCEPT
iptables -A INPUT -p tcp --syn -j DROP
```

- 스머프 완화(라우터 예시 설명)
  - 네트워크 경계 라우터에서 브로드캐스트 패킷에 대한 포워딩 차단
  - 내부 호스트의 ICMP 응답 정책 검토 및 불필요한 브로드캐스트 서비스 비활성화

## 시험 포인트(단답형/서술형 대비)

- DDoS의 정의와 목표(가용성 저해)를 명확히 설명할 것.
- 스머프 공격의 증폭 메커니즘(브로드캐스트 + 소스 IP 위조)을 설명할 것.
- SYN Flood의 동작(half-open 상태, SYN만 반복 전송)과 방어방법(SYN cookies 등)을 기술할 것.
- 탐지 시 흔히 관찰되는 네트워크 징후(비정상적 SYN/ICMP 트래픽 증가, ACK 부족 등)를 제시할 것.
- 실무에서 적용 가능한 계층적 방어 전략(네트워크 경계 필터링, 서버측 설정, 트래픽 분산 등)을 사례 중심으로 정리할 것.

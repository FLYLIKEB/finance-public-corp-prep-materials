# 02-12. NotebookLM 기반 압축 학습 전략

작성 기준일: 2026-06-25  
전제: 백엔드 실무 경험과 과거 면접 대비 경험이 있고, 현재 제공된 기출의 절반 이상은 풀 수 있는 상태이다. 따라서 6~8월에는 전공책을 과목별로 처음부터 정독하지 않고, `기출형 문제 생성 → 풀이 → 오답 개념 보강 → 서술형 답안화` 루프로 준비한다.

## 1. 핵심 방향

- 전공책 정독은 하지 않는다. 필요한 개념이 틀렸을 때만 발췌 확인한다.
- 정보처리기사 실기 내용은 이미 1회독했으므로, 전체 CS 목차 점검용 기준표로만 사용한다.
- 한국은행 기출은 9월 이후 실전 검증용으로 아껴 둔다.
- 단, NotebookLM에는 한국은행 기출을 소스로 넣어 `출제 스타일`, `빈출 개념`, `서술 깊이`를 반영하게 한다.
- 6~8월의 실제 풀이 재료는 비한은 금융공기업 기출, 국가직 전산직 기출, 위키 핵심정리, 정처기 실기 요약이다.
- 목표는 “많이 아는 상태”가 아니라 “시험장에서 5~7문장으로 부분점수를 안정적으로 확보하는 상태”이다.

## 2. NotebookLM 소스 구성

### 공통 소스

| 구분 | 넣을 자료 | 용도 |
|---|---|---|
| 기본 뼈대 | 정보처리기사 실기 요약/목차 | 빠진 과목·개념 탐지 |
| 현재 위키 | 04 IT 필기 핵심정리, 06~11 전공별 정리, 13 SQL/코딩, 16 금융 도메인 | 개념 설명·서술형 답안 재료 |
| 기출 스타일 | 05 금융공기업 IT 기출문제 전체 | 출제 패턴 학습 |
| 한은 스타일 | 05-14 한국은행 기출 | 9월 전까지 직접 풀이하지 않고 스타일 반영용으로만 사용 |
| 확장 문제 | 국가직 전산직 7급 컴퓨터일반·정보보호론 기출 | 객관식/단답형 약점 탐지 |
| 고난도 확장 | 국가직 전산직 5급 관련 기출 중 OS/DB/네트워크/보안/자료구조 핵심 문항 | 상위 개념 보강 |

### 과목별 노트북 분리

한 노트북에 전부 넣지 말고 다음처럼 분리한다.

1. `OS-DB 핵심/기출`
2. `네트워크-보안 핵심/기출`
3. `자료구조-알고리즘-SQL`
4. `소프트웨어공학-컴퓨터구조-AI/ML`
5. `한국은행 전공논술/일반논술 스타일`
6. `오답노트/약점 재생성`

## 3. 6월 25일 이후 운영 원칙

### 6/25~6/30: 진단과 문제 생성 체계 만들기

- 정처기 실기와 위키 04~11을 기반으로 과목별 NotebookLM 노트북을 만든다.
- 한국은행 기출은 직접 풀지 않고 NotebookLM 소스에만 넣는다.
- 비한은 기출과 국가직 7급 기출로 과목별 20~30문항 진단 세트를 만든다.
- 각 문제를 풀고 `맞음/애매함/틀림/모름`으로 표시한다.
- 6월 말 산출물은 전공책 요약노트가 아니라 다음 3개이다.
  - 과목별 약점표
  - 자주 틀리는 개념 30개
  - 서술형 답안 템플릿 20개

### 7월: 생성 문제 반복 + 약점 개념 보강

- 매일 NotebookLM으로 과목별 서술형·단답형 문제를 생성해 푼다.
- 틀린 문제는 위키와 정처기 실기 자료에서 해당 개념만 발췌 보강한다.
- 국가직 7급 기출은 객관식이라도 “왜 정답이고 왜 오답인지”를 서술형으로 바꿔 정리한다.
- 매주 1회는 한은 스타일을 반영한 모의 세트를 만들되, 실제 한은 기출 원문을 회차별로 풀지는 않는다.
- 7월 말 기준 목표는 `기출형 개념 70% 이상 즉답`, `주요 개념 5문장 설명 가능`이다.

### 8월: 서술형 답안화와 실전 시간 압박

- 새 자료 추가를 줄이고, 7월 오답과 약점에서 문제를 재생성한다.
- 과목별로 매주 최소 2회 “전공필기+전공논술 동시 세트”를 푼다.
- 답안은 키워드 나열이 아니라 `정의 → 원리 → 장단점/비교 → 예시 → 금융IT 적용` 구조로 쓴다.
- 한국은행 기출은 여전히 회차별 실전 풀이를 미루되, NotebookLM이 뽑아주는 빈출 개념·유사 문제는 푼다.
- 8월 말 기준 목표는 `오답 2회전`, `핵심 개념 100개 서술 가능`, `전공논술 소재 10개 확보`이다.

### 9월 이후: 한국은행 기출 실전 투입

- 9월부터 한국은행 기출을 회차별·시간제한으로 푼다.
- 이미 NotebookLM으로 스타일은 익혔으므로, 9월에는 점수화와 시간 배분에 집중한다.
- 틀린 문제는 새 개념을 넓히기보다 기존 오답노트에 병합한다.

## 4. NotebookLM에 넣을 요청 프롬프트

### 진단 세트 생성

```text
나는 금융공기업 IT 필기, 특히 한국은행 컴퓨터공학 직렬을 준비 중이다.
소스의 한국은행 기출은 직접 풀이용으로 소모하지 말고 출제 스타일 참고용으로만 사용해라.
OS/DB/네트워크/자료구조/보안/SW공학에서 실제 시험에 나올 법한 서술형·단답형 문제 20개를 만들어라.
각 문항에는 출제 의도, 핵심 키워드, 모범답안 5~7문장, 채점 포인트를 포함해라.
```

### 오답 기반 재출제

```text
아래는 내가 틀렸거나 애매했던 개념 목록이다.
이 개념들을 중심으로 변형 문제를 만들어라.
단순 암기 문제가 아니라 비교, 장단점, 원리 설명, 금융IT 적용까지 묻는 문제로 만들어라.
문제마다 내가 빠뜨리기 쉬운 함정도 함께 적어라.
```

### 객관식 기출의 서술형 변환

```text
국가직 전산직 객관식 기출을 금융공기업 서술형 필기 문제로 변환해라.
정답만 묻지 말고, 왜 다른 선택지가 틀렸는지 설명하게 만들어라.
모범답안은 5~7문장으로 작성하고, 부분점수 기준을 제시해라.
```

### 한은 스타일 모의 세트

```text
한국은행 기출 원문을 그대로 재사용하지 말고, 소스에서 관찰되는 출제 스타일과 난이도만 반영해 유사 모의문제를 만들어라.
전공필기 8문항과 전공논술 1문항으로 구성하고, 총 2시간 30분 내 풀이를 가정해라.
각 문항의 예상 소요시간과 채점 포인트를 표시해라.
```

## 5. 하루 루틴

| 블록 | 시간 | 내용 |
|---|---:|---|
| 1 | 60~90분 | NotebookLM 생성 문제 풀이 |
| 2 | 60분 | 틀린 개념만 위키/정처기/기출 해설로 보강 |
| 3 | 45~60분 | 5~7문장 서술형 답안 작성 |
| 4 | 30~45분 | SQL/코딩 또는 NCS 유지 |
| 5 | 20분 | 오답 개념을 다음 날 NotebookLM 재출제 목록에 추가 |

시간이 부족한 날에는 `문제 풀이 → 오답 3개 → 재출제 목록 추가`까지만 한다.

## 6. 주간 점검 기준

- 새로 읽은 분량이 아니라 맞힌 문제와 재풀이 성공률로 판단한다.
- 매주 일요일 다음을 체크한다.
  - 과목별 생성 문제 풀이 수
  - 정답/애매함/오답/모름 비율
  - 2회 이상 틀린 개념
  - 5~7문장으로 설명 가능한 개념 수
  - 금융IT 적용 문장으로 연결 가능한 개념 수
  - 다음 주 NotebookLM 재출제 목록

## 7. 최종 원칙

> 지금 필요한 것은 전공책 정독이 아니라, 이미 알고 있는 CS 지식을 금융공기업 서술형 답안으로 빠르게 변환하는 것이다.

> 한국은행 기출은 9월 실전 검증용으로 아끼되, NotebookLM 소스로 제공해 출제 스타일은 6월부터 흡수한다.

> 6~8월의 승부처는 “문제 생성량”이 아니라 “오답 개념을 다시 맞히는 회수율”이다.

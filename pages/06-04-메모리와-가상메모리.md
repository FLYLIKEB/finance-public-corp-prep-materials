# 06-04. 메모리와 가상메모리

> 학습 목적: 단편화, 페이징, 세그먼트, 가상메모리를 비교한다.
> 관련 기출: [05-9-운영체제-기출-모음](05-09-운영체제-기출-모음.md)
> 연결 핵심정리: [04-3-소프트웨어공학-운영체제-컴퓨터구조](04-03-소프트웨어공학-운영체제-컴퓨터구조.md)

## 핵심 개념

- 내부 단편화는 할당 블록 내부 낭비다.
- 외부 단편화는 연속 공간 부족 문제다.
- 페이징은 고정 크기, 세그먼트는 가변 크기 관리다.


### 서술형 확장 개념

- **가상메모리**는 프로세스가 연속된 큰 주소 공간을 가진 것처럼 보이게 하고, 실제 물리 메모리와 보조기억장치 사이의 매핑은 MMU와 페이지 테이블이 담당한다. 필요한 페이지만 적재하는 demand paging은 메모리 효율을 높이지만 페이지 폴트 처리 비용이 있다.
- **TLB(Translation Lookaside Buffer)**는 최근 사용한 가상주소→물리주소 변환 결과를 저장하는 캐시다. TLB hit이면 페이지 테이블 접근 없이 빠르게 변환하고, miss이면 페이지 테이블을 조회한 뒤 TLB를 갱신한다.
- 페이지 테이블이 커지는 문제는 **다단계 페이지 테이블**이나 inverted page table로 줄인다. 다단계 구조는 실제 사용하는 주소 범위의 하위 테이블만 만들 수 있어 희소 주소 공간에 유리하다.
- **페이지 교체 알고리즘**은 물리 프레임이 부족할 때 내보낼 페이지를 고른다. FIFO는 단순하지만 Belady anomaly가 가능하고, OPT는 이론상 최적이지만 미래 참조를 알아야 하며, LRU/Clock은 최근 사용성을 근사해 구현한다.
- **Thrashing**은 페이지 폴트가 너무 잦아 CPU가 실제 계산보다 페이지 교체에 시간을 쓰는 상태다. Working Set은 프로세스가 최근 일정 시간 동안 참조한 페이지 집합으로, 이를 수용할 프레임을 보장하면 thrashing을 줄일 수 있다.

| 알고리즘 | 선택 기준 | 특징 |
| --- | --- | --- |
| FIFO | 가장 오래 메모리에 있던 페이지 | 구현 단순, Belady anomaly 가능 |
| OPT | 가장 늦게 다시 쓰일 페이지 | 이론적 최적, 실제 구현 어려움 |
| LRU | 가장 오래 참조되지 않은 페이지 | 지역성 반영, 구현 비용 큼 |
| Clock | 참조 비트로 LRU 근사 | OS에서 실용적 |

## 쉽게 이해하기

- 메모리는 책상 공간이라고 생각하면 된다. 작업을 올려둘 공간이 부족하면 정리 방식이 중요해진다.
- 페이징은 책상을 같은 크기의 칸으로 나눠 쓰는 방식이고, 세그먼트는 작업 종류별로 필요한 만큼 나눠 쓰는 방식이다.
- 가상메모리는 실제 책상보다 더 넓은 책상이 있는 것처럼 보이게 하는 기술이다. 자주 안 쓰는 것은 서랍이나 창고에 잠시 빼 둔다.

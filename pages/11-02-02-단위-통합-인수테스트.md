# 11-02-02. 단위-통합-인수테스트

> 학습 목적: 단위, 통합, 시스템, 인수 테스트의 범위와 목적을 구분하고 회귀·스모크 테스트를 이해한다.

## 핵심 개념

- 단위 테스트는 개별 모듈, 함수, 클래스를 검증한다.
- 통합 테스트는 모듈 사이의 인터페이스와 데이터 흐름을 검증한다.
- 시스템 테스트는 완성된 전체 시스템이 요구사항을 만족하는지 확인한다.
- 인수 테스트는 사용자나 고객 관점에서 인수 기준 충족 여부를 판단한다.

## 단위 테스트(Unit Test)

단위 테스트는 가장 작은 개발 단위가 의도대로 동작하는지 검증한다.

- 대상: 함수, 메서드, 클래스, 모듈
- 목적: 내부 로직 오류를 빠르게 발견
- 특징: 빠르고 자동화하기 쉽다
- 보조 도구: Stub, Mock, Driver 등을 활용할 수 있다

## 통합 테스트(Integration Test)

통합 테스트는 여러 모듈을 연결했을 때 인터페이스와 데이터 흐름이 올바른지 확인한다.

### 통합 방식

| 방식 | 설명 | 특징 |
| --- | --- | --- |
| 빅뱅 통합 | 모든 모듈을 한 번에 결합 | 단순하지만 오류 원인 추적이 어렵다 |
| 상향식 통합 | 하위 모듈부터 결합 | 상위 모듈 대체용 Driver가 필요할 수 있다 |
| 하향식 통합 | 상위 모듈부터 결합 | 하위 모듈 대체용 Stub이 필요할 수 있다 |
| 샌드위치 통합 | 상향식과 하향식을 병행 | 병렬 진행 가능하지만 관리가 복잡하다 |

## 시스템 테스트(System Test)

시스템 테스트는 완성된 소프트웨어 전체가 기능 요구사항과 비기능 요구사항을 만족하는지 확인한다.

- 기능 테스트: 요구 기능이 명세대로 동작하는지 확인
- 성능 테스트: 응답 시간, 처리량, 자원 사용량 확인
- 보안 테스트: 인증, 권한, 취약점 확인
- 사용성 테스트: 사용자 편의성 확인
- 호환성 테스트: OS, 브라우저, 장치 환경 확인

## 인수 테스트(Acceptance Test)

인수 테스트는 고객이나 사용자가 시스템을 받아들일 수 있는지 판단하는 테스트다.

| 유형 | 설명 |
| --- | --- |
| 알파 테스트 | 개발 조직 내부 또는 제한된 환경에서 사용자 관점으로 수행 |
| 베타 테스트 | 실제 사용자 환경에서 제한된 사용자에게 배포해 수행 |
| 운영 인수 테스트 | 운영 절차, 백업, 복구, 모니터링 등을 확인 |

## 회귀 테스트와 스모크 테스트

### 회귀 테스트(Regression Test)

회귀 테스트는 변경 이후 기존 기능이 깨지지 않았는지 다시 확인하는 테스트다. 버그 수정, 기능 추가, 리팩터링 이후 수행한다.

### 스모크 테스트(Smoke Test)

스모크 테스트는 빌드나 배포 직후 핵심 기능이 기본적으로 동작하는지 빠르게 확인하는 테스트다. 깊이 있는 검증보다 “더 진행할 수 있는 상태인지” 판단하는 목적이 크다.

| 구분 | 회귀 테스트 | 스모크 테스트 |
| --- | --- | --- |
| 목적 | 변경 영향으로 기존 기능이 깨졌는지 확인 | 빌드·배포가 기본적으로 사용 가능한지 확인 |
| 범위 | 기존 기능 전반 또는 영향 범위 | 핵심 기능 중심의 얕은 점검 |
| 시점 | 변경 후 반복 수행 | 빌드·배포 직후 |

## 테스트 레벨 비교표

| 구분 | 단위 테스트 | 통합 테스트 | 시스템 테스트 | 인수 테스트 |
| --- | --- | --- | --- | --- |
| 관점 | 개발자 | 개발자·테스터 | 테스터·품질 | 사용자·고객 |
| 범위 | 개별 모듈 | 모듈 간 연결 | 전체 시스템 | 인수 기준 |
| 주요 결함 | 로직 오류 | 인터페이스 오류 | 요구사항 불일치 | 사용자 요구 미충족 |
| 관련 키워드 | Mock, Stub | Driver, Stub, Big Bang | 성능, 보안, 호환성 | 알파, 베타, UAT |

## 빈출 포인트

- “모듈 간 인터페이스 오류” → 통합 테스트.
- “사용자 요구사항 충족 여부” → 인수 테스트.
- “변경 후 기존 기능 재검증” → 회귀 테스트.
- “배포 직후 핵심 기능 빠른 확인” → 스모크 테스트.
- 상향식 통합에는 Driver, 하향식 통합에는 Stub이 자주 연결된다.

## 오답 포인트

- 통합 테스트는 전체 시스템의 모든 요구사항을 검증하는 단계가 아니라 모듈 간 연결 검증이 중심이다.
- 인수 테스트는 개발자가 내부 로직을 확인하는 테스트가 아니라 사용자·고객 관점의 테스트다.
- 스모크 테스트는 상세 테스트를 대체하지 않는다.

## 빠른 점검

- 단위, 통합, 시스템, 인수 테스트의 범위를 작은 것부터 큰 것으로 정렬할 수 있는가?
- 회귀 테스트와 스모크 테스트의 목적 차이를 설명할 수 있는가?
- 상향식·하향식 통합에서 필요한 보조 모듈을 구분할 수 있는가?

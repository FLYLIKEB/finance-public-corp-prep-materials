## 핵심 개념

- SELECT는 조회, WHERE는 조건, GROUP BY는 그룹화다. — 시험 답안 예: "SELECT는 결과 컬럼을 지정하는 절이고, WHERE는 행 필터링에 사용된다."
- HAVING은 그룹 조건, ORDER BY는 정렬이다. — 시험 답안 예: "HAVING은 그룹화 후 그룹 단위의 조건을 걸 때 사용한다."
- JOIN은 테이블 간 관련 행을 결합한다. — 시험 답안 예: "JOIN은 두 개 이상의 테이블을 결합해 관련 데이터를 한 행으로 만든다(예: 고객과 주문을 연결)."

(핵심 문장들은 문제 풀이 시 한두 문장으로 요약해 쓰기 적합합니다.)

## 쉽게 이해하기

- SQL은 데이터베이스에 질문하는 언어다. '어떤 표에서, 어떤 조건으로, 어떤 컬럼을 보여줘'라고 요청한다고 생각하면 된다.
- SELECT는 무엇을 볼지, FROM은 어디서 볼지, WHERE는 어떤 행만 볼지 정한다.
- 중요한 직관: 작성 순서와 실행 순서는 다르다. 일반적인 실행 순서는 다음과 같다.

1. FROM (테이블 선택, 서브쿼리 평가)
2. JOIN (테이블 결합)
3. WHERE (행 필터링)
4. GROUP BY (그룹화)
5. HAVING (그룹에 대한 필터링)
6. SELECT (컬럼/표현식 계산 및 중복 제거 처리 - DISTINCT 등)
7. ORDER BY (정렬)
8. LIMIT / OFFSET (결과 개수 제한)

- 이 순서를 머릿속에 두면 복잡한 쿼리도 단계별로 해석할 수 있다.

### 시험 답안에 바로 쓸 수 있는 실행 예시와 해설

예: 고객별 주문 건수와 그 중 주문 건수가 5건 이상인 고객만 보여주기

```sql
SELECT c.customer_id, c.name, COUNT(o.order_id) AS order_count
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
WHERE c.active = TRUE
GROUP BY c.customer_id, c.name
HAVING COUNT(o.order_id) >= 5
ORDER BY order_count DESC;
```

- 해설(한두 문장): FROM과 JOIN으로 고객-주문 관계를 결합한 뒤 active인 고객만 WHERE로 필터링한다. GROUP BY로 고객별 집계를 만들고 HAVING으로 5건 이상인 그룹만 남긴다. 마지막으로 ORDER BY로 결과를 정렬한다.

## 비교표 (시험에 바로 쓸 수 있는 요약 형태)

| 항목 | 용도 | 언제 사용하는가 | 비고(시험 표기) |
|---|---:|---|---|
| WHERE | 행 필터링 | GROUP BY 이전, 개별 행을 기준으로 필터 | 집계 함수 사용 불가 (예: WHERE COUNT(*) > 1 불가) |
| HAVING | 그룹 필터링 | GROUP BY 이후, 그룹 단위 조건 | 집계 함수 사용 가능 |
| GROUP BY | 그룹화 | 동일한 기준으로 집계가 필요할 때 | SELECT에 있는 비집계 컬럼은 GROUP BY에 포함 필요(일부 DB 예외) |
| DISTINCT | 중복 제거 | 전체 결과에서 중복 행 제거 | GROUP BY 없이 중복 제거 목적일 때 사용 |

### JOIN 종류 요약

| JOIN 종류 | 동작 | 시험에서 자주 쓰는 표현 |
|---|---|---|
| INNER JOIN | 일치하는 행만 결합 | '교집합' 효과 — 양쪽에 모두 존재하는 데이터만 결과
| LEFT (OUTER) JOIN | 왼쪽 테이블의 모든 행과 오른쪽 일치 행 결합 | 왼쪽 기준 전체 + 오른쪽 일치 데이터(없으면 NULL)
| RIGHT (OUTER) JOIN | 오른쪽 테이블의 모든 행과 왼쪽 일치 행 결합 | 오른쪽 기준 전체 + 왼쪽 일치 데이터(없으면 NULL)
| FULL (OUTER) JOIN | 양쪽 모두의 모든 행을 포함 | 양쪽 모두의 비어있는 부분은 NULL로 채움(일부 DB 미지원)

(시험에서는 INNER vs LEFT를 묻는 문제가 가장 빈번합니다. 쿼리 결과 예제를 통해 차이를 구체적으로 설명하면 점수가 좋습니다.)

## 서술형 확장 개념 (간단 명료하게)

- 인덱스: 특정 컬럼에 인덱스를 생성하면 WHERE, JOIN의 검색 속도가 개선된다. 단, 쓰기(INSERT/UPDATE/DELETE) 비용은 증가한다.
- 트랜잭션과 ACID: 트랜잭션은 원자성·일관성·격리성·지속성(ACID)을 보장해 여러 연산을 하나의 단위로 처리한다. 시험에서는 트랜잭션의 목적(데이터 무결성 보장)을 서술하라 묻는 경우가 많다.
- 정규화: 중복을 줄이고 이상현상을 방지하기 위해 테이블을 분해하는 과정. 실무/문제에서는 "정규화 수준(nF)을 설명하고 단점(추가 JOIN 증가)을 함께 적으라"는 유형이 있다.

## 약어 풀이

- SQL: Structured Query Language, 구조화 질의어
- DDL: Data Definition Language — 테이블/인덱스/스키마 등 구조 정의(예: CREATE, ALTER, DROP)
- DML: Data Manipulation Language — 데이터 조작(예: INSERT, UPDATE, DELETE)
- DCL: Data Control Language — 권한/권한 관리(예: GRANT, REVOKE)
- CRUD: Create, Read, Update, Delete — 기본 데이터 조작 동작

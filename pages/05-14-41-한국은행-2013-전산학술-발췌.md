## 2013 전산학술 발췌

파이프라인, 데이터 웨어하우스, 빅데이터, 가상메모리, 프로젝트 일정관리가 한 번에 묶인 종합형 발췌본이다.

### I. 하드웨어·데이터·신기술

#### 1. 파이프라인 회로

**2013 전산학술 — 3세그먼트 파이프라인 회로**

![2013 전산학술 — 3세그먼트 파이프라인 회로](https://raw.githubusercontent.com/FLYLIKEB/finance-public-corp-prep-materials/main/%EC%A4%80%EB%B9%84%EC%9E%90%EB%A3%8C/%ED%95%9C%EA%B5%AD%EC%9D%80%ED%96%89%20%EA%B8%B0%EC%B6%9C/pdf/html/5.%202013%EC%A0%84%EC%82%B0%ED%95%99%EC%88%A0%28%EA%B3%B5%EA%B0%9C%EC%B5%9C%EC%A2%85%29.html/bindata/BIN0001.bmp)


3개의 세그먼트로 구성된 파이프라인 회로를 두고 다음을 묻는다.

- 파이프라인 기법의 개념
- 각 세그먼트에서 수행되는 **부연산(suboperation)**
- 100개 연산 수행 시 **비파이프라인 대비 속도 향상률**
- `k`개 세그먼트를 가진 파이프라인의 **최대 속도 증가율**

### II. 운영체제와 프로젝트 관리

#### 1. 페이지 부재(page fault) 처리

**2013 전산학술 — 페이지 부재 처리 과정**

![2013 전산학술 — 페이지 부재 처리 과정](https://raw.githubusercontent.com/FLYLIKEB/finance-public-corp-prep-materials/main/%EC%A4%80%EB%B9%84%EC%9E%90%EB%A3%8C/%ED%95%9C%EA%B5%AD%EC%9D%80%ED%96%89%20%EA%B8%B0%EC%B6%9C/pdf/html/5.%202013%EC%A0%84%EC%82%B0%ED%95%99%EC%88%A0%28%EA%B3%B5%EA%B0%9C%EC%B5%9C%EC%A2%85%29.html/bindata/BIN0004.bmp)


페이지 부재 처리 흐름도에서

- `②~⑥`의 처리 과정을 `trap`, `페이지 교체`, `victim frame` 용어로 설명
- 메모리 접근시간 `200ns`, 평균 페이지 부재 처리시간 `8ms`일 때 **성능 저하율 10% 이하가 되기 위한 페이지 부재율** 계산
- `thrashing`의 개념 설명

#### 2. A프로젝트 일정관리

작업 `T1~T9`와 각 소요기간·선행작업이 주어진다. 이를 바탕으로

- `activity network` 작성
- `critical path`와 프로젝트 최단 완료기간 계산
- 최단 기간에 영향을 주지 않는 범위의 **최대 지연 가능 기간을 표시한 Gantt chart** 작성
- 최단 기간 완료를 위해 필요한 **최소 인원 수** 계산

를 요구한다.

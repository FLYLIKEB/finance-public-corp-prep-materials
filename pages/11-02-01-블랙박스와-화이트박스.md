# 11-02-01. 블랙박스와 화이트박스

> 학습 목적: 블랙박스 테스트와 화이트박스 테스트의 관점, 대표 기법, 커버리지 기준을 구분한다.

## 핵심 개념

- 블랙박스 테스트는 내부 구조를 보지 않고 명세, 입력, 출력만으로 테스트한다.
- 화이트박스 테스트는 프로그램 내부 구조, 제어 흐름, 조건, 경로를 기준으로 테스트한다.
- 동치분할, 경계값 분석, 결정 테이블은 블랙박스 대표 기법이고, 문장·분기·조건 커버리지는 화이트박스 대표 기준이다.

### 서술형 확장 개념

- 동치분할은 같은 결과를 낼 입력 영역을 대표값으로 줄이고, 경계값 분석은 오류가 잦은 경계 근처 값을 집중 테스트한다. 결정 테이블은 조건 조합과 결과가 많은 업무 규칙에 적합하고, 상태전이 테스트는 로그인/계좌상태처럼 상태에 따라 허용 행위가 달라지는 시스템에 적합하다.
- Statement coverage는 문장을 한 번 이상 실행했는지, branch coverage는 분기의 참/거짓을 모두 실행했는지, condition coverage는 복합 조건의 각 원자 조건이 참/거짓을 모두 가졌는지 본다. Path coverage는 가능한 실행 경로를 보지만 반복문 때문에 모든 경로 검증이 현실적으로 어려울 수 있다.
- Top-down 통합 테스트는 상위 모듈부터 검증하며 하위 모듈을 stub으로 대체한다. Bottom-up은 하위 모듈부터 검증하며 상위 호출자를 driver로 대체한다. Sandwich는 두 방식을 결합한다.

## 블랙박스 테스트

블랙박스 테스트는 프로그램 내부 코드가 어떻게 작성되었는지 보지 않고, 요구사항 명세에 따라 입력에 대한 출력이 올바른지 확인한다.

### 대표 기법

| 기법 | 설명 | 예시 |
| --- | --- | --- |
| 동치분할(Equivalence Partitioning) | 입력값을 같은 결과가 예상되는 집합으로 나누고 대표값을 테스트 | 나이 0~120 입력에서 유효/무효 구간 분리 |
| 경계값 분석(Boundary Value Analysis) | 오류가 자주 발생하는 경계 근처 값을 테스트 | 1~100 허용이면 0, 1, 2, 99, 100, 101 확인 |
| 결정 테이블(Decision Table) | 여러 조건 조합과 결과를 표로 정리해 테스트 | 할인 조건, 회원 등급, 쿠폰 사용 여부 조합 |
| 상태 전이 테스트 | 상태 변화와 이벤트를 기준으로 테스트 | 로그인 실패 횟수에 따른 계정 잠금 |
| 유스케이스 테스트 | 사용자 시나리오 흐름을 기준으로 테스트 | 회원 가입, 결제, 승인 요청 흐름 |

## 화이트박스 테스트

화이트박스 테스트는 코드 내부의 분기, 반복, 조건, 실행 경로를 확인한다. 개발자 관점에서 구조적 결함을 찾는 데 유용하다.

### 커버리지 기준

| 기준 | 의미 | 특징 |
| --- | --- | --- |
| 문장 커버리지(Statement Coverage) | 모든 문장이 최소 1번 실행되는지 확인 | 가장 약한 구조 기반 기준 |
| 분기 커버리지(Branch/Decision Coverage) | 각 분기의 참·거짓이 최소 1번 실행되는지 확인 | if, switch 분기 누락을 찾기 좋음 |
| 조건 커버리지(Condition Coverage) | 복합 조건의 각 개별 조건이 참·거짓을 갖는지 확인 | 분기보다 세부 조건에 초점 |
| 경로 커버리지(Path Coverage) | 가능한 실행 경로를 확인 | 완전 수행은 현실적으로 어려울 수 있음 |

## 비교표

| 구분 | 블랙박스 테스트 | 화이트박스 테스트 |
| --- | --- | --- |
| 기준 | 요구사항, 명세, 입출력 | 코드 구조, 분기, 조건, 경로 |
| 내부 코드 이해 | 필요 없음 | 필요함 |
| 수행 관점 | 사용자·테스터 관점 | 개발자·구조 분석 관점 |
| 대표 기법 | 동치분할, 경계값 분석, 결정 테이블 | 문장·분기·조건·경로 커버리지 |
| 발견하기 쉬운 결함 | 누락 기능, 명세 불일치, 경계 오류 | 논리 오류, 분기 누락, 경로 오류 |

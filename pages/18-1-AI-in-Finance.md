# 18-1. AI in Finance

## 핵심 개념

- 금융 AI는 신용평가, 이상거래탐지(FDS), 상담 자동화(챗봇/생성형 AI), 로보어드바이저, 문서 심사·자동화(OCR + NLP) 등 다양한 영역에 적용된다.
- 신용평가 ML
  - 사용 데이터: 정형 데이터(거래이력, 신용기록)뿐만 아니라 비정형·대안 데이터(소셜·행동·텍스트 로그 등)를 보완적으로 사용 가능하다.
  - 주요 고려사항: 데이터 품질(누락·왜곡), 피처 설계의 공정성(차별 예방), 모델 설명가능성(신용거부 사유 설명), 규제 준수(개인정보 보호·동의 등).
- 이상거래탐지(FDS)
  - 입력 신호: 거래 시간, 금액, 위치, 기기 정보, 계정 간 관계(네트워크), 과거 행태(시계열 패턴) 등.
  - 운영 관점: 미탐(사고 위험)과 오탐(고객 불편) 사이의 트레이드오프가 존재하므로 임계값 조정, 룰 기반 필터와의 조합, 휴리스틱 검토 절차가 필요하다.
  - 평가 지표: 정밀도/재현율(precision/recall) 관점에서 임팩트를 판단하고, 실제 운영에서는 거짓양성 수의 비용·탐지 지연 시간 등을 함께 고려한다.
- 챗봇 및 생성형 AI
  - 장점: 24/7 고객응대, 단순 문의 자동화, 내부 문서 검색 보조, 고객 상담 전 사전분석 등으로 업무 효율화.
  - 위험요소: 환각(hallucination)으로 인한 잘못된 정보 제공, 민감정보 유출, 투자·금융상품 관련 부적절한 조언 가능성.
  - 통제방법: 응답 필터링, 템플릿 기반 비즈니스 룰, 인간-검토(Human-in-the-loop), 로그·감사 추적, 개인정보 비식별화 또는 RAG(retrieval-augmented) 설계로 근거를 함께 제공.
- 설명가능성(XAI)
  - 목적: 고객에게 의사결정 사유 설명, 내부 승인·거버넌스, 감독기관 대응을 위해 모델 판단 근거를 제시.
  - 기법(개념적): 전역/국소 설명(전역적 특성 중요도 vs 개별 예측 설명), 대체모델(설명 가능한 단순 모델로 근사), 입력 중요도(피처 기여도: 예를 들어 SHAP/기여도 분석 개념), 규칙 기반 보충 설명.

## 면접 답변 포인트

- 요약형(한 문장): “AI는 비용과 시간을 절감하는 효율화 도구이나, 금융에서는 신뢰·공정성·투명성이 우선이므로 모델 성능뿐 아니라 데이터 편향, 설명가능성, 개인정보 보호, 운영 모니터링을 함께 관리해야 합니다.”

- 확장형(핵심 키워드 나열): 성능·편향·설명가능성(XAI)·프라이버시·모니터링(Drift detection)·거버넌스·사고대응 계획.

- 구체적 예시 답변(면접용): “신용평가 모델을 도입할 때는 모델 정확도뿐 아니라 입력 데이터의 대표성, 특정 집단에 대한 불공정성 여부를 검증합니다. 설명가능성 도구로 고객별 거부 사유를 제시하고, 운영 중에는 성능 저하를 탐지하는 모니터링과 재학습 정책을 마련합니다.”

## 시험 포인트 (요약형 질문 & 답변 가이드)

- Q: 신용평가 모델에서 대체데이터를 사용하는 장단점은?
  - A: 장점은 신용기록이 부족한 고객도 평가 가능해져 포용성이 증가한다는 점. 단점은 데이터 품질·대표성 문제로 편향을 초래할 수 있으며, 설명 및 규제 대응이 더 어려워질 수 있음.

- Q: FDS에서 오탐률을 낮추려면 어떤 접근을 취하나?
  - A: 피처 엔지니어링 개선, 룰 기반 필터와 ML 결합, 임계값 튜닝, 후처리(우선순위/확률 기반 스코어링), 피드백 루프(사건 레이블링)를 통해 점진적으로 조정.

- Q: 생성형 AI의 ‘환각’ 리스크를 어떻게 통제하나?
  - A: 사실 근거를 함께 제공하도록 retrieval 기반 설계, 응답 검증 규칙, 민감 주제에 대한 차단/전문화된 핸들러 적용, 인간 검토를 통해 허용 범위를 관리.

- Q: 금융에서 XAI를 적용할 때 주의할 점은?
  - A: 설명의 정확성(모델의 실제 내부 작동과 설명이 일치해야 함), 고객이 이해할 수 있는 수준의 언어로 번역, 규제 요구사항 충족 여부(예: 거부 사유 문서화).

## 실무 연결 — 체크리스트(모델 도입/운영 시 고려사항)

- [ ] 데이터 준비: 원천 데이터 출처, 동의 여부, 품질(결측/왜곡) 확인
- [ ] 편향 점검: 집단별 성능 차이(성별·연령·지역 등) 분석
- [ ] 설명가능성 확보: 고객·내부·감독기관 대상 설명 템플릿 마련
- [ ] 개인정보 보호: 최소수집 원칙, 비식별화·암호화, 접근 통제
- [ ] 운영 설계: 배포 파이프라인, A/B 테스트 계획, 롤백 프로세스
- [ ] 모니터링·알림: 성능 드리프트, 데이터 분포 변화, 지연·에러 모니터링
- [ ] 인간 검토 플로우: 고위험 사례에 대한 수동검토 루트 마련
- [ ] 감사/문서화: 모델 버전, 학습 데이터 스냅샷, 의사결정 근거 로그
- [ ] 사고 대응: 오탐/미탐 발생 시 보상·고객 안내 프로세스

## 참고 사항 및 실무 팁

- 작은 모델·단순 규칙과 결합해 안정성을 확보하라. 복잡한 모델은 성능 향상에는 유리하지만 설명성과 운영 복잡도를 높인다.
- 초기 단계에서는 수동 검토·휴리스틱을 적극 활용해 라벨 품질을 높이고, 점진적 자동화를 추진하라.
- 모델의 사회적 영향(금융 포용성, 차별 위험)을 비기술적 이해관계자(법무, 컴플라이언스, 고객담당)와 함께 평가하라.

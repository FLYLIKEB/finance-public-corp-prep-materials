# CS 학습 문서 외부 이미지 첨부 설계

## 목표

`pages/` 아래 CS/IT 학습 문서 중 이미지가 있으면 개념 이해가 쉬워지는 부분에 외부 이미지 URL을 직접 삽입한다. 최종 Wikidocs/GitHub Markdown에서 이미지가 바로 보이도록 하는 것이 우선 목표다.

## 대상 범위

우선 대상은 IT 필기와 CS 기본 개념 문서다.

- `pages/04-*`: IT 필기 핵심정리
- `pages/06-*`: 운영체제
- `pages/07-*`: 데이터베이스
- `pages/08-*`: 네트워크
- `pages/09-*`: 자료구조/알고리즘
- `pages/10-*`: 보안
- `pages/11-*`: 소프트웨어공학
- `pages/13-*`: SQL/코딩
- `pages/15-*`: 컴퓨터구조 심화

모든 문서에 억지로 이미지를 넣지 않고, 시각 자료가 암기·이해에 실제로 도움이 되는 문서만 수정한다.

## 이미지 선정 기준

1. 문서에서 바로 보이는 외부 이미지 URL을 사용한다.
2. Wikimedia Commons, 공식 문서, 공개 교육 자료처럼 장기 유지 가능성이 높은 출처를 우선한다.
3. 이미지 바로 아래에 짧은 설명과 출처를 남긴다.
4. 문서당 핵심 이미지 1~3개를 넘기지 않는 것을 기본값으로 한다.
5. 라이선스나 직접 표시 가능성이 애매한 경우는 직접 삽입하지 않고 건너뛴다.

## 삽입 형식

Markdown 형식은 다음 패턴으로 통일한다.

```md
![로지스틱 회귀의 시그모이드 곡선](https://upload.wikimedia.org/wikipedia/commons/8/88/Logistic-curve.svg)
> 그림: 로지스틱 회귀는 선형 결합 결과를 시그모이드 함수에 통과시켜 0~1 확률로 해석한다.  
> 출처: Wikimedia Commons, https://commons.wikimedia.org/wiki/File:Logistic-curve.svg
```

## 우선 삽입 후보

- 로지스틱 회귀 / 시그모이드 함수
- 머신러닝 분류 흐름
- OSI 7계층 / TCP-IP 계층
- TCP 3-way handshake
- 정규화와 함수 종속
- 트랜잭션 ACID
- 스택, 큐, 트리, 그래프
- BFS/DFS 탐색 흐름
- CPU 파이프라인, 캐시/메모리 계층
- 암호화·해시·인증 흐름

## 검증

- Markdown 이미지 문법이 깨지지 않는지 확인한다.
- 변경 파일 목록을 확인한다.
- 커밋 후 원격에 푸시한다.
